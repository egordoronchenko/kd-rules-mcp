# Грабли обменов КД 2 через БСП

Справочник проверенных случаев, не привязанных к конкретной конфигурации. Каждый подтверждён кодом
исполнителя правил БСП — обработки `КонвертацияОбъектовИнформационныхБаз`, модуль объекта
(`DataProcessors/КонвертацияОбъектовИнформационныхБаз/Ext/ObjectModule.bsl` в выгрузке любой конфигурации
на БСП), а для настроек обмена — общих модулей `ОбменДаннымиСервер` и `ОбщегоНазначения` той же БСП (так и
указано у ссылки). Ссылка — имя процедуры и строки в БСП **3.1.12**; в другой версии строки сдвигаются,
процедуры — те же (обработка сверена с 3.1.2).

## Как разбирать жалобу

1. **Направление и база.** Обработчики загрузки берутся из правил **отправителя**: он пишет свои правила
   в сообщение обмена (`ВыполнитьВыгрузкуДанных`, стр. 2233), получатель читает их оттуда
   (`НачатьЧтениеСообщения`, стр. 7481–7490). Ошибка загрузки в базе Б при обмене из А правится в правилах А;
   в Б те же правила лежат копией как правила корреспондента (для сверки версий).
2. **Живые правила из обеих баз** (ZIP «Сохранить правила конвертации в файл»): `rules_open` →
   `rules_validate` с обеими структурами — часть граблей ловится проверкой (код в скобках у заголовка).
3. **ПКО проблемного объекта** — `rules_get`: флаги (`СинхронизироватьПоИдентификатору`,
   `ПродолжитьПоискПоПолямПоискаЕслиПоИдентификаторуНеНашли`, `НеЗамещать`), ПКС с `search: true`,
   обработчик `ПоследовательностьПолейПоиска`. Как объект вообще уходит: ПВД и их обработчики, ПКС других
   ПКО с его `КодПравилаКонвертации`.
4. **Сравнить с типовым макетом** плана обмена (`rules_open` макета) — что доработано.
5. **Данные** — в песочнице через сервер данных базы (`data_mcp` в `project_list`), только чтение.
   Правилам и коду верить больше, чем словам «1С не даст записать»: проверять по модулю объекта.

## Поиск существующего объекта при загрузке

Загрузка ищет объект сразу, как прочитала узел `<Ссылка>` (`ПрочитатьОбъект`, стр. 10735–10757):
сначала по уникальному идентификатору (с подменой по регистру соответствий), затем — по полям поиска, если у
ПКО стоит `ПродолжитьПоискПоПолямПоискаЕслиПоИдентификаторуНеНашли`. В узел `<Ссылка>` выгрузка пишет
**только свойства поиска** ПКО (`ВыгрузитьПоПравилу`, стр. 790–826).

### Параметр объекта в обработчике поиска не виден (`search.param_not_in_search`)

- **Симптом:** объект задваивается, хотя обработчик `ПоследовательностьПолейПоиска` «должен» выбрать поиск
  по параметру (например, по виду лица — ИНН + КПП для юрлиц); срабатывает ветка `ПараметрыОбъекта = Неопределено`.
- **Причина:** обработчик читает `ПараметрыОбъекта["X"]`, а ПКС, передающее `X` (`ИмяПараметраДляПередачи`),
  без флага «Поиск». Такой параметр идёт в свойствах объекта и читается после поиска (`ПрочитатьОбъект`,
  стр. 10705).
- **Исправление:** флаг «Поиск» у ПКС параметра. Параметр уйдёт в `<Ссылка>` узлом `<ЗначениеПараметра>`
  (`СоздатьСложнуюИнформациюДляЗаписиВXML`, стр. 12691) и попадёт в `ПараметрыОбъекта` до поиска
  (`ПрочитатьСвойстваПоискаИзФайла`, стр. 8228–8291). ПКС с «Поиск» и пустым приёмником допустимо
  (`ЗагрузитьПКС`, стр. 5494); как условие запроса параметр не используется (`ЗагрузитьПравилоКонвертации`,
  стр. 6079–6082) — он только выбирает строку полей.
- Параметр нельзя сделать «полем поиска» в строке `СтрокаИменСвойствПоиска`: условие строится только по
  свойствам поиска (`НайтиЭлементПоСвойствамПоиска`, стр. 8566–8577), параметра среди них нет — он молча
  пропускается.
- Воспроизведено живым обменом в песочницах: без флага — второй объект с теми же ИНН/КПП, с флагом —
  документ ссылается на существующий (заведённый в приёмнике вручную, с другим наименованием).

### Наименование в полях поиска

- **Симптом:** дубль при совпадающих ИНН и КПП.
- **Причина:** поиск «ИНН, КПП, Наименование»: в двух базах наименование пишут по-разному (ручной ввод в одной,
  заполнение по ИНН из ФНС в другой — порядок слов, кавычки, сокращения формы собственности).
- **Исправление:** для юрлиц с ИНН — без наименования (ИНН + КПП), наименование — только когда ИНН пуст.

### Варианты поиска должны различаться

- Обработчик вызывается с `НомерВариантаПоиска` = 1, 2, … до 10, перебор идёт, только пока он возвращает
  **новую** строку полей: та же строка, что в прошлом варианте, `ПрекратитьПоиск` или найденный объект —
  конец (`НайтиОбъектПоСсылке`, стр. 8940, 8970–8972). Обработчик, который не смотрит на
  `НомерВариантаПоиска`, даёт одну попытку.
- Пустая строка полей (ни одна ветка не сработала; начальное значение — пустая строка, стр. 8913) — поиск
  по **всем** свойствам поиска ПКО (`НайтиЭлементПоСвойствамПоиска`, стр. 8561–8563).
- Типовой образец для контрагентов: 1 — ИНН, КПП, Наименование; 2 — ИНН, КПП; 3 — ИНН, Наименование; без ИНН —
  Наименование.

### Пустой ИНН в поиске по ИНН

- **Симптом:** объект источника связался в приёмнике с чужим объектом (без ИНН); документы «висят» не на том
  контрагенте. Хуже дубля — не видно сразу.
- **Причина:** пустое значение приходит `<Пусто/>` и читается пустой строкой (`ПрочитатьСвойство`,
  стр. 8060–8063), попадает в поля поиска (стр. 8290); запрос — `ВЫБРАТЬ Ссылка ИЗ … ГДЕ ИНН = &ИНН И КПП = &КПП`
  без пропуска пустых и без упорядочивания, берётся первая строка (`НайтиЭлементЗапросом`, стр. 8425–8463).
- **Исправление:** перед поиском без наименования проверять `ЗначениеЗаполнено(СвойстваПоиска["ИНН"])`
  (так делает типовой обработчик). То, что таких объектов сейчас нет, не защищает: типовой модуль объекта
  контрагента запись без ИНН не запрещает (иностранные, физлица). Исправление проверено живым обменом:
  юрлицо без ИНН создаётся отдельно и не цепляется к чужому объекту без ИНН; само ошибочное связывание
  (без проверки) живым обменом не воспроизводилось.

## Загрузка: ошибки и транзакции

### После ошибки обмена часть объектов уже в приёмнике

- **Симптом:** сообщение не загрузилось (ошибка в обработчике), а в приёмнике появились объекты из него —
  например, контрагент есть, документа на него нет; повторный обмен после исправления работает с ними.
- **Причина:** транзакцией загрузки управляет константа приёмника `КоличествоЭлементовВТранзакцииЗагрузкиДанных`
  (`ОбменДаннымиСервер.КоличествоЭлементовВТранзакцииЗагрузкиДанных`, стр. 686–690): обработка получает
  `ИспользоватьТранзакции = (значение <> 1)` (`ОбменДаннымиСервер`, стр. 5653–5654). При 1 транзакции нет,
  каждый объект пишется сам и не откатывается; при 0 — всё сообщение одной транзакцией, откатывается целиком
  (`ВыполнитьЗагрузкуДанных`, стр. 2496–2522); при N — фиксация каждые N объектов (стр. 16583–16588).
  `ПродолжитьПриОшибке` выключает транзакции (стр. 2470–2472).
- **Проверка:** значение константы в приёмнике; после неудачного обмена — объекты по реквизитам сообщения.
- **Исправление:** это настройка, не ошибка правил; при разборе жалобы «задвоилось после сбоя» учитывать, что
  первая неудачная попытка уже могла создать объекты.

### Обработчик падает в новом приёмнике: `Если Реквизиты.Флаг Тогда`

- **Симптом:** в новой или пустой базе приёмника обмен падает на первом объекте ПКО с «Преобразование значения
  к типу Булево не может быть выполнено» в `ПослеЗагрузки` (или в типовом `ПередЗаписью` объекта); на рабочей
  базе те же правила работают.
- **Причина:** `ОбщегоНазначения.ЗначенияРеквизитовОбъекта` по пустой ссылке (или несуществующему объекту)
  возвращает структуру с `Неопределено` в каждом поле (стр. 275–282, 306–307), и `Если … Тогда` на ней падает.
  Типично: реквизиты шаблона или вида документа, которые в рабочей базе всегда заполнены настройкой.
- **Проверка:** обработчик ПКО (`rules_get`) — обращения к результату `ЗначенияРеквизитовОбъекта` без
  проверки заполненности ссылки; в приёмнике — есть ли шаблоны/виды, на которые рассчитан код.
- **Исправление:** в правилах — `Если ЗначениеЗаполнено(Ссылка) И Реквизиты.Флаг = Истина Тогда`; для
  проверки в песочнице — завести недостающие настройки, а не править правила.

## Как проверить исправление живым обменом

`rules_validate`, `kd_check` и `bsp_check` подтверждают, что правила читаются, но не то, что поиск в приёмнике
найдёт нужный объект. Для этого — штатный обмен через файл между двумя песочницами:

1. **Узлы.** В обеих базах — код «этого узла» плана обмена и узел корреспондента с кодом «этого узла» другой
   базы; в заголовке сообщения `ОтКого` — код этого узла отправителя (`ИдентификаторЭтогоУзлаДляОбмена`,
   `ОбменДаннымиСервер`, стр. 3456–3478; код до двух символов заменяется префиксом узла), приёмник ищет
   по нему узел (`ПрочитатьДанныеПоОбмену`, стр. 17388–17402). Признак настройки —
   `РегистрыСведений.ОбщиеНастройкиУзловИнформационныхБаз.УстановитьПризнакНастройкаЗавершена` (иначе
   «настройка синхронизации … еще не завершена», `ОбменДаннымиСервер`, стр. 5134–5147). Константа
   `ИспользоватьСинхронизациюДанных` — Истина.
2. **Правила** — комплект ZIP из трёх файлов в обе базы:
   `РегистрыСведений.ПравилаДляОбменаДанными.ЗагрузитьКомплектПравил` с двумя менеджерами записи
   (конвертация и регистрация), затем `Записать` обоих — как форма загрузки.
3. **Данные** — в приёмнике заранее объект «как заведён вручную» (те же ключи, другое наименование);
   в источнике — объект и то, с чем он уходит (для объектов без своего ПВД — документ-носитель).
4. **Обмен** — зарегистрировать один объект на узле (`ПланыОбмена.ЗарегистрироватьИзменения`), выгрузить
   `ОбменДаннымиСервер.ВыполнитьВыгрузкуДляУзлаИнформационнойБазыВоВременноеХранилище`, загрузить в приёмник
   `ВыполнитьОбменДаннымиДляУзлаИнформационнойБазыЧерезФайлИлиСтроку` (`ДействиеПриОбмене = ЗагрузкаДанных`).
5. **Итог** — запрос в приёмнике: сколько объектов с этими ключами и на какой ссылается документ. Прогнать
   старые правила (дубль воспроизводится) и исправленные (дубля нет) на разных объектах.

Внешнее соединение (COM) для этого часто не годится: если у модуля обработчика подписки расширения нет флага
«Внешнее соединение», любая запись подписанного объекта по COM падает с «Обработчик события не найден».
Тогда шаги 1–5 выполнять внутри базы — через HTTP-сервис, который выполняет код (сервер данных базы).

## Выгрузка объектов

### Объект не выгружается сам — «ждём, пока выгрузится»

- **Причина:** ПВД объекта нет или его `ПередОбработкойПравила` / `ПередВыгрузкойОбъекта` ставит
  `Отказ = Истина`; объект уходит только значением свойства других объектов (например, контрагент — только
  как реквизит договора). Часто это рабочая схема, а не ошибка — уточнить у владельца правил.
- **Проверка:** `rules_get kind=pvd` — обработчики ПВД; кто ссылается на ПКО объекта — ПКС других ПКО с его
  `КодПравилаКонвертации`, их `ПередВыгрузкой` (`ВыгрузитьОбъект = Истина` — объект уходит целиком).

### Объект по ссылке: целиком или только ссылкой

- Значение ссылочного свойства выгружается объектом целиком, если объекта ещё нет в регистре соответствий для
  узла (объект добавляется туда как «выгружен по ссылке»); иначе — только узлом `<Ссылка>` со свойствами поиска
  (`ВыгрузитьСвойства`, стр. 13173–13190).

## Как пополнять

- Только универсальное: без имён баз, организаций, контрагентов и людей; пример — обезличенный.
- Только с доказательством: процедура и строки БСП (версия — в шапке) или воспроизведение в песочнице;
  что не воспроизводилось на живой базе — так и написать.
- Формат: симптом → причина → проверка → исправление.
- Грабли, которые ловятся по тексту правил без баз, — ещё и проверкой в `rules_validate`
  (`src/kd2_rules_mcp/validation/`, код проверки — в заголовке раздела).
