# Как БСП исполняет правила обмена через универсальный формат

Правила такого обмена — код общего модуля менеджера обмена (его генерирует «Конвертация данных 3»). Исполняет их
подсистема «Обмен данными» БСП. Ссылки ниже — имя процедуры и строки в БСП **3.1.12**: `XDTO:N` — общий модуль
`ОбменДаннымиXDTOСервер` (`CommonModules/ОбменДаннымиXDTOСервер/Ext/Module.bsl` в выгрузке любой конфигурации на
БСП), `ОСКД:N` — `КонвертацияОбъектноСобытияКД`, `КОС:N` — `КонвертацияОбъектноСлужебный`. В другой версии БСП
строки сдвигаются, процедуры — те же; перед тем как ссылаться на строку в ответе человеку, найди процедуру в
выгрузке его конфигурации (сервер кода проекта).

Всё здесь прочитано по коду, без запуска обмена. Что не проверено — сказано явно.

## 1. Какая версия формата и какой модуль менеджера работают

- **Карта «версия формата → общий модуль менеджера».** `ВерсииФорматаОбмена` (XDTO:9038–9086): для узла — из
  настроек плана обмена (ключ `ВерсииФорматаОбмена`, заполняется в модуле менеджера плана), без узла — из
  `ОбменДаннымиПереопределяемый.ПриПолученииДоступныхВерсийФормата` (9043–9048). Пустая карта — исключение
  (9050–9073). В конфигурации карта может быть записана в двух местах — сверяй оба.
- **Модуль по версии** — `МенеджерОбменаВерсииФормата` (XDTO:3566–3578); версии нет в карте — исключение
  «Не определен Менеджер конвертации».
- **Выбор версии.** `МаксимальнаяОбщаяВерсияФормата` (XDTO:3650–3670): наибольшая версия корреспондента, которая
  есть в своём списке; общей нет — `"0.0"`. Результат записывается в реквизит узла `ВерсияФорматаОбмена` при
  настройке из сообщения (4016–4017) и при каждом получении (`ОбновитьНастройкиXDTOКорреспондента`, 8163–8189).
- **Пустая версия в узле при выгрузке** — берётся **минимальная** поддерживаемая (`ВерсияФорматаОбменаПриВыгрузке`,
  XDTO:3612–3623; `МинимальнаяВерсияФорматаОбмена`, 9114–9133). Если разным версиям назначены разные модули
  менеджера, работать будет не тот модуль, который ты читаешь.
- **При получении** версия берётся не из узла, а из пространства имён сообщения; по ней выбирается модуль
  (`ОткрытьФайлЗагрузки`, XDTO:2386–2397).

Три разные «версии», которые нельзя путать:

| Что | Пример | Где смотреть |
|---|---|---|
| имя пакета формата в конфигурации | `EnterpriseData_1_8_6` | папка `XDTOPackages` выгрузки; `ed_schema_open(package=…)` |
| версия формата обмена (ключ карты, конец URI пакета) | `1.8` | карта версий плана обмена; `format_version` у `ed_schema_open` |
| версия модуля менеджера | `2` | функция `ВерсияФорматаМенеджераОбмена()` модуля; `manager_version` в ответе `ed_open` |

Версию модуля менеджера исполнитель читает в `ИнициализироватьТаблицыПравилОбменаРасширенный` (XDTO:4770–4774); при
любом исключении считает её равной `"1"`. При `"3"` процедуры заполнения получают другие параметры:
`ЗаполнитьПравилаКонвертацииОбъектов(КомпонентыОбмена, КоллекцияПравил, ТолькоЗаголовки)` (4716–4728), ПКПД — с
`КомпонентыОбмена` первым параметром (4730–4742); `ЗаполнитьПравилаОбработкиДанных` всегда вызывается как
`(НаправлениеОбмена, Правила)` (3917).

## 2. Что исполнитель делает с правилами при загрузке модуля

- **ПКО без типа формата исчезает молча.** `ТаблицаПравилКонвертации` (XDTO:4146–4158): если `ОбъектФормата`
  заполнен, а такого типа нет в пакете выбранной версии (и в расширениях формата этого правила), строка правила
  удаляется без сообщения. Так же молча при получении удаляются ПОД (`ТаблицаПравилОбработкиДанных`, 3946–3950).
  Один модуль обслуживает несколько версий формата, поэтому для старой версии часть правил закономерно пропадает.
- **Ключевые и общие свойства.** `ОтметитьКлючевыеСвойстваПравилаКонвертации` (XDTO:4884–4931) сравнивает имя
  свойства формата из ПКС со списком ключевых; группы «общие свойства» (тип с именем `ОбщиеСвойства…`)
  разворачиваются (`ЗаполнитьСписокСвойствОбъектаXDTO`, 9546–9557). В ПКС такие свойства пишут плоским именем,
  без имени оболочки; полное имя через точку тоже поддержано (6746–6750; при выгрузке 1514–1515, 1582–1589).
  `ed_schema_type` показывает оба вида: `physical_path` (с оболочкой) и `effective_path` (как в правиле).
- **Табличная часть формата** — свойство, тип которого содержит ровно одно свойство с верхней границей не 1
  (`ЭтоТаблицаОбъекта`, XDTO:5681–5691); при чтении строки берутся по имени `Строка` (6441).
- **Расширения формата.** Расширение у ПКО регистрирует вызов
  `ОбменДаннымиXDTOСервер.ИнициализироватьРасширениеПравилаКонвертацииОбъекта` в процедуре правила (XDTO:4808–4817).
  При получении свойство из пространства имён, которое не активно, пропускается
  (`КонвертацияСвойстваXDTOВЭлементСтруктуры`, 6193–6197; `ПространствоИменАктивно`, 7245–7250). Сторона выгрузки
  не проверена.

## 3. Обработчики: кто и когда их вызывает

**События конвертации** (`ПередКонвертацией`, `ПослеКонвертации`, `ПередОтложеннымЗаполнением`) исполнитель вызывает
у модуля менеджера напрямую (XDTO:604, 672, 2192, 4974–4995, 7150); так же — `ЗаполнитьПараметрыКонвертации` (4803).
Процедуры должны существовать, хотя бы пустые. `ПередОбработкойУдаляемогоОбъекта` (`ПриУдаленииОбъекта`,
8743–8748) вызывается в `Попытка` с пустым `Исключение`: отсутствие процедуры допустимо, но и любая ошибка внутри
неё молча проглатывается.

**Обработчики правил** вызываются не напрямую, а по строковому имени из правила через диспетчер модуля менеджера —
`ВыполнитьПроцедуруМодуляМенеджера` (для `ВыборкаДанных` — `ВыполнитьФункциюМодуляМенеджера`):

| Событие | Обёртка исполнителя | Ошибка в обработчике |
|---|---|---|
| ПОД `ПриОбработке` | `ПриОбработкеПОД`, XDTO:8428–8472 | не исключение: `Отказ`, объект пропускается, результат обмена «Ошибка» (8450–8466) |
| ПОД `ВыборкаДанных` | XDTO:8483–8530; только в обмене без плана обмена (641–650) | перевыбрасывается |
| ПКО `ПриОтправкеДанных` | XDTO:8545–8587 | перевыбрасывается |
| ПКО `ПриКонвертацииДанныхXDTO` | XDTO:8597–8638; в обычном пути вызывается всегда (1869–1873) | перевыбрасывается |
| ПКО `ПередЗаписьюПолученныхДанных` | XDTO:8652–8695 | перевыбрасывается |
| ПКО `ПослеЗагрузкиВсехДанных` | `ОтложенноеЗаполнениеОбъектов`, XDTO:7141–7239 | перевыбрасывается, транзакция откатывается |

Диспетчер — цепочка `Если ИмяПроцедуры = "…" Тогда …` без общей ветки «Иначе». **Имя, для которого ветки нет,
молча ничего не вызывает**: наличие самой процедуры в модуле не помогает. Это ловит `ed_validate`
(`ed.handler.missing`).

**У получения два пути** (`ПрочитатьСообщениеОбмена`, XDTO:7358–7384): обычный и «объектная конвертация»
(реквизит узла `ОбъектнаяКонвертацияXDTO`). Набор событий разный:

| Событие | Обычный путь | Объектная конвертация |
|---|---|---|
| `ПередКонвертацией`, `ПослеКонвертации` | ошибка прерывает обмен | ошибка записывается, обмен продолжается (ОСКД:95–112, КОС:1525–1545) |
| `ПередОтложеннымЗаполнением`, `ПослеЗагрузкиВсехДанных` | вызываются | **не вызываются** (XDTO:2172–2180) |
| `ПослеКонвертацииОбъекта`, `ПриУдаленииОбъектаИБ` | **не вызываются** (только флаги, XDTO:4200, 4203) | вызываются через диспетчер (ОСКД:138–180, 403–430) |

Обработчик события запроса выгрузки объекта в БСП 3.1.12 по коду не работает: исполнитель читает поле, которого в
таблице правил нет (ОСКД:253–254; колонка называется иначе, XDTO:3266). Исполнением не проверено. Путь объектной
конвертации в остальном (перенос данных в найденный объект, порядок событий) не разобран — утверждений о нём
без чтения кода не делай.

**Отложенная обработка** (`ПослеЗагрузкиВсехДанных`, XDTO:7197–7210): в обработчик передаётся структура с полями
`Объект`, `КомпонентыОбмена`, `ОбъектМодифицирован`; `ОбъектМодифицирован` по умолчанию `Истина` — объект
записывается, если обработчик не сбросил флаг. Новые объекты пропускаются (7175–7177), объект перечитывается из
базы (7190–7195). В очередь объект попадает только при непустом имени обработчика в правиле (7079–7105).

**`ИспользованиеПКО` в `ПриОбработке` ПОД** — структура, ключи которой — имена правил из `ИспользуемыеПКО` этого
ПОД, значения `Истина` (`ПравилаКонвертацииИзПравилаОбработки`, XDTO:8402–8414). Обращение к ключу, которого там
нет, — ошибка платформы; исполнитель превращает её в отказ по объекту (8440–8466). Значение `Ложь`: при выгрузке
— выгрузить удаление, если правил несколько (805…); при получении — в удаляемые при синхронизации по
идентификатору (7489–7497).

## 4. Конвертация свойств и объектов

- **Правило у ПКС.** При выгрузке (`ВыгрузитьСвойство`, XDTO:1539–1567) имя правила ищется сначала среди ПКПД
  (1543), затем среди ПКО (`ПКОПоИмени`, 1554) — и только если значение заполнено; при получении
  (`КонвертацияСвойстваСтруктурыОбъектаXDTO`, 6813–6827) — только для значения-структуры. Не найдено —
  исключение «Не найдено ПКО с именем…» (502–516) в момент, когда поиск понадобился. Имя правила может подменить
  обработчик инструкцией — структурой с ключами `Значение` и `ИмяПКО` (1530–1537, 6799–6810).
- **Отсутствующее ПКО в `ИспользуемыеПКО` ПОД.** При выгрузке молча пропускается (`ВыгрузкаОбъектаВыборки`,
  XDTO:794–799); при получении — исключение, результат обмена «Ошибка» (`ОбработатьДанныеСообщенияЛинейно`,
  7455–7475, 7592–7594).
- **Ссылка по уникальному идентификатору.** `СтруктураОбъектаXDTOВДанныеИБ` (XDTO:1809–1846): объект пришёл
  ссылкой из другого объекта, вариант идентификации — `ПоУникальномуИдентификатору`; не найден в базе —
  возвращается ссылка **без создания объекта** (1838–1843). Сам объект создастся, только если придёт полностью
  (своим ПОД).
- **Обновление найденного объекта (обычный путь).** `ЗаполнитьДанныеИБПоПолученнымДанным` (XDTO:7013–7064):
  в найденный объект переносятся только реквизиты, для которых есть ПКС шапки (7022, 7047); свойства, которых не
  было в сообщении, исключаются (6753–6765) — но сравниваются имена формата с именами конфигурации (6745 против
  7035): при разных именах защита не срабатывает. Табличная часть из ПКТЧ — `Очистить()` и `Загрузить()`
  (7051–7062), без проверки, была ли она в сообщении. `ПередЗаписьюПолученныхДанных` (1975) выполняется **до**
  переноса (1988): то, что обработчик записал в `ДанныеИБ` по реквизитам с ПКС, перенос затрёт; обнулённые
  `ПолученныеДанные` перенос отменяют (1987).
