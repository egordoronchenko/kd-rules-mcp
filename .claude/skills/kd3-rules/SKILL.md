# Обмен через универсальный формат: разбор и проверка

Правила такого обмена — код общего модуля менеджера обмена, который генерирует «Конвертация данных 3» и исполняет
БСП. Сервер `kd-rules-mcp` читает модуль **без исполнения**, раскладывает на правила (ПКО, ПКС, ПОД, ПКПД,
обработчики, алгоритмы), проверяет связность и сверяет со схемой формата. Типовой модуль сервер не правит; доработку
существующего правила объекта (свойство шапки, обработчик события ПКО, сохранение значения при отсутствии свойства,
алгоритмическое свойство отправки) выпускает расширением — `references/authoring.md`.

Термины — `kd2-rules-build/references/glossary.md`; инструменты — `kd2-rules-build/references/tools.md`; проверки —
`kd2-rules-build/references/checks.md` (оба большие: искать по имени инструмента или идентификатору проверки, не
читать целиком); серверы MCP для 1С — `kd2-rules-build/references/mcp-1c.md`, прочитать перед первым их вызовом.

## 0. До первого вызова

- «Версия» у человека — почти всегда версия формата обмена (`1.8`), не имя пакета и не `manager_version`.
- Один модуль — несколько версий формата; какой модуль работает, решает карта версий (`references/executor.md`, §1).
- Правило в модуле ещё не значит «работает»: тип не в пакете, нет ветки диспетчера, два пути получения.
- Типовой модуль на поддержке не правят — доработка расширением.

Подробно — `references/reading.md`, §0.

## 1. Порядок работы

1. Найти модуль (сервер кода проекта или выгрузка); отправку читают в источнике, получение — в приёмнике.
2. `ed_open` → `parse_status`; `partial` — `ed_overview`, выводов об отсутствии рядом не делать.
3. `ed_validate` **сразу** — замечания «до правок»; критерий доработки — **нет новых**.
4. `ed_list` → `ed_get(address)`; текст — `include_text`; от строки модуля — `ed_locate(line)`.
5. Что обработчик трогает — `ed_get(…, children_kind="reference")`; `unparsed` — читать глазами.
6. Схема — `ed_schema_open` → `ed_schema_type`.
7. `ed_validate(project_id, schema_id, structure_id, direction)`; без них — `skipped`, это «не проверено».
8. `ed_close`, `ed_schema_close`.

Шаги с разбором ответов — `references/reading.md`, §1. Проект дорабатывает обмен расширениями — открывать модуль
**вместе с ними** (`references/layers.md`); авторинг — на снимке с `extensions=[]`.

## 2. Отчёт и границы

- Замечания `ed_validate` расставлять по последствиям для обмена, а не по уровню (`references/validate.md`).
- Данные баз — только сервер данных песочницы и только с согласия человека в этой задаче; боевую базу не трогать.
- Выводы — по коду: адрес правила, строка модуля, процедура исполнителя БСП; «проверено чтением» и «проверено
  обменом» не смешивать; что не проверено — перечислить (`references/questions.md`, §4).
