# Правила обмена КД 2 через `kd-rules-mcp`

Сервер `kd-rules-mcp` (нет его — скилл `kd-install`) детерминированный: разбирает, предлагает кандидатов, пишет
XML и проверяет. Что во что конвертировать, решает агент — и пишет это в отчёт. Где что лежит — `project_list`;
сервер пишет только в рабочую папку (`workspace`) и в `rules_dir` с `writable`. Перенос в макет проекта 1С — по
правилам того проекта, не этим сервером.

## 0. Структуры

`project_list` → **в начале каждой задачи** `structure_load_project(project)` для обеих сторон (кэш —
`reused: true`; после ручной правки XML — `force: true`). Объект — `structure_object`, значения —
`structure_values`. После обновления конфигурации — новая структура, `structure_compare`, `rules_validate`.
Подробности — `references/start.md`.

## 1. Правила

- Перед `rules_open` — `rules_projects`; проект уже открыт другим агентом — `rules_open(path, private: true)`.
- Доработка: `rules_open` → `rules_validate` со структурами **до правок** — запомнить исходные замечания.
  Только проверить чужие правила — `references/review.md`. Новые правила — `rules_create(source, target)`.
- Перед созданием своего правила откройте 1–2 похожих (`rules_list`, `rules_get`) и оформите так же.

## 2. Порядок построения: ПКО → ПКС → ПВД → ПРО

1. Объект: `match_objects` **всегда с `text`** (и `kind`); ПКО для объекта ещё нет (`rules_list pko`).
2. ПКО с ПКС — `pko_create_from_candidates`; `unresolved` и `not_applied` (`auto: false`) — только решением агента.
3. ПКЗ — `match_values`, `rule_create kind=pkz`.
4. ПВД — `rule_create kind=pvd` по образцу существующего (`references/pvd.md`).
5. ПРО — `structure_plan_content`, `registration_build`, `rules_validate` со структурой источника, `rules_save`.
6. Обратное направление — `correspondent_draft` (`references/correspondent.md`).

Реквизит в существующее ПКО: `rules_get` → `match_properties` → `rule_create kind=pks` → `rules_validate`.
Код обработчиков: выгрузочные — против источника, загрузочные — против приёмника; переменные — `handlers_export`;
**перед первым вызовом серверов 1С — `references/mcp-1c.md`**. Всё это с разбором ответов —
`references/build-order.md`.

## 3. Чек-лист проверок (все — до переноса в проект)

Команды и чтение итога — `references/checklist.md` и `references/checks.md`. Скрипты `kdbase` — из папки клона
сервера; `bsp_check` и `exchange_check` — только базы роли «песочница».

- [ ] `rules_validate` с обеими структурами: **нет новых** замечаний относительно §1.
- [ ] Менялся код — `handlers_export` → синтакс-чекер → `handlers_locate`.
- [ ] `rules_save`; `format_check` без ошибок. Загрузка из файла — `rules_pack`: `warnings` пусты.
- [ ] `kd_check` → `ИТОГ OK`; `bsp_check` → `ИТОГ OK`, если правила грузятся в эту песочницу.
- [ ] `exchange_check`, если правились поиск или загрузка и есть две песочницы с сервером данных.
- [ ] Удаление — пометкой; физическое — только после отдельного «да» человека.
- [ ] ПРО пересобирались — `rules_validate` проекта ПРО со структурой источника.
- [ ] Отчёт: объекты и почему, решения по `unresolved`/`not_applied`/выключенным ПКС, замечания до и после, путь.

Ступень не запускалась — так и сказать: «не прогонялась».

## 4. Живые правила в `rules_dir`

Правка загрузки — и в правила корреспондента второго проекта; боевая база — никогда; перед коммитом —
`rules_diff`; коммит — с «да» человека (`references/live-rules.md`).

## 5. Состояние для передачи

Перед паузой или передачей — `rules_save` и запись по `references/handoff.md`.
