# ПКЗ и перечисления: формат, конвертация в БСП, автосопоставление
Читать, когда конвертируете перечисления или предопределённые элементы между конфигурациями.

Ссылки `(Процедура, стр. N)` — модуль `DataProcessors/КонвертацияОбъектовИнформационныхБаз/Ext/ObjectModule.bsl`
(БСП 3.1.12); `reference/kd2-cfg/…:N` — выгрузка КД 2.1.8.2; `MD83Exp:N` —
`reference/kd2-dist-src/MD83Exp/ВыгрузкаМетаданных/Ext/ObjectModule.bsl`.

## Формат `<Значение>`

- Писатель (`reference/kd2-cfg/DataProcessors/ВыгрузкаКонвертации/Ext/ObjectModule.bsl:563-607`): `<Значение>` с
  `Код, Наименование, Порядок, Описание, Комментарий, Источник, Приемник`; `<Группа>` — те же реквизиты и вложенные
  значения. Пустые теги не пишутся (:83-95): ПКЗ с пустым приёмником — без `<Приемник>`.
- `Источник`/`Приемник` — `Наименование` элемента справочника `Значения` (:583, :586), то есть **имя** значения
  перечисления (MD83Exp:1657) или имя предопределённого (MD83Exp:1737-1747; без имени — код или представление,
  :1749). Не синоним и не представление: синоним — отдельное поле (`ЗагрузкаСтруктурыМетаданных`, :848-851).
- В КД ПКЗ ссылается на `Справочник.Значения`
  (`reference/kd2-cfg/Catalogs/ПравилаКонвертацииЗначений.xml:345-394`); строки `ЗначениеИсточник` /
  `ЗначениеПриемник` — только для формы (`…/ПравилаКонвертацииЗначений/Ext/ObjectModule.bsl:10-15`).

## Чтение правил в БСП

- ЗагрузитьЗначения / ЗагрузитьПКЗ (стр. 5682–5728): из `<Значение>` берутся только `Источник` и `Приемник`; нет
  `Источник` — правило пропущено (стр. 5700–5702); нет `Приемник` — пустая строка (стр. 5685). Разбираются только
  узлы `<Значение>`, группы ПКЗ схлопываются (стр. 5720–5721).
- Хранятся в структуре «имя источника → имя приёмника» (ЗагрузитьПравилоКонвертации, стр. 5883;
  колонка таблицы ПКО, стр. 14079).
- **ПКЗ применяет только отправитель**: имена превращаются в ссылки лишь в режиме «Выгрузка»
  (ВосстановитьПравилаИзВнутреннегоФормата, стр. 7069–7075; ПолучитьЗначенияПредопределенныхДанных,
  стр. 15865–15873). Перечисление — по имени (одПолучитьЗначениеПоСтроке, стр. 3998–4000; одНайтиОбъектПоСвойству,
  стр. 3907–3909); прочее — предопределённый по имени, затем по коду, иначе пустая ссылка (стр. 3920–3928, 4002).
  Приёмник получает готовое имя; для обратного направления нужны свои ПКЗ в правилах другой стороны.

## Перечисление при выгрузке (ВыгрузитьПоПравилу, стр. 701–782, 845–876)

- Пустое значение — ни ПКО, ни ПКЗ не вызываются, уходит узел без значения (ВыгрузитьСвойства, стр. 13103–13126).
- ПКЗ для значения есть — возвращается имя приёмника (стр. 743, 876); в свойство пишется `<Значение>Имя</Значение>`
  с `Тип` = приёмник ПКО (ВыгрузитьСвойства, стр. 13217–13236). Пустое имя — пустое `<Значение>`.
- ПКЗ для значения нет, приёмник ПКО — `ПеречислениеСсылка.*`: протокол 71 «Не найдено соответствие для значения
  Источника» с текстом «…если подходящего значения приемника нет, то укажите пустое значение» (стр. 748–764),
  свойство не выгружается (стр. 772; ВыгрузитьСвойства, стр. 13211–13213). Код 71 взводит флаг ошибки и результат
  обмена «Ошибка» (ЗаписатьВПротоколВыполнения, стр. 4833–4839). Без протокола — ссылка, которой нет в базе
  (значение удалённого расширения, стр. 751–753).
- У ПКО перечисления нет ни одного ПКЗ — сопоставление пропускается (стр. 738), значение идёт общим путём объекта
  (стр. 788–843), имени в сообщении нет (что получит приёмник — не проверено). ПКЗ задавать всегда.

## Загрузка в приёмнике

- `<Значение>Имя</Значение>` с `Тип="ПеречислениеСсылка.X"` → `Перечисления.X[Имя]` (одЗначениеЭлемента,
  стр. 4529; одПолучитьЗначениеПоСтроке, стр. 3996–4000; одНайтиОбъектПоСвойству, стр. 3907–3909). Пустая строка —
  пустая ссылка (стр. 3983–3985). Имени нет в перечислении приёмника — исключение на `Менеджер[Имя]` (не проверено,
  как оно доходит до протокола).

## Предопределённые элементы

- Поиск по предопределённым разрешён у справочников, ПВХ, планов счетов и видов расчёта (ИнициализацияМенеджеров,
  стр. 14441, 14453, 14459, 14465); у документов и прочих — нет.
- Источник предопределённый и для него есть ПКЗ — имя приёмника уходит в `<Ссылка>` свойством
  `{ИмяПредопределенногоЭлемента}` вместе со свойствами поиска (ВыгрузитьПоПравилу, стр. 705–736, 790–791;
  ВыгрузитьСвойства, стр. 12806–12818). ПКЗ нет или элемент не предопределённый — обычный поиск, без ошибки
  (ВыгрузитьПоПравилу, стр. 776).
- Приёмник ищет после регистра сопоставления по имени предопределённого, без создания; не нашёл — по коду, иначе
  продолжает обычный поиск (НайтиОбъектПоСсылке, стр. 8790–8817; одНайтиОбъектПоСвойству, стр. 3920–3928).

## Автосопоставление в КД (`reference/kd2-cfg/DataProcessors/АвтонастройкаПравилКонвертацииЗначений/…`)

- Пара — точное равенство `Наименование` (имени) значений источника и приёмника внутри одного родителя
  (`СинхронизироватьЗначение`, :335-348; вызов :265-266). Синоним только показывается (:109-110, :215, :275).
- Несопоставленные значения приёмника — строки без источника (:268-277), источника — без приёмника (:207-217).
- `СохранитьПравилаКЗ` (:405-442) создаёт ПКЗ для отмеченных строк без ПКЗ, порядок шагом 50 (:432). Пустой
  приёмник код не проверяет (:410), хотя комментарий обещает (:399-400): получится ПКЗ «в пустое значение».

## Рецепт: перечисление с разным составом значений

1. ПКО `ПеречислениеСсылка.A` → `ПеречислениеСсылка.B`; ПКС ссылаются на него `КодПравилаКонвертации` (без кода
   найдётся по типу значения — `pks.md`, «Ссылочное значение»).
2. ПКЗ на **каждое** значение источника: совпавшие по имени — кандидаты `match_values`; переименованные — вручную
   по смыслу (синоним — подсказка, не ключ).
3. Значение источника без аналога — ПКЗ в ближайшее значение или в пустое (без `<Приемник>`). Без ПКЗ — протокол
   71 и результат обмена «Ошибка».
4. Значения, которые есть только в приёмнике, ПКЗ не требуют. Новое значение в источнике (доработка, расширение)
   — новое ПКЗ, иначе снова 71.
5. Обратное направление — отдельные ПКЗ в правилах другой стороны; взаимно однозначными они быть не обязаны.
6. Значение зависит от данных: ПКС без `КодПравилаКонвертации`, `Тип` приёмника `ПеречислениеСсылка.B`, в
   `ПередВыгрузкой` — `Значение = "ИмяЗначенияВПриемнике"`. Строка в неизвестный тип уходит как есть
   (ОпределитьВозможностьУстановкиЗначения, стр. 12497–12527), приёмник читает её по имени (путь по коду, живым
   обменом не проверено).
