# Обработчики событий КД 2 в обмене через БСП: фазы, переменные, ошибки
Читать перед тем, как писать, переносить или ревьюить код обработчиков правил обмена.

Исполнитель — `DataProcessors/КонвертацияОбъектовИнформационныхБаз/Ext/ObjectModule.bsl` (БСП 3.1.12), ссылки
`(Процедура, стр. N)`; `ОбменДаннымиСервер, стр. N` — общий модуль той же БСП; `ВК:N` — писатель КД 2.1.8.2
`reference/kd2-cfg/DataProcessors/ВыгрузкаКонвертации/Ext/ObjectModule.bsl`. Точный набор параметров каждого
обработчика — `handlers_export` (по макету КД `ПараметрыОбработчиков`). ПВД — `pvd.md`; поиск — `search.md`.

## Где и когда вызывается

Выгрузка — в базе-источнике, загрузка — в базе-приёмнике. «Отказ → …» — что делает БСП, если обработчик поставил
`Отказ = Истина`.

## Как выполняется код

- Текст обработчика выполняется `Выполнить(<текст>)` прямо внутри процедуры модуля обработки (например, стр. 577,
  10570, 12941). Поэтому видны все параметры и локальные переменные этой процедуры, переменные модуля и реквизиты
  обработки. `handlers_export` даёт документированный набор; реально доступно больше (например, `Правило` в ПВД
  `ПослеВыгрузкиОбъекта`, стр. 13526, — в макете его нет,
  `reference/kd2-cfg/DataProcessors/ВыгрузкаОбработчиков/Templates/ПараметрыОбработчиков/Ext/Template.txt:56–57`).
  На недокументированные локальные переменные не опираться — они меняются между версиями БСП.
- Отладка внешней обработкой в 3.1.12 отключена: при `ОтладкаОбработчиковВыгрузки`/`…Загрузки` обработка бросает
  «Внешняя обработка отладки, загружаемая из файла на диске, не поддерживается» (`ИнициализироватьОбработки`,
  стр. 14211–14216). Ветки `ВыполнитьОбработчик_*` (стр. 14847–15822) поэтому не используются.
- Безопасный режим: если у плана обмена есть профиль безопасности — весь сеанс в безопасном режиме
  (`ВыполнитьВыгрузкуДанных`, стр. 2198–2202; `ВыполнитьЗагрузкуДанных`, стр. 2482–2486); каждый `Выполнить`
  обёрнут в `ПрофильБезопасностиДляВыполнитьВычислить` (например, стр. 17959–17969), который без профилей
  безопасности возвращает пустую строку — тогда ограничений нет. `Выражение` из ПКС приёмник вычисляет
  `ОбщегоНазначения.ВычислитьВБезопасномРежиме` (`ПрочитатьСвойство`, стр. 8054–8057).

## Алгоритмы

- `Алгоритмы` — Структура «имя → текст» (стр. 14664, 6457, 6467). БСП текст в обработчики не подставляет, КД при
  записи правил тоже (ВыгрузитьАлгоритм, `ВК:1026–1047`): обработчик вызывает `Выполнить(Алгоритмы.Имя)`.
  Алгоритм работает в контексте вызвавшего: «параметры» — это переменные места вызова; поле `Параметры` алгоритма
  БСП не читает (`ЗагрузитьАлгоритм`, стр. 6440–6452).
- `ИспользуетсяПриЗагрузке = Истина` — алгоритм доступен **только при загрузке**: при выгрузке он лишь
  переписывается в правила для приёмника (стр. 6455–6464). `Ложь` — только при выгрузке (стр. 6465–6469).
  Алгоритм, нужный в обеих фазах, — два экземпляра. Запросы — так же (`ЗагрузитьЗапрос`, стр. 6527–6543).

## Переменные, доступные везде

- `Параметры` — реквизит обработки, Структура; ключи — из `<Параметры>` правил (`ЗагрузитьПараметры`,
  стр. 6581–6633). Кэш правил хранит ключи без значений (стр. 13877–13884, 7047): значения задавать в
  `ПередВыгрузкойДанных` / `ПередЗагрузкойДанных`. В приёмнике параметры с `ПередаватьПараметрПриВыгрузке`
  приходят узлами `<ЗначениеПараметра>` (стр. 17834–17846 → 7563–7587, 16164).
- `Алгоритмы`, `Запросы` (Структура «имя → Запрос», стр. 30, 7058–7063), `Конвертация` (тексты событий,
  стр. 14636–14643), `Правила` (ПКО по имени, стр. 7067–7077), `Менеджеры` (по типу, стр. 43).
- `УзелДляОбмена` — реквизит; при выгрузке — узел-получатель (`ОбменДаннымиСервер`, стр. 9993). В обработке
  загрузки его не заполняют — узел отправителя в `УзелОбменаЗагрузкаДанных` (`ОбменДаннымиСервер`,
  стр. 10009–10010). В загрузочных обработчиках `УзелДляОбмена` пуст.
- `ФайлОбмена` — при выгрузке поток записи сообщения (стр. 2181, 2189), при загрузке `ЧтениеXML` (стр. 7442).
- `ОбщиеПроцедурыФункции` в БСП **нет** — это переменная отладочного модуля КД; `handlers_export` объявляет её для
  синтакс-чекера. В правилах `ВыгрузитьПоПравилу`, `ЗаписатьОбъектВИБ` и т. п. вызывать напрямую — они в том же
  модуле.

## Исключение в обработчике

- `ПродолжитьПриОшибке` по умолчанию Ложь (`ОбменДаннымиСервер`, стр. 4955); Истина — только из настроек отладки
  правил, `НеОстанавливатьПоОшибке` (`ОбменДаннымиСервер`, стр. 5598, 10097).
- ПКО, ПКС, группы ПКС, ПВД: запись в протокол с флагом ошибки (`ЗаписатьВПротоколВыполнения`, стр. 4833–4841) и
  `ВызватьИсключение`, если не `ПродолжитьПриОшибке` (стр. 4976–4978, 4997–4999, 5028–5030, 5047–5049).
- **Выгрузка:** исключение из цикла → откат и повторное исключение (стр. 18515–18521) → `ПрерватьЗапись()`
  (стр. 18058–18063, 18086–18087): сообщение не формируется, `ПослеВыгрузкиДанных` не вызывается (стр. 18096).
  События конвертации выгрузки (`ЗаписатьИнформациюОбОшибкеОбработчикиКонвертации`, стр. 5053–5060) не бросают:
  `ПередВыгрузкойДанных` → отказ от выгрузки (стр. 17973–17984), `ПередПолучениемИзмененныхОбъектов` → выход без
  данных (стр. 18201–18205), `ПослеВыгрузкиДанных` → только протокол (стр. 18120–18123).
- **Загрузка:** «пропустить объект и продолжить» нет. Даже при `ПродолжитьПриОшибке` флаг ошибки после чтения даёт
  исключение (`ВыполнитьЗагрузкуДанных`, стр. 2503–2505, 2512–2514), транзакция откатывается (стр. 2520–2530),
  номер принятого не обновляется (`ЗакончитьЧтениеСообщения`, стр. 7684, не вызывается). `ПродолжитьПриОшибке`
  к тому же выключает транзакции (стр. 2470–2472). Что остаётся в приёмнике без транзакции — pitfalls,
  «Загрузка: ошибки и транзакции». События конвертации загрузки бросают сразу (стр. 7522, 7659, 17497–17501).
- `ПослеЗагрузкиПараметра` выполняется без `Попытка` (стр. 16182) — исключение прерывает загрузку.
- Это поведение БСП; дайджест формата §7 описывает V8Exchan83, где ошибка обработчика обмен не прерывает.

## Где лежат правила загрузки

- Отправитель пишет свои правила в сообщение (`ВыполнитьВыгрузкуДанных`, стр. 2232–2233), но приёмник берёт их
  оттуда, **только если у обработки ещё нет правил** (`НачатьЧтениеСообщения`, стр. 7485–7492).
- В штатной загрузке правила ставятся заранее: `ОбработкаОбменаДаннымиДляЗагрузки` →
  `УстановитьПравилаОбменаЗагрузкиДанных` читает `ПравилаЗачитанныеКорреспондента` (`ОбменДаннымиСервер`,
  стр. 10001–10083) — правила корреспондента из комплекта, загруженного в приёмник, зачитанные в режиме «Загрузка»
  (модуль менеджера РС `ПравилаДляОбменаДанными`, стр. 572–575, 615–619, 751–754, 794–797). Правила из сообщения
  используются, если правил корреспондента нет и у плана `НаличиеПравилКонвертацииОбязательно = Ложь`
  (по умолчанию Истина, `ОбменДаннымиСервер`, стр. 895, 10053–10067), и в обмене через внешнее соединение — там
  отправитель сам загружает свои правила в обработку приёмника (стр. 2208).
- Проверено живым обменом через файл: метка в `ПослеЗагрузки` ПКО из правил отправителя (была в сообщении) не
  сработала, сработала метка из правил корреспондента, загруженных в приёмник.
- Следствие: загрузочные обработчики и флаги ПКО в приёмнике — из **копии** правил отправителя, лежащей
  в приёмнике. Правка правил отправителя без перезагрузки комплекта в приёмник на загрузку не влияет. ПКО ищется
  по имени из атрибута `ИмяПравила` (стр. 906 → 10449, 10484): ПКО с этим кодом обязано быть в копии приёмника.
- `ПослеЗагрузкиПараметра`: события параметров собирает только разбор XML правил (стр. 6605–6609), в кэш правил
  они не входят (стр. 13886–13901, 7040–7050). При загрузке по кэшу корреспондента обработчик, по коду, не
  вызывается (живьём не проверено).

## Стандарты кода для обработчиков

Обработчик — код BSL, к нему применимы стандарты 1С. Тексты — на сервере справки: `standards()` — каталог,
`standards(name=…)` — правило (`mcp-1c.md`, «Потребность → инструмент»); здесь только какие брать и исключения.
Имена — из каталога набора `ai_rules_1c`; в другом каталоге сверить по `standards()`. Сервера справки нет — в
отчёте «стандарты не проверены» (`mcp-1c.md`, «Когда сервера нет»).

| Правило | Что смотреть в обработчике |
|---|---|
| `anti-patterns` §1–2 | запрос в цикле и реквизит через точку: обработчик ПКО и ПКС выполняется на каждый объект выгрузки, цена умножается на их число (вывод) |
| `anti-patterns` §4, §5a | отбор виртуальной таблицы в `ГДЕ`, временная таблица без индекса в соединении |
| `dev-standards-code-style` §2 | форматирование, имена, запрещённые конструкции — кроме исключений ниже |
| `query-design` | подготовка запроса; текст проверить `validatequery` сервера данных песочницы |
| `platform-solutions` §1, §6 | проверка на пустое (`ЗначениеЗаполнено`; грабля «`Если Реквизиты.Флаг Тогда`» в pitfalls), время на сервере |
| `locks-and-transactions` | загрузочный обработчик пишет другие объекты: загрузка уже может идти в транзакции — по константе приёмника (`ВыполнитьЗагрузкуДанных`, стр. 2496–2522; pitfalls, «Загрузка: ошибки и транзакции») |

Исключения — где стандарт к тексту обработчика не применяется:

- **Нет областей `#Область` и маркеров изменений.** Обработчик — фрагмент, который исполнитель выполняет
  `Выполнить(<текст>)` внутри своей процедуры (стр. 577, 10570, 12941), а не модуль; история правки — у файла
  правил (git `rules_dir`, база КД), не маркерами в тексте (вывод). `CodeOutOfRegion` чекера — шум (`mcp-1c.md`).
- **`Выполнить(Алгоритмы.Имя)` — штатный вызов алгоритма КД**, не нарушение запрета `Выполнить()` из
  `dev-standards-code-style` §2. Так его описывает справка КД
  (`reference/kd2-cfg/Catalogs/Алгоритмы/Ext/Help/ru.html:5`), и в эту форму КД сама переводит вызовы алгоритмов
  при загрузке обработчиков (`reference/kd2-cfg/DataProcessors/ЗагрузкаОбработчиков/Ext/ObjectModule.bsl:630`,
  `:671`). Исполнитель БСП сам алгоритм не вызывает: кладёт тексты в структуру `Алгоритмы` (стр. 6457, 6467) и
  выполняет текст обработчика, а тот — `Выполнить(Алгоритмы.Имя)` (раздел «Алгоритмы»). `ExecuteExternalCode`
  чекера на этой строке — ложное (`checks.md`, «Типичные ложные срабатывания»).
- **Переменные контекста не объявляются.** `Источник`, `Объект`, `Отказ`, `ПараметрыОбъекта`… — параметры и
  локальные переменные процедуры исполнителя, видимые в `Выполнить` (раздел «Как выполняется код»); присваивание
  в тексте меняет их значение для исполнителя (так работает `Отказ`). Объявлять их `Перем` не нужно (вывод).
- **Ошибка — средствами обмена.** Не продолжать — `Отказ` (что он делает — таблица «Где и когда вызывается»);
  остановить обмен — `ВызватьИсключение` с понятным текстом: исполнитель сам пишет его в протокол, журнал
  регистрации и результаты обмена (`ЗаписатьВПротоколВыполнения`, стр. 4787–4914). `Сообщить()` и своя запись в
  журнал — только если этого требует задача (`logging-strategy`).
