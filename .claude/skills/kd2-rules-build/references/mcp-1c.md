# MCP-серверы 1С в работе с правилами обмена

Правило читается по мере надобности: перед первым вызовом сервера 1С (код, метаданные, граф, справка, БСП,
шаблоны, проверка кода, сервер данных базы) в задаче — когда пишутся или разбираются обработчики и алгоритмы,
нужен API конфигурации или запрос в песочнице. В скилле `kd2-rules-build` лежит его копия `references/mcp-1c.md`.
Сопоставление объектов и реквизитов — инструменты `kd2-rules-mcp` (`structure_*`, `match_*`), не серверы 1С:
они знают расширения и формат КД.

## Основа — правила набора `ai_rules_1c` в проекте

Общие правила работы с серверами 1С здесь не повторяются: их даёт набор comol `ai_rules_1c`
(https://github.com/comol/ai_rules_1c), который стоит в проекте 1С вместе с серверами. Прочитай перед первым
вызовом:

- `mcp-policy` — обязательства, бюджет валидаторов, ответы серверов и действия по ним;
- `mcp-first-search` — индексы проекта раньше `Grep`/`Glob`/чтения файлов целиком.

Где лежат: `<папка проекта>\.cursor\rules\mcp-policy.mdc` и `mcp-first-search.mdc`; для Claude Code набор
кладёт их в `.claude\rules-1c\` (`.md`), для Codex — в `.codex\rules\`; точный список — раздел `files` в
`<папка проекта>\.ai-rules.json`. Папка проекта — `folder` в `project_list`. Агент, запущенный не в папке
проекта (в папке сервера kd2-rules-mcp или другого проекта), этих правил рядом не имеет — читает по пути.
Подробности по каждому серверу — `<папка проекта>\.cursor\skills\mcp-1c-tools\docs\<сервер>.md` (или
`.claude\skills\…`). Набора нет — работать по этому файлу и написать в отчёте «правила набора не найдены».

Ниже — только дельта для правил обмена. Где она расходится с набором, действует она: набор рассчитан на правку
исходников проекта, а обработчики правил живут не в исходниках.

## Какой сервер — для какой базы

Серверы называются ролями. Имя роли — из `project_list` (`code_mcp`, `data_mcp` у баз-песочниц, `shared_mcp`) и
списка серверов, подключённых к клиенту: из папки сервера kd2-rules-mcp серверы проекта подключены с префиксом
`<проект>-`, в папке проекта 1С — как в его `.mcp.json`.

- **Серверы кода проекта** (`code_mcp`) — код и метаданные, граф. Проект выбирает **фаза обработчика**:
  выгрузочный — сервером проекта-источника, загрузочный — сервером проекта-приёмника (таблица фаз — скилл
  `kd2-rules-build`). Не искать API приёмника в коде источника и не подменять индекс соседним проектом.
- **Общие** (`shared_mcp`): синтакс-чекер, проверка кода, справка платформы, поиск по БСП, шаблоны кода (в пакете
  comol — `1c-syntax-checker-mcp`, `1c-code-check-mcp`, `1C-docs-mcp`, `1c-ssl-mcp`, `1c-templates-mcp`).
- **Сервер данных базы** — только у песочниц (`data_mcp` базы в `project_list`).

## Потребность → инструмент

| Нужно | Сервер и вызов |
|---|---|
| Есть ли объект, реквизит, табличная часть; поля виртуальных таблиц регистра | сервер кода проекта: `metadatasearch(query, names_only=true, object_type="Справочники")` → `get_metadata_details(object_name="Справочник.Контрагенты", sections="attributes,tabular_parts,standard_attributes")`, для регистра — `sections="virtual_tables"`; большой ответ — `detail_level`, `max_items` и `cursor` |
| Объекты по условию или по смыслу (выбор состава обмена) | сервер графа: `search_metadata` (JSON-операции), `search_metadata_by_description` — прозой |
| Код процедуры конфигурации, которую зовёт обработчик | `search_function(name, include_body=false)` → то же с телом (`max_body_chars`); модуль — `get_module_structure(module_path)`; по тексту — `codesearch(query)` |
| Паспорт объекта; кто его пишет и вызывает (разбор чужого обработчика) | сервер графа: один раз `list_graph_projects` → `project_id` проекта своей фазы, дальше **в каждом вызове**: `get_object_dossier`, `find_usages_of_object`, `trace_call_chain`, `search_code(query, search_type=…, project_id)` |
| Функция БСП: сигнатура и что возвращает | поиск по БСП: `ssl_search(query="ОбщегоНазначения.ЗначенияРеквизитовОбъекта", detail="full")`; дальше — по `doc_id` из ответа; версию БСП сверить с конфигурацией, код — сервером кода проекта |
| Метод или тип платформы | справка: известно имя — `docinfo(name="Массив.Найти")`, иначе `docsearch(query, detail_level="compact")`; `since` сверить с режимом совместимости (`CompatibilityMode` в `Configuration.xml`) |
| Стандарты кода | справка: `standards()` — каталог, `standards(name=…)` — правило; через `docsearch` стандарты не находятся |
| Статья ИТС | проверка кода: `its_help` → `fetch_its` по каждому идентификатору, на который опираешься |
| Образец кода | шаблоны: `templatesearch(query)` — запрос прозой задачи, не ключевыми словами → `get_template(template_id)` |

## Проверка кода обработчиков

1. `handlers_export` — каждый обработчик отдельным `.bsl` с обёрткой из переменных события (как у КД).
2. По каждому изменённому файлу — `syntaxcheck(code=<текст файла>, file_name="<имя>.bsl")`. **Не**
   `syntaxcheck_file` (в наборе это форма по умолчанию) и не `files=` у `check_1c_code`: серверы видят только
   смонтированные у них исходники, рабочая папка kd2-rules-mcp и папки правил им не видны.
3. Логика и производительность — `check_1c_code(code=…)`; стиль — `review_1c_code(code=…)`, по надобности.
   Синтаксически битый код в них не отправлять.
4. Номер строки из ответа → `handlers_locate` (обработчик и строка в правилах).

Бюджет — как в наборе: один чистый прогон каждого проверяющего на последнем состоянии; блокирующая ошибка —
исправить и одно подтверждение; повтор на неизменённом тексте — нет; бюджет кончился без чистого прогона — «не
проверено». Чекер не ловит необъявленные переменные и вызовы несуществующих методов — это проверяют серверы кода
проекта. `CodeOutOfRegion` и подобный стиль для текста обработчика — шум.

## Сервер данных базы (песочница)

`validatequery(querytext)`, `vcexecutequery(querytext)` — запрос **в одну строку**, параметры прямо в тексте;
паролей и секретов в тексте нет — он идёт по HTTP. `vcexecutecode(bslcode)` — результат через переменную
`Результат`. Код — **одной строкой** (многострочный не выполняется, ответ пустой без ошибки); без `Процедура` /
`Функция` (код идёт через `Выполнить`); у `Новый Тип(…)` метод не вызвать — сначала в переменную; оборачивать в
`Попытка … Исключение Результат = ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()); КонецПопытки;`, последняя
ошибка журнала — `vcloggetlasterror`. Запись в базу — только в песочнице и с согласия пользователя; живая проверка
обмена — скрипт `exchange_check` из клона сервера (`references/checks.md`), не руками.

Клиент получил 404 на OAuth от базы с пользователями — сервер есть: в его записи в конфигурации MCP клиента нужен
заголовок Basic с логином базы (в папке сервера kd2-rules-mcp его пишет настройка машины), затем перезапуск
клиента. Сам сервис проверяется прямым HTTP-вызовом `tools/list`.

## Ответ сервера → действие

Полная таблица — `mcp-policy`, раздел C; здесь — ответы серверов, которые зовёт работа с правилами.

| Ответ | Сервер | Действие |
|---|---|---|
| `stale_generation` | граф | повторить без `generation` и курсора, с тем же `project_id`; старые страницы отбросить |
| нет `project_id` или ответ не того проекта | граф | `list_graph_projects` один раз; `project_id` проекта своей фазы — в каждом вызове |
| `not_found`, пустые `items` | граф, код, БСП, справка | законченный ответ: одна переформулировка, потом другой путь; без доказательства свежести индекса — «не установлено», а не «нет» |
| `ambiguous_name` с кандидатами | `ssl_search`, справка | уточнить по сигнатуре или взять нужный `doc_id`; не выбирать молча |
| `truncated`, `next_cursor` | постраничные | листать с теми же аргументами, прежде чем утверждать «всё» |
| `timeout` | граф, проверка кода | не повторять тот же вызов: сузить запрос, меньше `max_items` |
| `provenance.index` = `absent` / `building` / `failed` | синтакс-чекер | проверены только синтаксис и локальные правила — так и записать; не ждать и не перезапускать |
| блокирующая ошибка | синтакс-чекер, проверка кода | исправить, одно подтверждение; дальше — «не проверено» |
| HTTP 401 / 403, нет инструментов | сервер данных, любой | сервера в сессии нет: сказать один раз, «не проверено», ответ не выдумывать |

## Когда сервера нет

Недоступный сервер — не пройденная проверка и не доказательство, что API нет: в отчёте так и писать
(«не проверено: синтаксис — нет синтакс-чекера»). Код и метаданные конфигурации можно читать прямо из
выгрузки проекта (`folder` проекта + `dump` конфигурации из `project_list`).
