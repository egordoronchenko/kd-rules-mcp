# ПКО: поля и флаги правила конвертации объектов (КД 2 → обмен через БСП)
Читать, когда создаёте или правите ПКО и решаете, какие флаги ставить и что они реально меняют в обмене БСП.

Исполнитель — `DataProcessors/КонвертацияОбъектовИнформационныхБаз/Ext/ObjectModule.bsl` (БСП 3.1.12), ссылки
`(Процедура, стр. N)`. Писатель КД 2.1.8.2 —
`reference/kd2-cfg/DataProcessors/ВыгрузкаКонвертации/Ext/ObjectModule.bsl`, ссылки `ВК:N`.
Поиск при загрузке по шагам — `search.md`; обработчики — `handlers.md`; грабли — скилл `kd2-exchange-pitfalls`.
`УОД:N` — модуль объекта универсальной обработки `УниверсальныйОбменДаннымиXML` из той же выгрузки (версия
обработки 1.0.5.234, в другой версии строки сдвинуты); всё ниже — про обмен через план обмена.

## Как флаг доходит до приёмника

- КД пишет булевы флаги ПКО только со значением Истина, в порядке ВК:819–829; `ПриоритетОбъектовОбмена` — только
  «Ниже»/«Совпадает» (ВК:831–840); затем `Источник`, `Приемник`, варианты поиска, `<Свойства>`, `<Значения>`
  (ВК:843–861).
- Отправитель читает ПКО (`ЗагрузитьПравилоКонвертации`, стр. 5737–6137) и переносит флаги в сообщение атрибутами
  `<Ссылка>` и `<Объект>` (`ВыгрузитьПоПравилу`, стр. 806–822, 914–918). Приёмник ведёт себя по этим атрибутам
  и по своей копии правил отправителя — правилам корреспондента из комплекта, загруженного в приёмник
  (`handlers.md`, «Где лежат правила загрузки»); при чтении для загрузки в ПКО попадают только `Код`,
  `СинхронизироватьПоИдентификатору`, `ПродолжитьПоиск…`, `…GIUD`, `НеЗамещатьОбъектСозданный…`, `ГенерироватьНовыйНомер…`, `НеЗамещать`, `Источник`,
  `Приемник`, обработчики загрузки, `ПоляПоиска`/`ПоляТаблицы` (стр. 5758–5827, 5929–5980, 6121–6127).
- **Порядок тегов важен:** `СинхронизироватьПоИдентификатору` должен идти до `<Свойства>` — свойство поиска
  `{УникальныйИдентификатор}` добавляется при чтении `<Свойства>` по уже прочитанному флагу (стр. 5868–5876).
- Неизвестный тег внутри `<Правило>` молча пропускается: у цикла чтения нет ветки «иначе» (стр. 5751–6037).

## Идентификация правила

- `Код` — имя правила: ключ `Правила[...]`, атрибут `ИмяПравила` у `<Объект>`, имена обработчиков `ПКО_<Код>_…`
  (стр. 5755–5759, 906, 5889–5890). `Наименование` читается только для показа (стр. 5761–5763); `Порядок`,
  `Описание`, `Комментарий` БСП не читает (веток нет, стр. 5755–6035).
- `Источник` — тип источника строкой; при выгрузке `Тип(Значение)` и `Менеджеры[Тип].ПКО = правило` — последнее
  правило с этим источником становится правилом «по умолчанию» для типа (стр. 5824–5845; `НайтиПравило`,
  стр. 6985–6987). Неверный тип — ошибка 11 в протокол (стр. 5847–5850).
- `Приемник` — тип приёмника строкой, уходит атрибутом `Тип` у `<Объект>` (стр. 5816–5822, 905); по нему же
  приёмник ищет ПКО с обработчиком поиска для значений-ссылок (стр. 8484–8522).

## Флаги

**`СинхронизироватьПоИдентификатору`** («Синхронизировать объекты по внутренним идентификаторам»)
- Добавляет в свойства поиска `{УникальныйИдентификатор}` (стр. 5868–5876); отправитель пишет GUID ссылки с типами
  ПКО в `<Ссылка>` (`ВыгрузитьСвойства`, стр. 12880–12892). Приёмник ищет по регистру соответствий, затем по GUID;
  новый объект получает GUID источника (`УстановитьСсылкуНового`, стр. 7773–7781). Шаги — `search.md`.
- Типично: Да и для справочников, и для документов. Нет — только когда объект надо сводить строго по полям.
- `pko_create_from_candidates` и `rule_create` ПКО ставят флаг сами, если приёмник ссылочный и не перечисление
  (`reference/kd2-cfg/CommonModules/ОбщегоНазначения/Ext/Module.bsl:1907-1924`); значение в `fields`,
  в том числе ложь, сильнее. Заметка об этом — в `warnings` ответа.

**`ПродолжитьПоискПоПолямПоискаЕслиПоИдентификаторуНеНашли`**
- Атрибут `ПродолжитьПоиск="true"` на `<Ссылка>` (стр. 810–812); приёмник читает его оттуда (стр. 8747). Без него
  основной объект, не найденный по GUID, сразу создаётся (стр. 8837, 8856–8860), значение-ссылка возвращается
  ссылкой с GUID без проверки (стр. 8884–8888); с ним — переход к полям поиска (стр. 8862–8882).
- Типично: справочники, которые могли завести в обеих базах независимо (контрагенты, номенклатура) — Да;
  документы — Нет. Справочник с обоими флагами считается «классификатором» при сборе статистики сопоставления
  (стр. 17040–17044, 17071).

**`НеСоздаватьЕслиНеНайден`** (в КД — `НеСоздаватьОбъектВПриемникеЕслиНеНайденПоПолямПоиска`, ВК:824)
- Атрибут на `<Ссылка>` (стр. 403, 806–808), читается и для основного объекта, и для ссылки (стр. 8727–8738).
  Основной объект не создаётся и пропускается (стр. 8837, 9058; `ПрочитатьОбъект`, стр. 10771–10777).
  Значение-ссылка без GUID остаётся `Неопределено` (стр. 9050–9065); с GUID флаг не действует — приходит ссылка
  с GUID источника (стр. 8884–8888, 9054–9056).
- Менять: объект должен уже быть в приёмнике (организации, валюты, общие классификаторы).

**`НеЗамещать`** («Не замещать найденные объекты при загрузке»)
- Атрибут `НеЗамещать="true"` у `<Объект>` (стр. 402, 916–918). Найденный объект пропускается целиком; если у ПКО
  есть `ПриЗагрузке` — после него, и обработчик может сбросить `НеЗамещатьОбъект` (стр. 10450, 10780–10785,
  10829–10834). Не найденный — создаётся как обычно.
- Менять: данные «хозяина»-приёмника — создать, если нет, но не перетирать правки приёмника.
- В существующее ПКО с этим флагом добавлен реквизит — найденные объекты его не получат: решение человека или
  рецепт ниже.

**Рецепт: у найденного объекта обновлять только новое свойство** (ПКО с `НеЗамещать`)
- Флаг ПКО действует на объект целиком, флаг `НеЗамещать` у ПКС — на одно свойство. Читатель: ПКС —
  `ЗагрузитьПКС`, стр. 5543–5544; группа ПКС — `ЗагрузитьПКГС`, стр. 5350–5351. Отправитель пишет атрибут
  `НеЗамещать="true"` у `<Свойство>` (`ВыгрузитьСвойства`, стр. 12837–12839, 12972–12974). Приёмник у
  **найденного** объекта такое свойство пропускает (`ПрочитатьОбъект`, стр. 10677, 10686–10693), табличную часть
  или набор записей — тоже (стр. 10896–10902); свойство поиска не переписывает (`ПрочитатьСвойстваПоискаИзФайла`,
  стр. 8267, 8297–8299; `УстановитьРеквизитыПоискаУОбъекта`, стр. 8087–8092). Новый объект получает все свойства.
- Шаги: `rule_update(kind=pko, key=<ПКО>, fields={"НеЗамещать": false})`; затем один вызов
  `rule_update_many(kind=pks, owner=<ПКО>, fields={"НеЗамещать": true}, except_keys=[<путь нового ПКС>])` — все ПКС
  этого ПКО, кроме нового (группы ПКС — отдельным вызовом с `kind=pks_group`); всё или ничего, при ошибке на любом
  правиле откат всех. Список путей — `rules_get(kind=pko, key=<ПКО>)`. Флаги пишет
  отправитель по своим правилам (стр. 402, 916–918, 12837): править `ExchangeRules.xml` источника и его копию у
  приёмника (`live-rules.md`).
- Побочный эффект — сказать человеку: найденный объект теперь записывается при каждом приходе, свойство без флага
  получает значение из сообщения без проверки на пустоту (стр. 10711) — пустое в источнике затрёт заполненное в
  приёмнике. ПКС, добавленные в это ПКО позже, без флага тоже будут перезаписывать.

**`ГенерироватьНовыйНомерИлиКодЕслиНеУказан`**
- Перед записью: пустой `Номер` (документ, задача, бизнес-процесс) — `УстановитьНовыйНомер()`, пустой `Код`
  (справочник, ПВХ, план обмена) — `УстановитьНовыйКод()` (`ПровестиГенерациюКодаНомераПриНеобходимости`,
  стр. 10386–10420; вызовы стр. 11097, 11216, отложенная запись стр. 10371–10374). Объект пишется в режиме
  `ОбменДанными.Загрузка` (`ЗаписатьОбъектВИБ`, стр. 1761) — сам код/номер платформа тогда не назначит
  (поведение платформы, по коду БСП не проверено).
- Менять: `Номер`/`Код` не передаётся (нет ПКС) или нумерация в приёмнике своя.

**`ПриоритетОбъектовОбмена`** (`Ниже` / `Совпадает`; по умолчанию «Выше» — тег не пишется)
- Атрибут `ПриоритетОбъектаОбмена` у `<Ссылка>`/`<Объект>` (`ЗаписатьПриоритетОбъектовОбмена`, стр. 13374–13387).
  Приёмник при не-«Выше» вызывает `ПриПолученииДанныхОтПодчиненного`, иначе `ПриПолученииДанныхОтГлавного`
  (стр. 10422–10437, 11035–11039) — от этого зависит разрешение коллизий; результат `Игнорировать` — объект не
  пишется (стр. 11042–11049). Что именно делают эти обработчики БСП — не проверено. В универсальной обработке
  приоритета нет.
- Типично: не задавать.

**`НеЗапоминатьВыгруженные`** (в БСП — `ЗапоминатьВыгруженные = Не …`, стр. 5806–5808; по умолчанию Истина, 5745)
- Учитывается только при циклической ссылке объекта на себя: `ЗапоминатьВыгруженные = ОбъектВыгружаетсяПоСсылке
  ИзСамогоСебя И ПКО.ЗапоминатьВыгруженные` (`ВыгрузитьПоПравилу`, стр. 388–398); от него зависят кэш выгруженных и
  атрибут `Нпп` (стр. 603–699, 796–804). Повтор объекта по ссылке гасит регистр соответствий
  (`kd2-exchange-pitfalls/references/export.md`, «Объект по ссылке: целиком или только ссылкой»). Типично: Нет.
- Ключ кэша по умолчанию — имя ПКО (стр. 424); `ЗапоминатьВыгруженные = Истина` в `ПередВыгрузкой` без своего
  `КлючВыгружаемыхДанных` даст всем объектам ПКО один ключ — со второго вернётся узел первого (вывод: стр. 469–471,
  557–595, 607–633). В универсальной обработке запоминание включено у каждого ПКО, ключ —
  `ЗначениеВСтрокуВнутр(Источник)` (УОД:3842, 1682–1702; `kd2-exchange-pitfalls/references/manual.md`).

### Флаги КД, которые БСП 3.1.12 не исполняет

- `ВыгружатьОбъектТолькоПриНаличииНаНегоСсылки` — не читается: ветки нет (стр. 5751–6037), имени в модуле нет.
- `ИспользоватьБыстрыйПоискПриЗагрузке` — читается в колонку (стр. 5797–5799) и больше нигде не используется.
- `НеВыгружатьОбъектыСвойствПоСсылкам` — читается (стр. 5778–5780); признак `НЕВыгружатьПодчиненныеОбъекты`
  (стр. 784) дальше не используется.
- `ПриПереносеОбъектаПоСсылкеУстанавливатьТолькоGIUD` (так, с опечаткой) — читается (стр. 5787–5790), но
  поведение зашито: для значения-ссылки с GUID — всегда «только GUID» (стр. 8736, 8758, 9054–9056).
- `НеЗамещатьОбъектСозданныйВИнформационнойБазеПриемнике` — атрибут доходит (стр. 820–821, 8740–8745), но
  принимающие его процедуры его не используют (стр. 8153–8191, 8616–8628).
- `НастройкаВариантовПоискаОбъектов` — читается только в режиме «информация о правилах» (стр. 6185–6212);
  справка КД: в БСП не используется (`reference/kd2-cfg/Catalogs/ПравилаКонвертацииОбъектов/Ext/Help/ru.html:4`).

В универсальной обработке КД
(`reference/kd2-dist-src/V8Exchan83/УниверсальныйОбменДаннымиXML/Ext/ObjectModule.bsl`) часть этих флагов
работает (стр. 5877–5878, 9095, 9341) — поведение там и в БСП не путать. Своя `УниверсальныйОбменДаннымиXML`
есть и в конфигурации на БСП (`УОД`) — тоже другой исполнитель: например, `НеВыгружатьОбъектыСвойствПоСсылкам`
там действует (УОД:2046–2050); отличия — `kd2-exchange-pitfalls/references/manual.md`.

`ВсеОбъектыВыгружены` — не тег XML, а колонка ПКО в памяти (стр. 14087) и параметр `ПередВыгрузкой` (стр. 566):
при Истина объект выгружается только узлом `<Ссылка>` (стр. 401, 603, 881–891). `ПоискПоДатеНаРавенство` — флаг
ПКС, не ПКО (см. `search.md`).

## Связи ПКО с другими правилами

- **ПКС (`<Свойства>`).** ПКС с `Поиск` или `Обязательное` — свойство поиска, остальные — свойства объекта
  (`ЗагрузитьПКС`, стр. 5482–5502; универсальная обработка `Обязательное` не читает, УОД:3624–3643). Свойства
  поиска уходят только в `<Ссылка>` (стр. 790–830); если их нет и нет
  `СинхронизироватьПоИдентификатору`, `<Ссылка>` не формируется (стр. 790–791, 841–843) — приёмник каждый раз
  создаёт новый объект, если его не нашёл `ПриЗагрузке` (`ПрочитатьОбъект`, стр. 10617–10671).
  `КодПравилаКонвертации` у ПКС — каким ПКО выгружать значение (стр. 5546–5547); пусто — ПКО по типу источника
  (стр. 6985–6987).
- **ПВД.** `КодПравилаКонвертации` ПВД — ПКО для выгрузки выбранных объектов
  (`ВызватьСобытияПередВыгрузкойОбъекта`, стр. 13451; `ВыгрузкаОбъектаВыборки`, стр. 13633). ПКО без ПВД
  выгружается только как значение свойств других объектов (`kd2-exchange-pitfalls/references/export.md`, «Объект не выгружается сам»).
- **ПКЗ (`<Значения>`).** Пары «значение источника → имя в приёмнике» (`ЗагрузитьПКЗ`, стр. 5700–5701; пустой
  источник пропускается). Предопределённое с парой в ПКЗ уходит как `{ИмяПредопределенногоЭлемента}`
  (стр. 705–736, 12809–12814); значение перечисления без пары — ошибка 71, значение не выгружается
  (стр. 743–772).

## Обработчики ПКО по фазам (детали — `handlers.md`)

| Обработчик | База | Где | Для чего обычно |
|---|---|---|---|
| `ПередВыгрузкой` | отправитель | стр. 558–595 | `Отказ`, флаги на лету (`НеЗамещать…`, `ВсеОбъектыВыгружены`) |
| `ПриВыгрузке` | отправитель | стр. 945–986 | своя запись свойств (`СтандартнаяОбработка = Ложь`), `Отказ` |
| `ПослеВыгрузки` | отправитель | стр. 1035–1052 | доп. объекты, правка узла `Приемник` |
| `ПослеВыгрузкиВФайл` | отправитель | стр. 1145–1162 | действия после записи `<Объект>` в файл |
| `ПоследовательностьПолейПоиска` | приёмник | стр. 8940–9016 | варианты ключей поиска (`search.md`) |
| `ПередЗагрузкой` | приёмник | стр. 10550–10592 | `Отказ` до поиска, смена `НеЗамещатьОбъект` |
| `ПриЗагрузке` | приёмник | стр. 10798–10835 | после поиска: `ОбъектНайден`, `НеЗамещатьОбъект` |
| `ПослеЗагрузки` | приёмник | стр. 10988–11020 | дозаполнение перед записью, `Отказ`; проведение документа — `Объект.Проведен` / `РежимЗаписи` |

Код обработчиков загрузки приёмник берёт из своей копии правил отправителя — файла правил корреспондента в
комплекте приёмника, а не из сообщения (`handlers.md`, «Где лежат правила загрузки»).

Документ в приёмнике при загрузке пишется непроведённым и проводится очередью после фиксации транзакции
загрузки; режим выбирается после `ПослеЗагрузки`, проводить документ в обработчике самому нельзя —
`handlers.md`, «Проведение документов в приёмнике».
