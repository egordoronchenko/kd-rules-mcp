# Чек-лист проверок (все — до переноса в проект)

Полный чек-лист с командами; «шаг 1» ниже — замечания `rules_validate` до правок (`start.md`, «Правила»).

Что каждая проверка доказывает и чего нет, как её запускать и читать итог, типичные ложные замечания —
`references/checks.md`; здесь только порядок. Скрипты `kdbase` запускаются из папки клона сервера
kd-rules-mcp (путь спросить у человека, если его нет в правилах проекта); нужны Windows с платформой 1С, для
`bsp_check` и `exchange_check` — базы роли «песочница». Клона нет — `bsp_check` и `exchange_check` через сервер
данных доступны инструментами `live_rules_check` и `live_exchange_run` (узлы — `live_nodes_setup`); запись в базу
у них — `preview` → `apply`, и только с согласия человека в этой задаче.

- [ ] `rules_validate` с обеими структурами: **нет новых** замечаний относительно шага 1.
- [ ] Менялся код обработчиков — `handlers_export` → синтакс-чекер текстом каждого файла → `handlers_locate`
      (`references/mcp-1c.md`, «Проверка кода обработчиков»).
- [ ] `rules_save` в рабочую папку или в `rules_dir` проекта. Перед записью он проверяет правила как
      `rules_validate` — со структурами из вызова, а без них со структурами последнего `rules_validate` этого
      проекта, запомненными в снимке (структуры нет в кэше — она в `validation.dropped`: загрузить снова или
      передать явно). Есть ошибки —
      файл не пишется, ошибка `rules_save_errors` со списком `errors`: исправить и сохранить снова.
      `acknowledge_errors: true` пишет файл с ошибками (`saved_with_errors: true`) — только для промежуточного
      сохранения или ошибки, которую человек признал ложной; в отчёте — какие ошибки и почему. В ответе
      `validation.errors` = 0.
- [ ] Правила загружаются в базу из файла — `rules_pack` (папка комплекта или файлы): `warnings` пусты,
      `load_with` — какой формой загружать.
- [ ] `kd_check` — база КД принимает файл: `uv run python kdbase\kd_check.py check <файл>` → `ИТОГ OK`.
- [ ] `bsp_check` — БСП песочницы принимает комплект без записи в базу:
      `uv run python kdbase\bsp_check.py --archive <ZIP> --plan <план> --project <проект> --base <песочница>`
      → `ИТОГ OK`. Запускать, если человек знает, что правила грузятся в эту песочницу. У базы с `data_mcp`
      скрипт идёт через сервер данных (строка `ТРАНСПОРТ сервер данных`), логин берёт сам; без `data_mcp` нужен
      COM и `login: true` у базы в `project_list` (есть ли логин — только оттуда или из `check_server.py`;
      `projects.local.yaml` и `.dev.env` не читать). Нет логина для COM или нет ответа человека — ступень
      «не прогонялась», так и сказать. Без клона — `live_rules_check(base, plan, files)`: итог успешен, только если
      загружены все виды правил; сообщения БСП — в ответе. `compatibility` с видом «УстаревшиеПравила» или
      «УстаревшаяВерсияКонфигурации» — правила другой версии конфигурации: продолжить (`accept_version_mismatch=true`,
      как кнопка «Продолжить» формы БСП) — только с «да» человека; «НекорректнаяКонфигурация» — не те правила.
- [ ] `exchange_check` — если правились поиск или загрузка и есть две песочницы с сервером данных: живой обмен
      одного объекта (`references/checks.md`) → `ИТОГ OK`; старые правила на другом объекте воспроизводят проблему.
      Без клона — `live_exchange_run`: сначала `mode="preview"` — показать человеку необратимые действия (снятие
      регистраций узла в источнике, запись в приёмник), затем `mode="apply"` с `expected_preview_hash`.
- [ ] Удаление: в конвертации есть `ПриПолученииИнформацииОбУдалении` с пометкой вместо удаления; физическое
      удаление на получателе — только после отдельного прямого «да» человека (`references/handlers.md`,
      «Правило: физического удаления в обмене быть не должно»).
- [ ] Правила регистрации пересобирались — `rules_validate` проекта ПРО со структурой источника.
- [ ] Отчёт: выбранные объекты и почему, решения по `unresolved`/`not_applied`/выключенным ПКС, замечания
      до и после, путь файла.

Рабочая папка (`workspace`): папка на задачу `<проект>-<план>-<задача>\` (латиница, дефис; кириллический план —
коротким латинским сокращением, например `ОбменБухгалтерияПредприятияДокументооборот20` → `acme-bpdo20-search`),
файлы под именами комплекта БСП, обёртки обработчиков — `handlers\` внутри; что теряется при перезапуске и что можно удалять —
https://github.com/egordoronchenko/kd-rules-mcp/blob/main/docs/workflow.md.
