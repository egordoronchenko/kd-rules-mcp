# ПВД: правила выгрузки данных в обмене через план обмена БСП
Читать, когда добавляете объект в обмен, правите ПВД или выясняете, почему объект не уходит или уходит «по ссылке».

Исполнитель — `DataProcessors/КонвертацияОбъектовИнформационныхБаз/Ext/ObjectModule.bsl` (БСП 3.1.12), ссылки
`(Процедура, стр. N)`; `ОбменДаннымиСервер, стр. N` — общий модуль той же БСП. Писатель КД 2.1.8.2 —
`reference/kd2-cfg/DataProcessors/ВыгрузкаКонвертации/Ext/ObjectModule.bsl`, ссылки `ВК:N`.
Обработчики всех уровней — `handlers.md`; грабли — скилл `kd2-exchange-pitfalls`. `УОД:N` — модуль объекта
универсальной обработки `УниверсальныйОбменДаннымиXML` из той же выгрузки (версия обработки 1.0.5.234, в другой
версии строки сдвинуты).

## Главное

- В обмене через план обмена БСП выгружает **только зарегистрированное на узле**: одна выборка
  `ПланыОбмена.ВыбратьИзменения(Получатель, НомерСообщения, МассивМетаданных)`
  (`ВыполнитьВыгрузкуЗарегистрированныхДанных`, стр. 18236; обёртка — `ОбменДаннымиСервер`, стр. 3524–3531).
  Массив — типы **включённых** ПВД (`ВыполнитьВыгрузку`, стр. 17931–17942; стр. 18210–18228).
- ПВД здесь — пропуск типа в выборку изменений, привязка к ПКО и обработчики, а не выборка данных.
  `СпособОтбораДанных`, отбор построителем и `ПроизвольныйАлгоритм` обрабатывает только `ВыгрузитьДанныеПоПравилу`
  (стр. 1405–1600); её не вызывает ни эта обработка, ни общие модули конфигурации (проверено поиском). В
  универсальной обработке (ручной обмен) способы исполняются: стандартная выборка и произвольный алгоритм, где
  `ВыборкаДанных` из `ПередОбработкой` — запрос, результат, выборка или коллекция, а `Отказ` отменяет правило
  (УОД:11166–11186, 11297–11299, 11375–11396). Отдельного способа «Запрос» в формате нет: в КД 2.1.8.2 только
  `СтандартнаяВыборка` и `ПроизвольныйАлгоритм` (`reference/kd2-cfg/Enums/СпособыОтбораДанных.xml:41-59`).
- Зарегистрированный объект без включённого ПВД в выборку не попадает и не уходит; регистрация при этом остаётся
  (фильтр выборки — платформа, не проверено живьём).
- Для одного типа работает **первый** найденный ПВД (`ТаблицаПравилВыгрузкиИспользуемые.Найти`, стр. 18363);
  второй ПВД на тот же тип молча не используется.
- Отбор «что выгружать» делается регистрацией (ПРО, `pro.md`) или `Отказ` в `ПередВыгрузкойОбъекта`, не ПВД.

## Поля ПВД

Писатель — `ВК:896–957`, читатель — `ЗагрузитьПВД` (стр. 6764–6861); на приёмнике ПВД не читаются
(`ЗагрузитьПравилаОбмена`, стр. 16454–16459).

| Поле XML | КД пишет | Что делает БСП |
|---|---|---|
| `Отключить` (атрибут) | ВК:910 | `Включить = Не Отключить` (стр. 6768); выключенный тип не выбирается (стр. 17931) |
| `Код` | ВК:913 | имя ПВД (стр. 6773–6775) — в протоколе ошибок |
| `Наименование` | ВК:914 | пустое заменяется кодом (стр. 6857–6859) |
| `Порядок` | ВК:915 | читается (стр. 6781–6783), не используется: порядок типов задаёт выборка изменений |
| `Описание`, `Комментарий` | ВК:916–917 | не читаются (нет ветки в стр. 6770–6855) |
| `КодПравилаКонвертации` | ВК:919 | начальное `ИмяПКО` объекта (стр. 6825–6827, 13451); пусто — `НайтиПравило(Источник, "")` (стр. 13311–13324) |
| `СпособОтбораДанных` | ВК:920, `СтандартнаяВыборка` / `ПроизвольныйАлгоритм` (`reference/kd2-cfg/Enums/СпособыОтбораДанных.xml:43,55`) | читается (стр. 6785–6787); в обмене через план не используется |
| `ОбъектВыборки` | ВК:921 — имя типа источника: `СправочникСсылка.X`, `РегистрСведенийЗапись.X`, `КонстантыНабор` | `Тип(…)` (стр. 6812) → `Метаданные.НайтиПоТипу` (стр. 17938) — ключ поиска ПВД для объекта выборки (стр. 18354–18365) |
| `ВыбиратьДанныеДляВыгрузкиОднимЗапросом` | ВК:923, только Истина | пропускается: «игнорируется при on-line обмене» (стр. 6789–6792) |
| `НеВыгружатьОбъектыСозданныеВБазеПриемнике` | ВК:924, только Истина | читается в колонку (стр. 6794–6796, 14131), дальше нигде не используется |
| `ПередОбработкойПравила`, `ПередВыгрузкойОбъекта`, `ПослеВыгрузкиОбъекта`, `ПослеОбработкиПравила` | ВК:927–930, если не пусто | тексты обработчиков (стр. 6831–6849), см. ниже |
| `<Группа>` + `Отключить` | ВК:936–953; вложенные правила пишутся всегда (ВК:951) | `ЗагрузитьПравилаВыгрузки` разбирает только `<Правило>` (стр. 6868–6888): группа и её `Отключить` не читаются — правила выключенной группы работают |

Не теги XML: `ИмяОбъектаДляЗапроса` / `ИмяОбъектаДляЗапросаРегистра` БСП вычисляет из `ОбъектВыборки` для отбора
построителем (стр. 6816–6821), `СинхронизироватьПоИдентификатору` — из ПКО по `КодПравилаКонвертации`
(стр. 6808, 6890–6901; КД пишет код ПКО раньше `ОбъектВыборки`, ВК:919–921). Тег `ИмяТипаПриемника` читается
(стр. 6798–6800), КД его не пишет.

## Как объект попадает в сообщение

1. `ПередВыгрузкойДанных` (`ВыполнитьВыгрузку`, стр. 17946–17987), затем `ПередПолучениемИзмененныхОбъектов`
   (`ВыполнитьВыгрузкуЗарегистрированныхДанных`, стр. 18174–18208).
2. Массив метаданных: типы включённых ПВД; константы — если есть ПВД `КонстантыНабор` (стр. 18213–18217);
   РС `СоответствияОбъектовИнформационныхБаз` выгружается отдельно (стр. 18222–18228).
3. Выборка изменений (стр. 18236). Цикл по ней (стр. 18266–18473), `Данные` — сам объект (`СправочникОбъект`,
   `ДокументОбъект`, набор записей), не ссылка (стр. 18278).
4. Удаление → информация об удалении (`ОтработатьУдалениеОбъекта`, стр. 18283–18287).
5. Смена типа в выборке → `ПослеОбработкиПравила` прошлого ПВД и `ПередОбработкойПравила` нового
   (стр. 18295–18406).
6. `СтандартныеПодсистемыСервер.ПриОтправкеДанныхПодчиненному`: `Игнорировать` — пропуск, `Удалить` — информация
   об удалении (стр. 18408–18435).
7. Регистр — `ВыгрузкаРегистра` (стр. 18438–18441); константы — `ВыгрузитьНаборКонстант` (стр. 18443–18448);
   остальное — `ВыгрузкаОбъектаВыборки(Данные, ПВД, …)` (стр. 18467): `ПередВыгрузкойОбъекта` (глобальный,
   затем ПВД), `ВыгрузитьПоПравилу`, `ПослеВыгрузкиОбъекта` (стр. 13604–13647).
8. После цикла — `ПослеОбработкиПравила` последнего ПВД (стр. 18475–18511).
9. Исключение внутри цикла → откат и `ВызватьИсключение` (стр. 18515–18521) → `ЗаписьСообщения.ПрерватьЗапись()`
   (`ВыполнитьВыгрузку`, стр. 18058–18063, 18086–18087): сообщение не формируется целиком.

## Объект «только по ссылке»

Своего ПВД нет; есть ПКО, и на объект ссылается свойство другого ПКО (ПКС с `ПравилоКонвертации`, либо ПКО
находится по типу значения, если у ПКС правило не указано — `ВыгрузитьСвойства`, стр. 13131–13168).

- По умолчанию значение уходит узлом `<Ссылка>` со свойствами поиска ПКО (`ВыгрузитьПоПравилу`, стр. 788–843):
  свойства объекта выгружаются с `ВыгрузитьТолькоСсылку = Истина` (стр. 1019), а при `ТолькоПолучитьУзелСсылки`
  правило возвращается сразу после узла ссылки (стр. 881–891).
- Целиком (`<Объект>`) — в двух случаях:
  - ПКС `ПередВыгрузкой` / `ПриВыгрузке` ставит `ВыгрузитьОбъект = Истина` (стр. 12924, 12949, 13053, 13078);
  - режим «по необходимости»: у ПРО этого объекта есть реквизит-флаг узла типа `РежимыВыгрузкиОбъектовОбмена`
    со значением `ВыгружатьПриНеобходимости` или пустым (`ВыгружатьОбъектПоСсылке`, стр. 3393–3437), и объекта
    ещё нет в РС соответствий для узла (стр. 13175–13195, 17889–17893). Тогда пишется запись «выгружен по ссылке»,
    объект регистрируется на узле и получает номер сообщения (`ВыполнитьВыгрузку`, стр. 18065–18077).
    Без такого флага в ПРО объект всегда уходит только ссылкой.
- ПКО объекта отрабатывает и для ссылки: `ПередКонвертациейОбъекта` и ПКО `ПередВыгрузкой` вызываются до возврата
  узла ссылки (стр. 482–595); `ПриВыгрузке`, `ПослеВыгрузки`, `ПослеВыгрузкиВФайл` — только для полного объекта.
  ПКС свойств поиска выполняются при каждой записи ссылки (стр. 826–828).
- Приёмник ищет объект по узлу `<Ссылка>` — `search.md` и раздел «Поиск существующего объекта» в pitfalls.

## Обработчики ПВД

| Обработчик | Когда вызывается | `Отказ` | Что можно сделать |
|---|---|---|---|
| `ПередОбработкойПравила` | при смене типа в выборке, перед первым объектом серии (стр. 18369–18404) | **не проверяется** (переменная-заглушка, стр. 18173) | заполнить `ИсходящиеДанные` — придут в ПКО как `ВходящиеДанные` каждого объекта типа (стр. 18370, 18467 → 13633). `ВыборкаДанных` не используется — подменить выборку нельзя |
| `ПередВыгрузкойОбъекта` | перед каждым объектом, после глобального `ПередВыгрузкойОбъекта` (стр. 13456–13522) | `Истина` → объект не выгружается (стр. 13626–13628); глобальный `Отказ` — ПВД-обработчик не вызывается (стр. 13486–13488) | отфильтровать по `Объект`; сменить `ИмяПКО` (стр. 13451 → 13633); заполнить `ИсходящиеДанные` — станут `ИсходящиеДанные` ПКО (стр. 13633) |
| `ПослеВыгрузкиОбъекта` | после `ВыгрузитьПоПравилу`, и при `Отказ` ПКО тоже (стр. 13637–13643, 13562–13592) | нет | пост-обработка по `Объект`, `ИмяПКО`; `УзелСсылки` — всегда Неопределено (стр. 13529) |
| `ПослеОбработкиПравила` | при смене типа и после цикла (стр. 18299–18331, 18475–18511) | нет | итоги по типу |

- `Отказ` в `ПередВыгрузкойОбъекта` не снимает регистрацию: объект уже выбран с номером сообщения (стр. 18236),
  регистрация удалится подтверждением приёма (поведение платформы, не проверено).
- Исключение в любом обработчике ПВД → `ЗаписатьИнформациюОбОшибкеОбработчикиПВД` → `ВызватьИсключение`, если не
  `ПродолжитьПриОшибке` (стр. 5034–5051) → вся выгрузка прерывается (см. шаг 9).
- Грабля «объект не выгружается сам» (pitfalls, «Выгрузка объектов»): `Отказ` в `ПередОбработкойПравила` в обмене
  через план ничего не отменяет — смотреть `ПередВыгрузкойОбъекта`, регистрацию и `Отключить`.

## Рецепт: добавить объект в обмен

1. ПКО и ПКС, свойства поиска — `pko_create_from_candidates` / `rule_create` (`pko.md`, `pks.md`, `search.md`).
2. ПВД: `ОбъектВыборки` — тип источника, `КодПравилаКонвертации` — код ПКО, `СпособОтбораДанных` —
   `СтандартнаяВыборка`, без обработчиков. Один ПВД на тип; выключать — само правило (`Отключить` группы БСП
   не читает).
3. Регистрация: объект в составе плана обмена и ПРО в правилах регистрации (`registration_build`, `pro.md`) —
   без регистрации выборка изменений его не вернёт.
4. Приёмник: загрузка идёт по правилам корреспондента, лежащим в приёмнике (`handlers.md`, «Где лежат правила
   загрузки»), — комплект с новым ПКО загрузить в обе базы, код ПКО в обеих копиях одинаковый.
5. Объект только по ссылке: ПВД не нужен; ПКО со свойствами поиска и ПКС у ссылающихся ПКО. Полная выгрузка при
   первой ссылке — флаг ПРО «по необходимости» или `ВыгрузитьОбъект = Истина` в ПКС.
6. Проверка: `rules_validate`, затем живой обмен (pitfalls, «Как проверить исправление живым обменом»).
