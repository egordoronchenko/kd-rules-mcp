# Сервер на другой машине: файлы по ссылкам

Сервер `kd-rules-mcp` может работать не на твоей машине. Тогда он видит свои папки, а ты — свои: файл, который
сервер сохранил, у тебя не открывается, а твой файл не виден серверу. Файлы передаются по ссылкам HTTP, мимо
модели: содержимое не попадает в ответ инструмента, и набирать его заново не нужно.

**Как понять, что сервер на другой машине:** путь из ответа сервера (`path` у `rules_save` и `rules_pack`,
`workspace` в `project_list`) у тебя не открывается — или так сказал человек. Сервер на той же машине — ссылки не
нужны: файлы лежат по путям из ответа.

## Что такое ссылка

- Одна ссылка — один файл и одно действие (скачать или закачать). Действует 10 минут, если сервер не настроен
  иначе; другой срок — параметр `ttl_seconds`, не больше часа. Когда истекает — поле `expires_at` ответа.
- Токен MCP для ссылки не нужен: доступ даёт подпись в самой ссылке. Пока ссылка действует, по ней файл получит
  любой — не пиши её в файлы, отчёты и коммиты.
- В Windows PowerShell 5 `curl` — это `Invoke-WebRequest`, а не программа curl. Всегда пиши `curl.exe`: так и
  написано в `command` ответа.

## Забрать файл с сервера

1. Файл сохранён (`rules_save`, `rules_pack` и другие инструменты, которые пишут файл) — `download_link(path)` с
   путём из ответа. В ответе: `url`, `file_name`, `size` (байты), `sha256`, `expires_at` и `command` — готовая
   команда: `command.windows` для Windows, `command.posix` для Linux и macOS.
2. Выполнить команду в папке, куда нужен файл: `curl.exe -fsS -o "<file_name>" "<url>"`. Файл ляжет под именем
   `file_name`; другое имя или папка — поменять путь после `-o`.
3. Сверить хеш с `sha256` ответа:
   - Windows: `(Get-FileHash -Algorithm SHA256 "<файл>").Hash` — PowerShell пишет заглавными буквами, сравнивать
     без учёта регистра;
   - Linux: `sha256sum "<файл>"`.

   Не совпал — файл изменился на сервере после выдачи ссылки или скачался не целиком: новая ссылка, скачать снова.
4. Положить файл в свою копию репозитория проекта — по правилам проекта; коммит — с «да» человека.

Ссылка — только на файл. На папку (комплект правил, выгрузка обработчиков) — отказ `file_not_found`: комплект для
загрузки в базу собрать в ZIP `rules_pack` и скачать ZIP, остальное — по ссылке на каждый файл.

## Отдать свой файл серверу

1. `upload_link(name)` — только имя файла, без папок: `ПравилаОбмена.xml`. В ответе: `url`, `path` (куда ляжет
   файл: входящая папка `inbox` в рабочей папке сервера), `max_bytes` (предел размера), `expires_at`,
   `overwrite` и `command`.
2. Подставить свой файл в команду: `curl.exe -fsS -T "<путь к своему файлу>" "<url>"`. Сервер отвечает JSON с
   `path`, `size` и `sha256` — сверить `sha256` с хешем своего файла (команды — выше).
3. Дальше работать по `path` из ответа: он сразу годится для `rules_open`, `rules_diff`, `rules_pack`, `ed_open`.

Файл с таким именем во входящей папке уже есть — закачка без перезаписи получит 409. Взять другое имя или, если
прежний файл точно не нужен, `upload_link(name, overwrite=true)`.

## Если не получилось

| Симптом | Причина и что делать |
|---|---|
| `path_outside_workspace` у `download_link` | по ссылке отдаются только файлы рабочей папки и папок живых правил (`rules_dir`); выгрузки конфигураций у тебя и так есть в репозитории |
| `file_not_found` | файла нет или это папка: проверить путь; комплект — ZIP через `rules_pack` |
| `invalid_argument` у `upload_link` | в имени папка, `..` или недопустимые символы — передать только имя файла |
| `curl.exe` выходит с кодом 22, «returned error: 403» | ссылка просрочена, обрезана при копировании или выдана на другое действие (скачивание вместо закачки) — попросить новую |
| «returned error: 404» | файла на сервере уже нет — сохранить заново и взять новую ссылку |
| «returned error: 409» | имя занято во входящей папке — другое имя или `overwrite=true` |
| «returned error: 413» | файл больше `max_bytes` — сказать человеку: предел задаёт сервер (`KD2_UPLOAD_MAX_MB`) |
| `curl` ругается на параметры, вывод как у `Invoke-WebRequest` | PowerShell 5: писать `curl.exe`, не `curl` |
| соединение не устанавливается, в ссылке `127.0.0.1`, `localhost` или `0.0.0.0` | серверу не задан публичный адрес: человеку — задать `server_url` с адресом машины сервера при установке (или `KD2_PUBLIC_URL`) и перезапустить сервер |
