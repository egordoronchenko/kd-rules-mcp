# Поиск объекта при загрузке (ПравилаОбмена КД 2, обмен через БСП)
Читать, когда выбираете ключи поиска и флаги ПКО или разбираетесь, почему объект задвоился или не нашёлся.

Код — `DataProcessors/КонвертацияОбъектовИнформационныхБаз/Ext/ObjectModule.bsl` (БСП 3.1.12), ссылки
`(Процедура, стр. N)`; без имени процедуры — `НайтиОбъектПоСсылке` (стр. 8681–9085). Флаги ПКО — `pko.md`,
обработчики — `handlers.md`, проверенные грабли поиска — скилл `kd2-exchange-pitfalls`, раздел «Поиск
существующего объекта при загрузке» (здесь не повторяются).

## Что приходит в сообщении

- Узел `<Ссылка>` пишет отправитель, только если у ПКО есть свойства поиска или предопределённое имя
  (`ВыгрузитьПоПравилу`, стр. 790–791). В нём: свойства поиска ПКО (стр. 826–828), атрибуты `Нпп`/`ГНпп`,
  `НеСоздаватьЕслиНеНайден`, `ПродолжитьПоиск`, `ПриоритетОбъектаОбмена` (стр. 796–822).
- Свойство поиска — ПКС с флагом «Поиск» или «Обязательное» (`ЗагрузитьПКС`, стр. 5482–5497); при
  `СинхронизироватьПоИдентификатору` добавляется `{УникальныйИдентификатор}` (`ЗагрузитьПравилоКонвертации`,
  стр. 5868–5876) — GUID ссылки источника с атрибутами `ТипИсточника`/`ТипПриемника` ПКО (`ВыгрузитьСвойства`,
  стр. 12880–12892). ПКС с «Поиск» и `ИмяПараметраДляПередачи` уходит узлом `<ЗначениеПараметра>` (грабли,
  «Параметр объекта в обработчике поиска не виден»).
- Нет `<Ссылка>` → искать нечем: объект создаётся заново при каждой загрузке (`ПрочитатьОбъект`, стр. 10617–10671).

## Кто вызывает поиск

- **Основной объект** (`<Объект>`): `ПрочитатьОбъект` на узле `<Ссылка>` вызывает поиск с
  `РежимПоискаОсновногоОбъекта = Истина` и именем правила из атрибута `ИмяПравила` (стр. 10735–10763).
- **Значение-ссылка** (`<Свойство><Ссылка>`): `ПрочитатьСвойство`, режим «по ссылке» (стр. 7984–8010). ПКО для
  обработчика поиска — по атрибуту `ИмяПКО` (его пишут, только если у ПКО значения есть обработчик поиска,
  `ВыгрузитьСвойства`, стр. 13008–13014), иначе первое правило с этим `Приемник` и обработчиком поиска
  (стр. 8920–8930; `ОпределитьПоТипуОбъектаПриемникаПравилоКонвертацииКотороеСодержитАлгоритмПоиска`,
  стр. 8484–8522).

## Шаги (порядок кода; переход к следующему — если объект не найден)

**0. Чтение `<Ссылка>`** (`ПрочитатьСвойстваПоискаИзФайла`, стр. 8228–8318).
- `<Свойство Имя=…>` → `СвойстваПоиска[Имя]` (Соответствие, ключ — имя реквизита приёмника, стр. 8295);
  с `НеЗамещать` — ещё в `СвойстваПоискаНеЗамещать` (стр. 8297–8301); `<ЗначениеПараметра>` → `ПараметрыОбъекта`
  (Соответствие, создаётся при первом параметре; стр. 8288–8291, `ДобавитьПараметрПриНеобходимости`, 9783–9789).
- `ПоискПоДатеНаРавенство` = ИЛИ по атрибутам всех свойств (стр. 8269–8270); `ЭтоГруппа` не Истина → Ложь
  (стр. 8282–8286). Флаги из атрибутов `<Ссылка>`: стр. 8727–8747.

**1. Регистр соответствий** (`ВыполнитьЗаменуУникальногоИдентификатораПриНеобходимости`, стр. 8320–8363).
- По `{УникальныйИдентификатор}`: запрос к `РегистрСведений.СоответствияОбъектовИнформационныхБаз` — узел,
  `УникальныйИдентификаторПриемника` = GUID из сообщения, типы (текст — стр. 14727–14738). Нашли → GUID
  подменяется GUID этой базы (стр. 8357–8359).
- Основной объект: получаем объект по GUID; существует — свойства поиска переписываются на нём, конец; удалён —
  поиск идёт дальше (стр. 8761–8779). Значение-ссылка: ссылка по GUID без проверки существования (стр. 8781–8785).
- Не нашли — готовится запись (стр. 8340–8350); после записи основного объекта `ЗаписатьОбъектВИБ` добавляет её с
  его ссылкой (стр. 1772–1778). Объект, найденный по полям, со следующего обмена находится уже здесь.

**2. Предопределённый** (`{ИмяПредопределенногоЭлемента}`, стр. 8790–8830): по имени предопределённых данных,
затем `НайтиПоКоду` (`одНайтиОбъектПоСвойству`, стр. 3920–3928); не создаётся (стр. 8793).

**3. По GUID** (если есть `{УникальныйИдентификатор}`, стр. 8832–8909).
- Основной: `Ссылка.ПолучитьОбъект()` (`ПроверитьСуществованиеСсылки`, стр. 3852–3861); нашли — свойства поиска
  пишутся в объект (`НайтиИлиСоздатьОбъектПоСвойству`, стр. 8170–8187). Не нашли и нет `НеСоздаватьЕслиНеНайден`
  и `ПродолжитьПоиск` — создаётся новый объект с GUID источника (стр. 8837, 8159–8165; `УстановитьСсылкуНового`,
  стр. 7773–7781). Без `ПродолжитьПоиск` на этом шаге всё заканчивается (стр. 8856–8860).
- Ссылка без `ПродолжитьПоиск`: сразу `ПолучитьСсылку(GUID)` без проверки (стр. 8884–8888) — «битая» ссылка, пока
  сам объект не придёт. С `ПродолжитьПоиск`: проверка запросом, без создания (стр. 8862–8882, 3863–3878).

**4. Обработчик `ПоследовательностьПолейПоиска`** — см. раздел ниже (стр. 8911–9016).

**5. Поля поиска без обработчика** — один поиск по всем свойствам поиска (стр. 9018–9024).

`НайтиЭлементПоСвойствамПоиска` (стр. 8552–8604) для шагов 4–5:
- Берёт свойства из `СтрокаИменСвойствПоиска` (`СтрРазделить(…, ", ")` — разделители запятая и пробел), пустая —
  все свойства поиска (стр. 8559–8576). Свойство не из `СвойстваПоиска` молча пропадает.
- Документ: ровно два свойства (без GUID и имени предопределённого), это `Номер` и `Дата`, и нет
  `ПоискПоДатеНаРавенство` → `Менеджер.НайтиПоНомеру(Номер, Дата)` (`НайтиСсылкуНаДокумент`, стр. 8524–8549);
  иначе запрос, где `Дата = &Дата` — точное совпадение с временем.
- Запрос: `ВЫБРАТЬ Ссылка ИЗ <Вид>.<Имя> ГДЕ A = &A И …` (стр. 14361–14363; `НайтиЭлементЗапросом`,
  стр. 8414–8456); строка неограниченной длины — `ПОДОБНО` (стр. 8440–8442); GUID и имя предопределённого в
  условие не входят (стр. 8429–8431); ни одного условия — «не найден» (стр. 8452–8454). Берётся первая строка без
  сортировки (стр. 8465–8468).

**6. Найденный документ** (также задача, бизнес-процесс): `Дата` из свойств поиска переписывается, если не пустая
и без `НеЗамещать` (стр. 9026–9047).

**7. Не нашли** (стр. 9049–9072).
- Значение-ссылка с GUID — ссылка с этим GUID, без создания (стр. 8736, 8758, 9054–9056).
- Иначе, если нет `НеСоздаватьЕслиНеНайден` — `СоздатьНовыйОбъект` (стр. 7861–7957): группа, если
  `ЭтоГруппа` = Истина (стр. 7873–7877); GUID источника или новый (стр. 7771–7792); свойства поиска — в объект,
  если `УстанавливатьУОбъектаВсеСвойстваПоиска` (стр. 7928–7930); пустая дата документа — текущая (стр. 7937–7941).
  Основной объект пишется позже, со всеми свойствами; значение-ссылка без GUID **записывается сразу** только со
  свойствами поиска (стр. 7945–7947, 9060–9061).
- `НеСоздаватьЕслиНеНайден` у основного объекта — объект пропускается (`ПрочитатьОбъект`, стр. 10771–10777).

**После поиска** (`ПрочитатьОбъект`): `НеЗамещать` у найденного (стр. 10780–10785, 10829–10834); свойства с
`НеЗамещать` у найденного не пишутся (стр. 10686–10693); пустые `Номер`/`Код` при
`ГенерироватьНовыйНомерИлиКодЕслиНеУказан` (стр. 10386–10420, 11097, 11216).

## Обработчик `ПоследовательностьПолейПоиска`

- Выполняется в приёмнике, код — из копии правил отправителя в приёмнике (правила корреспондента,
  `handlers.md`, «Где лежат правила загрузки»; чтение — стр. 5967–5982); `Выполнить` в контексте
  `НайтиОбъектПоСсылке` (стр. 8959), в режиме отладки — процедурой с 7 параметрами
  (`ВыполнитьОбработчик_ПКО_ПоследовательностьПолейПоиска`, стр. 15321–15343). Опираться только на них:
  - `НомерВариантаПоиска` — 1, 2, … до 10 (стр. 8912, 8940, 9013);
  - `СвойстваПоиска` — Соответствие свойств поиска (шаг 0), в т.ч. `{УникальныйИдентификатор}`;
  - `ПараметрыОбъекта` — `Неопределено` или Соответствие параметров из `<Ссылка>`;
  - `СтрокаИменСвойствПоиска` — вернуть имена через запятую (начально пустая, стр. 8913);
  - `ПрекратитьПоиск` — Истина: больше не искать (стр. 8915, 8974);
  - `СсылкаНаОбъект` — можно найти объект самому: заполненная ссылка завершает цикл (стр. 8976);
  - `УстанавливатьУОбъектаВсеСвойстваПоиска` — Ложь: свойства поиска не переносятся ни в найденный, ни в новый
    объект (стр. 8616–8618, 7928–7930).
- Цикл: после вызова — поиск, если строка изменилась, `ПрекратитьПоиск` не стоит и ссылка не заполнена
  (стр. 8974–8984); найден — конец. Как подбирать варианты — грабли, «Варианты поиска должны различаться».
- Исключение — ошибка 73 в протокол и прерывание загрузки, если не включено «продолжать при ошибке»
  (стр. 8967–8972; `ЗаписатьИнформациюОбОшибкеЗагрузкиОбработчикаПКО`, стр. 4974–4978).
- Таблица «Варианты поиска» ПКО (`НастройкаВариантовПоискаОбъектов`) в обмен не идёт (стр. 6194–6200): имена
  вариантов в обработчике недоступны, только номер.

## Рецепт: ключи поиска

**Справочник**
1. Объект рождается в одной базе (источник — хозяин): `СинхронизироватьПоИдентификатору`, без
   `ПродолжитьПоиск`; поля поиска всё равно нужны: они пишутся в найденный объект (стр. 8187) и в новый.
2. Объект могли завести в обеих базах (контрагенты, номенклатура, банки): плюс `ПродолжитьПоиск`; ключ —
   естественный и заполненный в обеих базах (ИНН + КПП, код классификатора, артикул); наименование — последним
   вариантом. Несколько ключей — обработчик с вариантами от узкого к широкому и проверкой заполненности ключа.
3. Уникальность в разрезе владельца или родителя (договоры, банковские счета) — `Владелец`/`Родитель` в ключ;
   значение-ссылка в ключе сама ищется по своему ПКО — проверьте, что её ПКО находит.
4. Справочник ведёт приёмник — `НеЗамещать`; обязан уже быть в приёмнике — `НеСоздаватьЕслиНеНайден` (для
   значения-ссылки с GUID не действует — шаг 7).

**Документ**
1. `СинхронизироватьПоИдентификатору` — да; `ПродолжитьПоиск` — обычно нет (документ рождается в одной базе).
2. Если нужен поиск по полям: `Номер` + `Дата` — поиск `НайтиПоНомеру` (в пределах периода уникальности номера —
   поведение платформы, по коду БСП не проверено); третий ключ (`Организация`) переводит на запрос с точной
   датой; `ПоискПоДатеНаРавенство` у ПКС даты — тоже точная дата.
3. `Номер` не передаётся или нумерация своя — `ГенерироватьНовыйНомерИлиКодЕслиНеУказан`.

**Всегда:** ПКО без свойств поиска и без `СинхронизироватьПоИдентификатору` — новый объект при каждой загрузке.
Проверка ключей — живым обменом (грабли, «Как проверить исправление живым обменом»).
