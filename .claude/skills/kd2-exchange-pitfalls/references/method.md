# Метод разбора: ссылки на БСП, порядок целиком, как пополнять

Полный текст разделов `SKILL.md`: что значат ссылки на строки БСП в справочниках скилла, шаги 0–6 «Как разбирать жалобу» с доказательствами и правила пополнения скилла.

Справочник проверенных случаев, не привязанных к конкретной конфигурации. Каждый подтверждён кодом
исполнителя правил БСП — обработки `КонвертацияОбъектовИнформационныхБаз`, модуль объекта
(`DataProcessors/КонвертацияОбъектовИнформационныхБаз/Ext/ObjectModule.bsl` в выгрузке любой конфигурации
на БСП), а для настроек обмена — общих модулей `ОбменДаннымиСервер` и `ОбщегоНазначения` той же БСП (так и
указано у ссылки). Ссылка — имя процедуры и строки в БСП **3.1.12**; в другой версии и в конфигурации с
доработками строки сдвигаются, процедуры — те же (обработка сверена с 3.1.2). `РПО, стр. N` — модуль менеджера
регистра `ПравилаДляОбменаДанными` той же БСП. `УОД:N` — модуль объекта универсальной обработки
`УниверсальныйОбменДаннымиXML` («Универсальный обмен данными в формате XML») из той же выгрузки, версия обработки
1.0.5.234; в другой версии обработки строки сдвинуты.

## Как разбирать жалобу

Ответ человеку: диагноз — со ссылкой на процедуру и строки БСП (из этого скилла или из выгрузки конфигурации
приёмника), а не только на строку файла правил; строки, которые прочитаны, но в ответ не попали, доказательством
для человека не служат.

0. **Есть текст ошибки обмена** — где лежит протокол, что значит код и как от строки дойти до правила —
   `references/protocol.md`. **Жалоба словами** («задвоились», «не уходит», «пришёл непроведённым», «опять те же
   объекты») — `references/symptoms.md`: что проверить первым, процедура и строки исполнителя, раздел скилла и
   проверка сервера.
1. **Направление и база.** Обработчики загрузки в базе Б при обмене из А — из правил направления А → Б, но
   исполняет их **копия в Б** — файл правил корреспондента (`CorrespondentExchangeRules.xml`) комплекта Б.
   Ошибка загрузки в Б правится в `ExchangeRules.xml` комплекта А **и** в правилах корреспондента Б, загружаются
   оба комплекта. Доказательства и исключение (внешнее соединение) —
   `kd2-rules-build/references/handlers.md`, «Где лежат правила загрузки».
2. **Живые правила из обеих баз** (ZIP «Сохранить правила конвертации в файл»): `rules_open` →
   `rules_validate` с обеими структурами — часть граблей ловится проверкой (код в скобках у заголовка).
3. **ПКО проблемного объекта** — `rules_get`: флаги (`СинхронизироватьПоИдентификатору`,
   `ПродолжитьПоискПоПолямПоискаЕслиПоИдентификаторуНеНашли`, `НеЗамещать`), ПКС с `search: true`,
   обработчик `ПоследовательностьПолейПоиска`. Как объект вообще уходит: ПВД и их обработчики, ПКС других
   ПКО с его `КодПравилаКонвертации`.
4. **Сравнить с типовым макетом** плана обмена (`rules_open` макета) — что доработано. Макет лежит в выгрузке
   конфигурации (`dump` в `project_list`): `<dump>\ExchangePlans\<план>\Templates\ПравилаОбмена\Ext\Template.txt`,
   правила корреспондента — `…\Templates\ПравилаОбменаКорреспондента\Ext\Template.txt`. Макет действует, только
   если правила в базе взяты из него: правила, загруженные из файла, обновление из макетов не перекрывает, а без
   обоих макетов конвертации записи из макетов нет вовсе — живые правила брать из базы, не из макета
   (`kd2-rules-build/references/live-rules.md`, «Какие правила действуют в базе»).
5. **Данные** — в песочнице через сервер данных базы (`data_mcp` в `project_list`), только чтение и только с
   согласия человека в этой задаче: спросить одной строкой, какой запрос и зачем; нет согласия — «не проверено».
   Правилам и коду верить больше, чем словам «1С не даст записать»: проверять по модулю объекта.
   Серверы кода, БСП и данных — по правилу `kd2-rules-build/references/mcp-1c.md` (прочитать перед первым
   вызовом).
6. **Правка** — по скиллу `kd2-rules-build` (`kd2-rules-build/references/live-rules.md`): `rules_open` живого
   `ExchangeRules.xml` источника → `rule_update` в этом проекте правил → `rules_validate` → `rules_save` в
   `ExchangeRules.xml` источника и в правила корреспондента приёмника (шаг 1); коммит — спросить одной строкой.
   Правила конвертации (`ExchangeRules.xml`, `CorrespondentExchangeRules.xml`) правятся только сервером, руками
   (инструментом редактирования, `sed`) — нет: шум концов строк и канонической формы, см. `live-rules.md` там же,
   шаг 5. Правила регистрации (`RegistrationRules.xml`) — сервером (`registration_build`), а то, чего он не пишет
   (обработчики), — правкой файла по `kd2-rules-build/references/pro.md`, «Ручная правка
   файла»: загрузка БСП не сверяет ни `Ид`, ни версию, но читает файл потоково — важны порядок элементов,
   `Валидное="true"` у каждого правила, булевы `true`/`false`, тексты обработчиков экранированным текстом без
   CDATA и комментариев. Правка — побайтово (не `sed -i`), после неё `rules_validate` и `bsp_check`.

## Как пополнять

- Только универсальное: без имён баз, организаций, контрагентов и людей; пример — обезличенный.
- Только с доказательством: процедура и строки БСП (версия — в шапке) или воспроизведение в песочнице;
  что не воспроизводилось на живой базе — так и написать.
- Формат: симптом → причина → проверка → исправление.
- Грабли, которые ловятся по тексту правил без баз, — ещё и проверкой в `rules_validate` (код проверки — в
  заголовке раздела; список проверок — `kd2-rules-build/references/checks.md`, новая — задача в репозитории
  сервера https://github.com/egordoronchenko/kd-rules-mcp).
- Новая находка пишется в справочник своей темы; в `SKILL.md` — только строка маршрута, если темы ещё нет.
