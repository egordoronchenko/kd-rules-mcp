# Протокол обмена БСП: где лежит и как от строки дойти до правила
Читать, когда жалоба пришла с текстом ошибки обмена или обмен завершился «Ошибка» / «с предупреждениями».

Ссылки `стр. N` — модуль объекта обработки `КонвертацияОбъектовИнформационныхБаз` (БСП 3.1.12);
`ОбменДаннымиСервер, стр. N` — общий модуль той же БСП. В другой версии строки сдвигаются, процедуры те же.

## Где лежит

- Каждая строка протокола проходит через `ЗаписатьВПротоколВыполнения` (стр. 4787–4914) и пишется сразу в
  несколько мест — искать можно в любом из них.
- **Журнал регистрации** — всегда: событие «Обмен данными.<имя плана обмена>.<действие>» (ключ —
  `ОбменДаннымиСервер.КлючСообщенияЖурналаРегистрации`, стр. 6202–6214; запись — стр. 4875–4877, 18595–18610),
  уровень «Ошибка», «Предупреждение» или «Информация» по результату (стр. 4861–4873); при загрузке метаданные
  события — план обмена узла-отправителя (стр. 18603–18606).
- **Регистр `РезультатыОбменаДанными`** — причина, узел, проблемный объект, если известен, и тип проблемы «ошибка
  кода обработчиков при отправке / при получении данных» (стр. 4879–4911); это предупреждения синхронизации в
  интерфейсе программы (вывод: форма не сверялась).
- **Файл протокола** — только если в настройках отладки правил узла включено протоколирование и задано имя
  файла: поля `РежимПротоколированияОбменаДанными`, `ИмяФайлаПротоколаОбмена` регистра правил
  (`ОбменДаннымиСервер`, стр. 5596–5598, 10096–10110); пишутся ошибки, а с протоколированием — и информация
  (стр. 4845–4859); кодировка ANSI (стр. 4718).
- **Итог обмена** — результат «Выполнено» или нет; штатный обмен через файл или строку при ошибке бросает
  исключение с текстом последней записи протокола (`ОбменДаннымиСервер`, стр. 5219–5222). Это строка
  `ЗАГРУЗКА ОШИБКА <текст>` в выводе `exchange_check` (скрипт из клона сервера); полный протокол прогона — в
  журнале регистрации песочницы (последняя ошибка — `vcloggetlasterror` сервера данных,
  `kd2-rules-build/references/mcp-1c.md`).

## Как читать запись

- Первая строка — текст по коду ошибки (таблица кодов — `ИнициализацияСообщений`, стр. 14258–14354; выбор
  текста — стр. 4800–4810) или сам текст исключения, если кода нет.
- Дальше — строки «Поле = значение» (стр. 4816–4829) из структуры записи (`ЗаписьПротоколаОбмена`,
  стр. 4652–4697): `ИмяПКО` или `ПКО` («код (наименование)»), `ПКС`, `ПВД`, `Объект`, `ТипОбъекта`, `Источник`,
  `СвойствоПриемника`, `КонвертируемоеЗначение`, `Обработчик`, `ОписаниеОшибки`, `ПозицияМодуля`
  (стр. 4958, 4985, 5007–5008, 5037).
- `Обработчик` — имя по шаблону: `ПКО_<код ПКО>_<событие>` (стр. 5889–5975), `ПКС_<ПКО><родитель><свойство>_
  <событие>_<код ПКС>_<длина>` (стр. 5581–5607), `ПКГС_…` (стр. 5382–5426), `ПВД_<код ПВД>_<событие>`
  (стр. 6833–6848).

## От строки протокола к правилу

1. Код → строка таблицы: фаза, база и вид правила. Без кода — исключение платформы (запись, блокировка,
   проверка заполнения) — искать по `Объект` и `ОписаниеОшибки` (вывод).
2. Живые правила той базы, где выполнялась фаза (`rules_open`), → `rules_get` по коду ПКО из `ИмяПКО`/`ПКО`
   или из имени `Обработчик`; ПКС — по коду из поля `ПКС`.
3. `ОписаниеОшибки` и `ПозицияМодуля` — текст исключения; номер строки в позиции для кода из `Выполнить` —
   строка внутри текста обработчика (вывод: не сверено с платформой). Текст обработчика — `rules_get` (длинный
   обрезается) или `handlers_export`; ошибка синтаксиса — синтакс-чекер и `handlers_locate`.
4. `Объект`, `Источник`, `КонвертируемоеЗначение` — на каких данных; повторить обмен этого объекта в песочницах
   (`kd2-rules-build/references/checks.md`, `exchange_check`) — старыми правилами ошибка воспроизводится,
   исправленными — нет.
