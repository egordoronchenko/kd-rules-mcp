# Выгрузка объектов
Читать, когда объект не выгружается, уходит только ссылкой или реквизит в приёмнике пуст без ошибки в протоколе.

## Объект не выгружается сам — «ждём, пока выгрузится»

- **Причина:** включённого ПВД на тип объекта нет (выборка изменений берёт только типы включённых ПВД,
  `ВыполнитьВыгрузку`, стр. 17931–17942; `ВыполнитьВыгрузкуЗарегистрированныхДанных`, стр. 18236), объект не
  зарегистрирован на узле, или `ПередВыгрузкойОбъекта` ПВД / глобальный ставит `Отказ = Истина`
  (`ВыгрузкаОбъектаВыборки`, стр. 13626–13628). Объект уходит только значением свойства других объектов
  (например, контрагент — только как реквизит договора). Часто это рабочая схема, а не ошибка — уточнить у
  владельца правил. `Отказ` в `ПередОбработкойПравила` ПВД в обмене через план не проверяется (стр. 18369–18404),
  `Отключить` у группы ПВД не читается (`ЗагрузитьПравилаВыгрузки`, стр. 6868–6888).
- **Проверка:** `rules_get kind=pvd` — обработчики ПВД; регистрация на узле; кто ссылается на ПКО объекта — ПКС
  других ПКО с его `КодПравилаКонвертации`, их `ПередВыгрузкой` (`ВыгрузитьОбъект = Истина` — объект уходит
  целиком). Подробно — `kd2-rules-build/references/pvd.md`.

## Объект по ссылке: целиком или только ссылкой

- Значение ссылочного свойства выгружается объектом целиком, только если у правила регистрации объекта есть
  реквизит-флаг узла (`РежимыВыгрузкиОбъектовОбмена`) со значением «при необходимости» или пустым
  (`ВыгружатьОбъектПоСсылке`, стр. 3393–3437) и объекта ещё нет в регистре соответствий для узла (он добавляется
  туда как «выгружен по ссылке»); иначе — только узлом `<Ссылка>` со свойствами поиска (`ВыгрузитьСвойства`,
  стр. 13170–13196). Ещё путь — `ВыгрузитьОбъект = Истина` в `ПередВыгрузкой` ПКС.
- **Следствие для правил:** у ПКО, которое уходит только ссылкой, исполняются лишь ПКС с флагом «Поиск»;
  остальные ПКС и их замечания (`structure.pko_missing`, `structure.pks_type`) на обмен не влияют, а правка такой
  ПКС ничего не меняет в приёмнике. Сервер предупреждает об этом заранее — `structure.pko_ref_only` в
  `rules_validate`: ПКО ссылочного типа без ПВД, на которое ссылаются только ПКС без `ВыгрузитьОбъект = Истина`.
  Текст замечания называет оба выхода; для классификаторов, которые приёмник находит по полям поиска, это
  штатная схема.
- **Обработчики загрузки такого ПКО не вызываются.** `ПередЗагрузкой`, `ПриЗагрузке` и `ПослеЗагрузки`
  выполняются только при чтении узла `<Объект>` (`ПрочитатьОбъект`; «после загрузки» — на закрывающем теге,
  стр. 10986–11005). Узел `<Ссылка>` в значении свойства читает `ПрочитатьСвойство` → `НайтиОбъектПоСсылке`
  (стр. 7984–8010): из правил ссылочного ПКО исполняется только `ПоследовательностьПолейПоиска`
  (стр. 8920–8959). Что будет с ненайденным объектом, зависит от того, есть ли в узле `<Ссылка>` уникальный
  идентификатор (стр. 8736, 8758–8759, 9054–9061): **с идентификатором объект не создаётся** — в реквизит
  ставится ссылка с этим идентификатором, и пока сам объект не придёт целиком, это битая ссылка («объект не
  найден»); без идентификатора объект создаётся и записывается сразу, без обработчиков ПКО. Обмен с битой
  ссылкой завершается без ошибки (ветка с идентификатором подтверждена обменом в тестовых базах).
  Поэтому ошибка в обработчике загрузки ПКО, которое уходит только ссылкой (например, `algorithm.missing`), в
  обычной работе не проявляется — до тех пор, пока объект не начнёт уходить целиком (флаг «при необходимости»
  в правилах регистрации или `ВыгрузитьОбъект = Истина`). Проверено чтением кода, не обменом.

## Реквизит молча не приходит

- **Симптом:** ссылочный реквизит в приёмнике пуст, в протоколе обмена ошибок нет.
- **Причина:** у ПКС нет `КодПравилаКонвертации`, а ПКО для типа значения в правилах нет — значение молча не
  выгружается (`ВыгрузитьСвойства`, стр. 13154–13162). ПКС без источника берёт реквизит источника с именем
  приёмника, ошибка чтения проглатывается (`ПолучитьЗначениеСвойства`, стр. 12128–12156).
- **Исправление:** код ПКО у ПКС или ПКО для типа (`kd2-rules-build/references/pks.md`).
