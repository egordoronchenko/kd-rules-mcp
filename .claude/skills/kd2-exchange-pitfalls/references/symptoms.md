# От слов человека к месту в коде: симптом → что проверить → где читать
Читать, когда жалоба пришла словами («задвоились», «не уходит», «пришёл непроведённым»), без текста ошибки.
С текстом ошибки и кодом — `protocol.md`.

Строка таблицы — **что проверить первым**, а не готовый диагноз: причина подтверждается правилами, данными и
протоколом конкретного обмена. Из файла правил не видны данные узла, даты запрета, права, счётчики сообщений.

Ссылки `стр. N` — модуль объекта обработки `КонвертацияОбъектовИнформационныхБаз` (БСП 3.1.12); `События` —
общий модуль `ОбменДаннымиСобытия`; `Сервер` — общий модуль `ОбменДаннымиСервер`; `РПО` — модуль менеджера
регистра `ПравилаДляОбменаДанными`; `ЗПР` — модуль объекта обработки `ЗагрузкаПравилРегистрацииОбъектов`.
В другой версии строки сдвигаются, процедуры те же.

## Регистрация и выгрузка

| Как говорит человек | Что проверить | Где читать, что ловит сервер |
|---|---|---|
| «Объект вообще не регистрируется» | Вызывается ли подписка плана и не отключена ли регистрация свойством `ОтключитьМеханизмРегистрацииОбъектов` (События, стр. 20–39); правила регистрации исполняются при записи, только если авторегистрация объекта в составе плана запрещена (События, стр. 1389–1414). При выборочной регистрации — входит ли изменённый реквизит в ПКС | SKILL, «Регистрация»; `kd2-rules-build/references/pro.md`, «Как БСП применяет ПРО»; `registration.autoregistration`, `registration.plan_membership` |
| «Зарегистрировал вручную, а в файле нет» / «вместо объекта ушло удаление» | При отправке объект проверяется правилами регистрации ещё раз: не прошёл — при начальной выгрузке пропускается, иначе уходит удалением, регистрация снимается (`ПриОтправкеДанных`, События, стр. 2944–3009). Выборка идёт только по типам включённых ПВД (стр. 18210–18236) | `pro.md`, «Перепроверка при выгрузке»; `registration.no_pvd` |
| «Правило регистрации выбирает не тех получателей» | Как собран запрос отбора: группы «И»/«ИЛИ», табличные части узла (ЗПР, стр. 693–781); свой запрос и его параметры (`МассивУзловПоЗначениямСвойств`, События, стр. 2192–2228). Несколько правил одного объекта объединяют получателей (События, стр. 1642–1681) | `pro.md`, разделы об отборах; `registration.plan_property`, `registration.object_property` |
| «Одно правило сработало, другого как будто нет» | Несколько включённых ПВД одного типа: при обмене через план берётся первое найденное (стр. 18361–18367) | `kd2-rules-build/references/pvd.md` |
| «После обновления программы работает старый код правил» | Правила загружены из файла: обновление типовых макетов их не трогает (Сервер, стр. 11769–11817, 11963–11974). Проверить обе копии направления: правила выгрузки в отправителе и правила корреспондента в приёмнике (Сервер, стр. 10022–10083) | `kd2-rules-build/references/live-rules.md`, «Какие правила действуют в базе»; SKILL, «Как разбирать жалобу», шаги 1 и 4 |
| «В форме нельзя выбрать файл правил» | В БСП 3.1.12 переключатель «из файла» в форме загрузки правил отключён; программная загрузка комплекта работает (`ЗагрузитьКомплектПравил`, РПО, стр. 632–813) | `live-rules.md`; SKILL, «Загрузка правил в базу» |
| «Реквизит изменили, а объект не ушёл» | Режим выборочной регистрации «согласно правилам XML»: изменение реквизита, которого нет ни в одной ПКС (включая отключённые), объект не регистрирует | `pro.md`, «Как БСП применяет ПРО» |

## Поиск и загрузка

| Как говорит человек | Что проверить | Где читать, что ловит сервер |
|---|---|---|
| «Задвоились контрагенты» | На каком шаге поиска объект не нашёлся и какой ключ был фактически (`НайтиОбъектПоСсылке`, стр. 8761–8785, 8832–8909, 9018–9024). Отдельно — не осталась ли часть объектов от прошлой загрузки с ошибкой: транзакция необязательна, отложенные операции идут после фиксации (стр. 2496–2536) | SKILL, «Поиск существующего объекта при загрузке», «После ошибки обмена часть объектов уже в приёмнике»; проверки `search.*` |
| «Нашёлся помеченный на удаление элемент» | В запросе поиска по полям отбора по пометке удаления нет (`НайтиЭлементЗапросом`, стр. 8424–8468) | `kd2-rules-build/references/search.md` |
| «Объект не найден» / «ссылка пустая, хотя идентификатор есть» | Объект, пришедший значением-ссылкой с идентификатором, не ищется и не создаётся: берётся ссылка с этим идентификатором, даже если объекта нет (стр. 8887); продолжение поиска по полям — стр. 9018–9024 | `search.md`, шаги; `search.continue_without_fields`, `search.unreachable_handler` |
| «Нашёл документ другого дня» | Ровно два свойства поиска `Номер` и `Дата` без точного равенства даты — поиск `НайтиПоНомеру` в пределах периода номера (`НайтиСсылкуНаДокумент`, стр. 8524–8549) | `search.md`, «Рецепт: ключи поиска», документ |
| «Группы пришли элементами» | Признак `ЭтоГруппа` не среди свойств поиска: вид объекта выбирается при создании только по нему (стр. 7870–7883) | `search.md`, «Признак ЭтоГруппа среди свойств поиска»; `search.group_flag` |
| «Документ пришёл непроведённым» | Какой режим записи выбран и попал ли документ в очередь отложенного проведения (`ПрочитатьОбъект`, стр. 11053–11156; Сервер, стр. 6278–6388); ошибка проведения записывается в протокол, обмен при этом не падает | SKILL, «Документ в приёмнике не проведён после обмена»; `structure.document_posting` |
| «Исправил правила в сообщении — ничего не изменилось» | Приёмник исполняет свою копию правил: при заранее заполненной таблице правила внутри сообщения не читаются (`НачатьЧтениеСообщения`, стр. 7485–7492) | `kd2-rules-build/references/handlers.md`, «Где лежат правила загрузки» |
| «Параметр в обработчике пустой — пришёл поздно» | Порядок: `ПередЗагрузкойДанных` (стр. 7494–7531) → параметры (стр. 7563–7587) → `ПослеЗагрузкиПараметров` (стр. 7590–7598) | `handlers.md`, «Где и когда вызывается» |
| «Нет субконто, хотя сумма проводки есть» | Вид субконто и значение конвертируются раздельно; значение без ПКО своего типа молча пропускается (`_ВыгрузитьСубконто`, стр. 12288–12330) | `kd2-rules-build/references/pks.md`; `structure.pko_missing` |
| «Хранилище значения загрузилось, ссылки внутри чужие» | Значение хранилища сериализуется целиком, ссылки внутри по ПКО не конвертируются (стр. 12584–12595, 4346–4352, 4512–4521) | — |
| «Удалил последнюю запись регистра, у получателя осталась» | Передан ли пустой набор и с каким отбором: выгрузка набора (`ВыгрузитьРегистр`, стр. 2314–2345, 2397–2405), чтение и запись (стр. 10140–10185, 10314–10331). Пустой набор — штатное сообщение, а не ошибка | `pks.md`, «Группа ПКС: табличная часть и набор записей» |
| «Две группы свойств в одну табличную часть — строки пропали» | Каждая группа загружается отдельно и замещает строки; `НеОчищать` на табличную часть не действует | `pks.md`, «Поля ПКС в XML» |

## Доставка, коллизии, запреты

| Как говорит человек | Что проверить | Где читать |
|---|---|---|
| «Моя правка затёрлась при обмене» | Была ли у объекта своя регистрация к выгрузке и что решил обработчик коллизии; в режиме по умолчанию главный узел принимается, подчинённый игнорируется (`ПроверитьКоллизиюИзмененийДанных`, События, стр. 3883–3928; приоритет — стр. 11035–11049) | по файлу правил не определяется: нужны данные узлов |
| «Документ не загрузился из-за даты запрета» | Проверяется запрет **загрузки** для узла (`ПроверитьНаличиеЗапретаЗагрузкиПоДате`, События, стр. 3980–4017); это не дата запрета изменения для пользователей | настройки дат запрета в приёмнике |
| «Опять пришли те же объекты» | Отправитель не получил подтверждения (ответного сообщения) либо объект изменён заново (`ПрочитатьДанныеПоОбмену`, стр. 17385–17447). Различать новый номер сообщения с теми же объектами и повтор прежнего номера | счётчики узла в обеих базах и регистрация |
| «Сообщение уже было принято» (код 174) | Номер входящего не больше принятого (стр. 17418–17434). Счётчики не обнулять | `protocol.md`, код 174 |
