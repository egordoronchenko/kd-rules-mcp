# Поиск существующего объекта при загрузке
Читать, когда объект задвоился, связался с чужим или не находится при загрузке.

Загрузка ищет объект сразу, как прочитала узел `<Ссылка>` (`ПрочитатьОбъект`, стр. 10735–10757), по шагам
`kd2-rules-build/references/search.md` (`НайтиОбъектПоСсылке`, стр. 8702–8711, 8761–8830, 9018–9024): регистр
соответствий и уникальный идентификатор — только если в `<Ссылка>` есть `{УникальныйИдентификатор}` (флаг ПКО
`СинхронизироватьПоИдентификатору`), между ними — имя предопределённого; затем обработчик
`ПоследовательностьПолейПоиска` или поля поиска — сразу, если идентификатора нет, а с ним — только когда по нему не
нашли и у ПКО стоит `ПродолжитьПоискПоПолямПоискаЕслиПоИдентификаторуНеНашли` (без флага поиск кончается на
идентификаторе, стр. 8856–8858). В узел `<Ссылка>` выгрузка пишет **только свойства поиска** ПКО
(`ВыгрузитьПоПравилу`, стр. 790–826).

## Параметр объекта в обработчике поиска не виден (`search.param_not_in_search`)

- **Симптом:** объект задваивается, хотя обработчик `ПоследовательностьПолейПоиска` «должен» выбрать поиск
  по параметру (например, по виду лица — ИНН + КПП для юрлиц); срабатывает ветка `ПараметрыОбъекта = Неопределено`.
- **Причина:** обработчик читает `ПараметрыОбъекта["X"]`, а ПКС, передающее `X` (`ИмяПараметраДляПередачи`),
  без флага «Поиск». Такой параметр идёт в свойствах объекта и читается после поиска (`ПрочитатьОбъект`,
  стр. 10705).
- **Исправление:** флаг «Поиск» у ПКС параметра. Параметр уйдёт в `<Ссылка>` узлом `<ЗначениеПараметра>`
  (`СоздатьСложнуюИнформациюДляЗаписиВXML`, стр. 12691) и попадёт в `ПараметрыОбъекта` до поиска
  (`ПрочитатьСвойстваПоискаИзФайла`, стр. 8228–8291). ПКС с «Поиск» и пустым приёмником допустимо
  (`ЗагрузитьПКС`, стр. 5494); как условие запроса параметр не используется (`ЗагрузитьПравилоКонвертации`,
  стр. 6079–6082) — он только выбирает строку полей.
- Параметр нельзя сделать «полем поиска» в строке `СтрокаИменСвойствПоиска`: условие строится только по
  свойствам поиска (`НайтиЭлементПоСвойствамПоиска`, стр. 8566–8577), параметра среди них нет — он молча
  пропускается.
- Воспроизведено живым обменом в песочницах: без флага — второй объект с теми же ИНН/КПП, с флагом —
  документ ссылается на существующий (заведённый в приёмнике вручную, с другим наименованием).

## Наименование в полях поиска

- **Симптом:** дубль при совпадающих ИНН и КПП.
- **Причина:** поиск «ИНН, КПП, Наименование» — условие запроса по **каждому** имени строки полей
  (`НайтиЭлементПоСвойствамПоиска`, стр. 8559–8576), строка ограниченной длины сравнивается на точное равенство
  `Наименование = &Наименование` (`НайтиЭлементЗапросом`, стр. 8440–8446); одно расхождение в наименовании — не
  найден, создаётся новый. Расходится оно часто: в двух базах наименование пишут по-разному (ручной ввод в одной,
  заполнение по ИНН из ФНС в другой — порядок слов, кавычки, сокращения формы собственности) — (вывод).
- **Исправление:** для юрлиц с ИНН — без наименования (ИНН + КПП), наименование — только когда ИНН пуст.

## Варианты поиска должны различаться

- Обработчик вызывается с `НомерВариантаПоиска` = 1, 2, … до 10, перебор идёт, только пока он возвращает
  **новую** строку полей: та же строка, что в прошлом варианте, `ПрекратитьПоиск` или найденный объект —
  конец (`НайтиОбъектПоСсылке`, стр. 8940, 8974–8976). Обработчик, который не смотрит на
  `НомерВариантаПоиска`, даёт одну попытку.
- Пустая строка полей **в первом вызове** (ни одна ветка не сработала; начальное значение — пустая строка,
  стр. 8913) — поиск по **всем** свойствам поиска ПКО (`НайтиЭлементПоСвойствамПоиска`, стр. 8559–8561). Между
  вызовами строка не сбрасывается (стр. 9014): со второго вызова несработавшая ветка оставляет прошлую строку —
  перебор кончается без поиска, и после цикла — «не найден», шаг 7 `kd2-rules-build/references/search.md` (стр. 9050–9063). Поиск по всем свойствам
  на позднем варианте — только явным присвоением пустой строки.
- Типовой образец для контрагентов: при заполненном ИНН 1 — ИНН, КПП, Наименование; 2 — ИНН, КПП; 3 — ИНН,
  Наименование; без ИНН — Наименование (у всех — ещё `ЭтоГруппа`). Так — обработчик
  `ПоследовательностьПолейПоиска` ПКО `Контрагенты` в типовом макете `ПравилаОбмена` плана
  `ОбменБухгалтерияПредприятияДокументооборот20` (Бухгалтерия предприятия 3.0.205, `Ext/Template.txt`,
  стр. 1308–1321); в другом плане и версии — сверить с его макетом (`rules_open` → `rules_get`).

## Пустой ИНН в поиске по ИНН

- **Симптом:** объект источника связался в приёмнике с чужим объектом (без ИНН); документы «висят» не на том
  контрагенте. Хуже дубля — не видно сразу.
- **Причина:** пустое значение приходит `<Пусто/>` и читается пустой строкой (`ПрочитатьСвойство`,
  стр. 8060–8063), попадает в поля поиска (стр. 8290); запрос — `ВЫБРАТЬ Ссылка ИЗ … ГДЕ ИНН = &ИНН И КПП = &КПП`
  без пропуска пустых и без упорядочивания, берётся первая строка (`НайтиЭлементЗапросом`, стр. 8425–8463).
- **Исправление:** перед поиском без наименования проверять `ЗначениеЗаполнено(СвойстваПоиска["ИНН"])`
  (так делает типовой обработчик). То, что таких объектов сейчас нет, не защищает: типовой модуль объекта
  контрагента запись без ИНН не запрещает (иностранные, физлица). Исправление проверено живым обменом:
  юрлицо без ИНН создаётся отдельно и не цепляется к чужому объекту без ИНН; само ошибочное связывание
  (без проверки) живым обменом не воспроизводилось.

## Ключ поиска свёлся к `ЭтоГруппа`

- **Симптом:** разные элементы источника в приёмнике «находят» один и тот же существующий элемент (группы —
  одну группу) и по очереди перезаписывают его; новые объекты не создаются.
- **Причина:** из свойств поиска (без GUID и имени предопределённого) в условии осталось одно `ЭтоГруппа`: у ПКО
  нет других ПКС с «Поиск»/«Обязательное», или обработчик задаёт строку «ИНН, КПП, ЭтоГруппа», а `ИНН` и `КПП` не
  свойства поиска — они молча выпадают (`НайтиЭлементПоСвойствамПоиска`, стр. 8565–8574). Условие —
  `ЭтоГруппа = &ЭтоГруппа` (у элемента Ложь, `ПрочитатьСвойстваПоискаИзФайла`, стр. 8282–8286), берётся первая
  строка без упорядочивания (`НайтиЭлементЗапросом`, стр. 8424–8450, 8465–8468), `ОбъектНайден = Истина`
  (стр. 9067–9070), свойства `<Объект>` пишутся в найденный (`ПрочитатьОбъект`, стр. 10711). Без `ЭтоГруппа` в
  строке те же имена дали бы пустое условие и «не найден» (стр. 8452–8454). При идентификаторе без
  `ПродолжитьПоиск` до полей не доходит (стр. 8856–8858). (вывод по цепочке кода, живым обменом не проверялось)
- **Проверка:** `rules_get` ПКО — ПКС с `search: true`; каждое имя из строк обработчика должно быть среди них.
- **Исправление:** флаг «Поиск» у ПКС ключевых реквизитов; `ЭтоГруппа` — только вместе с настоящим ключом.

## У ПКО нет ключей поиска

- **Симптом:** при каждом обмене в приёмнике новый экземпляр одного и того же объекта.
- **Причина:** у ПКО нет ни свойств поиска, ни `СинхронизироватьПоИдентификатору` — узел `<Ссылка>` не
  пишется (`ВыгрузитьПоПравилу`, стр. 788–791), искать приёмнику нечем (`ПрочитатьОбъект`, стр. 10617–10671).
- **Исправление:** ключи поиска или флаг синхронизации (`kd2-rules-build/references/search.md`, «Рецепт»).
