# Правила установки целиком

Полный текст правил из `SKILL.md`: точки, где закончить ход, доступ к серверу и чужим настройкам. Таблица «Если не получилось» — `troubleshooting.md`.

## Правила

- **После каждого шага — его проверка.** Не прошла — не идти дальше, разобрать по таблице `troubleshooting.md`, сказать
  человеку, что не так.
- **Спрашивать, а не угадывать:** где лежат проекты, какие у них базы и какая из баз **песочница**. Роль базы
  определяет только человек: `песочница` разрешает скриптам подключаться к базе, `боевая` — нет.
- **Где закончить ход.** В этих точках не делать работу человека и не считать согласием ответы на прежние
  вопросы: написать, что нужно от него, и **закончить ход**; продолжать только после его ответа.
  1. Установка программ: `git`, `uv` — после согласия; Docker Desktop (WSL 2) и регистрацию `comcntr.dll`
     человек ставит сам, с правами администратора (шаги 0, 8).
  2. Пароли: не спрашивать их в чате и не вписывать в файлы. Логин базы берётся из `.dev.env` проекта
     (`dev_env` у базы) либо человек сам вписывает `logins` в `projects.local.yaml` (шаги 3–4, 8).
  3. `projects.yaml` — показать файл целиком и получить «да» (шаг 3).
  4. Запись в репозиторий проекта 1С — скиллы и `.mcp.json` (шаг 6), папка `rules_dir` (шаг 2) — только с его «да».
  5. Одобрение MCP-сервера: сервер, дописанный в `.mcp.json` в этой сессии, клиенту не виден до перезапуска —
     человек перезапускает клиент и одобряет сервер (шаг 6).
  6. Обновление при несохранённых проектах правил (шаг 9.1, до любых команд обновления); предусловие проекта, без которого сервер не работает
     (шаг 2); `docker info` падает (шаг 0).
- **Инструменты сервера — только через клиент.** Свой MCP-клиент, HTTP-запросы к серверу из скриптов — нельзя:
  это обход одобрения сервера человеком. Исключение — `scripts/check_server.py` из клона либо через
  `docker compose exec` своего сервера как проверка шага 5.
- **Чужие настройки не читать.** Глобальные настройки клиентов (`~\.cursor`, `~\.claude`, `%APPDATA%\…`) не
  читать и не цитировать: там токены других серверов. Что подключено к клиенту — `claude mcp list` /
  `cursor-agent mcp list` или вопрос человеку. Чужие контейнеры и процессы (`docker inspect`, `docker exec` не
  своего контейнера) не трогать: в их настройках чужие пути и секреты. Имена и порты своего экземпляра —
  `docker ps` и `docker compose config` в папке клона.
- `projects.yaml`, `projects.local.yaml`, `.mcp.json`, `.cursor/mcp.json`, `docker-compose.override.yml`, `.env`
  в git не коммитить (они в `.gitignore`).
- Тексты с обратной косой (пути Windows) править инструментами редактирования файлов, а не строками Python в
  скрипте.
