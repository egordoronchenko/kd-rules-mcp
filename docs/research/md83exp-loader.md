# Загрузчик MD83Exp в SQLite: замеры и решения

Дата: 26.09.2026.
Код: `src/kd_rules_mcp/structures/` (`db.py` — схема, `md83exp.py` — загрузчик, `store.py` — кэш).
Тесты: `tests/test_structures_md83exp.py` (синтетический файл `tests/data/md83exp_small.xml`);
тест на реальных выгрузках (маркер `structures`) в репозиторий не входит.

## Замеры на выгрузках песочницы БП

Python 3.12, lxml 6.1, SQLite из stdlib. Пиковая память — `PeakWorkingSetSize` процесса.

| Выгрузка | Размер | Объекты | Свойства | Значения | Наборов типов | Загрузка | Пик памяти | Файл кэша |
|---|---|---|---|---|---|---|---|---|
| `БП с расширениями.xml` | 970 МБ | 5 524 | 188 485 | 17 963 | 6 227 | 70,8 с | 383 МБ | 85 МБ |
| `БП без расширений.xml` | 951 МБ | 5 429 | 186 973 | 17 873 | 6 156 | 68,6 с | 383 МБ | 85 МБ |

- Счётчики совпадают со спецификацией и с разовым сравнением `md83exp-extensions-check.md`.
- Повторная загрузка того же содержимого — 0,8 с (только SHA-256 входа, без разбора).
- 188 485 свойств ссылаются всего на 6 227 различных наборов типов: дедупликация сжимает
  950 МБ XML до 85 МБ базы.
- Сам проход по XML — около 30 с; остальное — вставка в SQLite и разрешение ссылок.

## Решения

- **Один проход вместо двух.** КД читает файл дважды (`ЗагрузкаСтруктурыМетаданных`,
  строки 19–151), чтобы ссылки на ещё не прочитанные объекты разрешались. Здесь записи идут в
  промежуточные таблицы с GUID, а владелец, родитель и типы разрешаются в конце запросами —
  результат тот же, файл читается один раз. Исходная постановка предполагала «два прохода»; проверяемые
  критерии (счётчики, память < 1 ГБ) выполнены.
- **Имя типа — `Description` объекта** (`СправочникСсылка.Валюты`): MD83Exp пишет его в
  `ВыгрузитьОбъект` (`reference/kd2-dist-src/MD83Exp/ВыгрузкаМетаданных/Ext/ObjectModule.bsl:250-264`),
  а `Типы/Row/Тип` свойства ссылается на `Ref` этого объекта (`ПолучитьУИИмениТипа`, 2079–2092).
- **`ТипыСтрокой` не хранится**: MD83Exp всегда пишет его пустым (строки 1321, 1369, 1456, 1492, 1530).
- **Неразрешённые типы** сохраняются у свойства (`properties.unresolved`) и считаются в
  метаданных. В выгрузках песочницы БП их 10 — все у элементов состава планов обмена и все
  указывают на **последовательности** (`ДокументыОрганизаций`, последовательности доработки,
  `Удалить…Взаиморасчеты…`): последовательности MD83Exp объектами не выгружает.
- **Кэш**: один файл SQLite на структуру; повторное использование — при том же SHA-256 входа
  **и той же версии загрузчика** (хеш исходников `db.py` и `md83exp.py`), иначе изменённый
  загрузчик тихо работал бы на старых данных. Загрузка идёт во временный `.part`, который
  заменяет прежний файл только при успехе — ошибка входа сохранённую структуру не портит.
- **Идентификатор структуры** — латиница, цифры и `_.-`: он же имя файла в кэше.

## Как воспроизвести

```bash
uv run pytest -m structures -q
```

Первый прогон разбирает обе выгрузки (~2,5 мин) в `cache/`, следующие берут их из кэша.
