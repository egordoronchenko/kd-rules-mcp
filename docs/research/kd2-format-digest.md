## 1. Файл структуры метаданных (MD83Exp)

Файл: `КД\reference\kd2-dist-src\MD83Exp\ВыгрузкаМетаданных\Ext\ObjectModule.bsl`.

### 1.1 Корень и общая раскладка

Корневой элемент — `<Конфигурация Имя="...">` с объявлением `xsi` (строки 48–50). Внутри — плоская последовательность элементов четырёх «псевдо-справочников» (это не настоящий справочник, а имя XML-типа для `ЗаписатьXML`/`ПрочитатьXML`, читается как дамп табличных данных Конфигурации/Объекты/Свойства/Значения):

- `CatalogObject.Конфигурации` — один элемент, сама конфигурация (`ВыгрузитьКонфигурацию`, строки 106–123).
- `CatalogObject.Объекты` — узлы метаданных: сначала группы-разделы (`Справочники`, `Документы`, …, строка 184 `ВыгрузитьОбъекты`), затем сами объекты (`ВыгрузитьОбъект`, 246–273), плюс группа `ПланыВидовРасчета`/`ПланыОбмена` и т.д. Иерархия строится через `Owner`/`Parent` (см. 1.3).
- `CatalogObject.Свойства` — реквизиты/измерения/ресурсы/табличные части/элементы состава плана обмена/движения регистраторов; строится дерево через `Parent`.
- `CatalogObject.Значения` — значения перечислений и предопределённые элементы; плоский список, привязан через `Owner`.

Порядок выгрузки объектов (`ВыполнитьВыгрузку`, 28–104): `ПланыОбмена → Справочники → Документы → Перечисления → ПланыВидовХарактеристик → ПланыСчетов → ПланыВидовРасчета → [РегистрыСведений/Накопления/Бухгалтерии/Расчета, если не отключены флагами] → БизнесПроцессы → Задачи`. Перед этим выгружаются 7 примитивных типов-заглушек (`Число, Строка, Дата, Булево, ХранилищеЗначения, УникальныйИдентификатор, НаборКонстант`, строки 127–135) и обрабатываются общие реквизиты (`ЗаполнитьТаблицуОбщихРеквизитов`, 2173–2219).

### 1.2 Что пишется на объект

`ВыгрузитьОбъект` (246–273) пишет `Ref/IsFolder/DeletionMark/Owner/Parent/Description/Имя/Синоним/Комментарий/Тип` (Тип — родовое имя вида `Справочник`/`Документ`/…, до точки в `ПолноеИмя()`), затем `ВыгрузитьНастраиваемыеСвойстваОбъекта` (275–406) добавляет по `Попытка/Исключение`‑пробе (то есть только если у объекта есть соответствующее свойство метаданных): `Иерархический, ВидИерархии, ОграничиватьКоличествоУровней, КоличествоУровней, СерииКодов, КонтрольУникальности, АвтоНумерация, Периодичность, Подчиненный` (эти поля есть и в справочнике-каталоге `Объекты`: `КД\reference\kd2-cfg\Catalogs\Объекты.xml`, атрибуты в строках 344–853).

Далее для каждого объекта последовательно (`ВыгрузитьОбъекты`, 217–225):
1. `ВыгрузитьОсновныеСвойства` (408–1150) — «условно-обязательные» системные реквизиты через `Попытка/Перейти ~Метка` (обход по свойствам метаданных: `ПометкаУдаления` всегда; `Код`(строка/число по `ТипКодаСправочника`); `Наименование`; `Родитель`(если иерархический); `ЭтоГруппа`; `Номер`; `Дата`/`Проведен`(для документов); `Владелец`(тип — массив ссылок на все владельцы); для регистров — `Активность`+`Регистратор`(регистратор пишется отдельной функцией, см. 1.4); `Период`(для периодических/накопления/бухгалтерии/расчёта); `ВидДвижения`/`СчетДт,СчетКт,СубконтоДт,СубконтоКт`(регистр бухгалтерии, с/без корреспонденции); `ВидРасчета,ПериодРегистрации,БазовыйПериодНачало/Конец,ПериодДействияНачало/Конец,Сторно`(регистр расчёта); `ПериодДействияБазовый`(план видов расчёта); `Стартован,Завершен,ВедущаяЗадача,РеквизитыАдресации*,БизнесПроцесс,Выполнена,ТочкаМаршрута`(бизнес-процессы/задачи).
2. `ВыгрузитьСвойства` (1152–1224) — `Измерения → Ресурсы → Реквизиты` объекта плюс общие реквизиты, каждый как `CatalogObject.Свойства` с `Вид="Измерение"/"Ресурс"/"Реквизит"`.
3. `ВыгрузитьТабличныеЧасти` (1423–1469) — на табличную часть пишется узел-папка `IsFolder=true, Вид="ТабличнаяЧасть"`, дочерние — её реквизиты `Вид="Реквизит"` с `Parent` = УИ табличной части.
4. `ВыгрузитьДвижения` (1545–1627) — на движение документа пишется узел `Вид` = `НаборДвиженийРегистра{Сведений|Накопления|Бухгалтерии|Расчета}`, затем рекурсивно `ВыгрузитьОсновныеСвойства`+`ВыгрузитьСвойства` уже от лица регистра (родитель — УИ движения).
5. `ВыгрузитьЗначенияПеречисления`/`ВыгрузитьПредопределенныеЗначения` (1629–1760) — значения перечислений и предопределённые элементы справочников/ПВХ/ПСч/ПВР (запросом `ГДЕ _.Предопределенный = ИСТИНА`; `Description` = имя предопределённого через `ПолучитьИмяПредопределенного`, либо код/представление).
6. Для `ПланыВидовРасчета` — `ВыгрузитьПредопределенныеТабличныеЧастиПВР` (1505–1543, использует `ПолучитьПредопределенныеТабличныеЧастиПВР`/`ПолучитьРеквизитыПредопределеннойТабличнойЧастиПВР`, 2094–2171) — синтетические ТЧ `БазовыеВидыРасчета`, `ВедущиеВидыРасчета`, `ВытесняющиеВидыРасчета` с колонкой `ВидРасчета` (ссылка на ПВР).
7. Для `ПланыОбмена` — `ВыгрузитьСоставПланаОбмена` (1471–1503) — узел `{Состав}` с `Вид="СоставПланаОбмена"`, дочерние — `ВыгрузитьЭлементСоставаПланаОбмена` (1329–1384) с `Вид="ЭлементСоставаПланаОбмена"` и `Авторегистрация` (из `АвтоРегистрацияИзменений.Разрешить`).
8. `ВыгрузитьТочкиМаршрутаБизнесПроцесса` (1762–1827) — точки маршрута как отдельные объекты `Тип="ТочкаМаршрутаБизнесПроцесса"`, их значения — сами точки как `CatalogObject.Значения`.

### 1.3 Ссылки между узлами — GUID, не имена

Каждый узел получает свой `Ref = Новый УникальныйИдентификатор()` (случайный, не детерминированный между запусками, кроме УИ для *типов*, см. ниже). Иерархия строится **только** через `Owner`(типизированная ссылка `xsi:type="CatalogRef.…"`, кто «владеет» строкой — объект метаданных для его свойств, конфигурация для корневых объектов) и `Parent`(предок в дереве того же справочника — например, УИ табличной части для её реквизитов). Родитель/владелец не по имени — по УИ, сгенерированному в текущем запуске выгрузки.

Единственная стабилизация — `ПолучитьУИИмениТипа` (2079–2092): УИ для *имени типа* (`СправочникСсылка.Объекты`, `ДокументСсылка.Заказ` и т.п.) кэшируется в `мСоответствиеИменТиповОбъектовУИ` **на время одного запуска**, чтобы один и тот же тип везде получал один и тот же `Ref` в `CatalogObject.Объекты` (используется как `Тип` в `CatalogObject.Свойства.Типы.Row.Тип`, 1372–1380, 1401–1413). Между разными запусками выгрузки эти УИ не совпадают — сопоставление при загрузке в КД делается по паре бизнес-ключей (Владелец+Наименование+Родитель+Вид, см. 1.4), а не по УИ.

Типы кодируются строками вида `СправочникСсылка.Имя`/`ДокументСсылка.Имя`/`ПеречислениеСсылка.Имя`/`РегистрСведенийЗапись.Имя` и т.д. (`ПолучитьТип`, 2021–2054, для примитивов и `XMLТип(...).ИмяТипа` с заменой префиксов для ссылочных; `ПолучитьТипОбъектаМетаданных`, 2056–2077, — то же для типа-владельца по `ПолноеИмя()`). Множественный тип свойства — несколько `<Типы><Row><Тип>…`.

### 1.4 Загрузка структуры в КД (`ЗагрузкаСтруктурыМетаданных`)

Файл: `КД\reference\kd2-cfg\DataProcessors\ЗагрузкаСтруктурыМетаданных\Ext\ObjectModule.bsl`.

`ВыполнитьЗагрузку` (19–151) читает файл **дважды**: первый проход — только `CatalogObject.Конфигурации`+`CatalogObject.Объекты` (заполняет справочник `Объекты`, попутно помечает на удаление то, что не встретилось при повторной загрузке, если не `ДобавлятьТолькоНовыеОбъектыСвойстваЗначения`), второй проход — `CatalogObject.Свойства`+`CatalogObject.Значения` (заполняет `Свойства`/`Значения`). Всё в одной транзакции, если `ВыполнятьЗагрузкуСтруктурыВОднойТранзакции`.

Целевые справочники и их ключевые атрибуты (сверено с `КД\reference\kd2-cfg\Catalogs\*.xml`):
- **Конфигурации** (`ПрочитатьКонфигурациюXML`, 153–289; атрибуты `Конфигурации.xml:91-318`): `Имя, Синоним, Комментарий, Версия, ДатаОбновления, Приложение`.
- **Объекты** (`ПрочитатьОбъектXML`, 291–507; атрибуты `Объекты.xml:344-853`): `Имя, Синоним, Комментарий, Тип, Иерархический, ВидИерархии, ОграничиватьКоличествоУровней, КоличествоУровней, СерииКодов, КонтрольУникальности, АвтоНумерация, Периодичность, Подчиненный` — сопоставление с уже существующей строкой не показано явно в первых ~500 строк модуля (не выписан явный поиск-запрос уровня «Объект»; при полной загрузке — стандартный `ПрочитатьXML` без поиска, см. строка 61 `ПрочитатьОбъектXML(ЧтениеXML, ...)`).
- **Свойства** (`ПрочитатьСвойствоXML`, 507–791): поиск существующей строки — запросом по `(Наименование, Владелец, Родитель, ЭтоГруппа, Вид)` (`мЗапросСвойств`/`мЗапросСоставПланаОбмена` в зависимости от того, `Вид=ЭлементСоставаПланаОбмена`; параметры видны в 653–657). Если не найдено — создаётся новый элемент/группа; если найдено — `УстановитьЗначениеПараметра` точечно обновляет только изменившиеся реквизиты (612–787), включая перестройку табличной части `Типы` только если изменилось количество строк.
- **Значения** (`ПрочитатьЗначениеXML`, 804+, не читалось построчно, но по аналогии со свойствами — атрибуты по `Значения.xml:94-248`: `Синоним, Комментарий, Предопределенное, Типы`).

Ключевой вывод: КД **не полагается на `Ref`/GUID из файла** как на устойчивый идентификатор между загрузками — сопоставление делается по бизнес-ключам (имя+владелец+родитель+вид), а `Ref` из файла используется только для *новых* элементов (`УстановитьСсылкуНового`) и для построения карты соответствия УИ старый→новый (`УстановитьСоответствиеУИ`, 964–969) внутри одной сессии загрузки — то есть, только для связывания `Owner="<GUID>"` с уже подставленным объектом в рамках текущего файла.

## 2. Писатель ПравилаОбмена 2.01 (`ВыгрузкаКонвертации`)

Файл: `КД\reference\kd2-cfg\DataProcessors\ВыгрузкаКонвертации\Ext\ObjectModule.bsl` (2610 строк).

### 2.1 Общий каркас (`ВыгрузитьКонвертацию`, 1449–1497)

```
<ПравилаОбмена>
  <ВерсияФормата РежимСовместимости="РежимСовместимостиСБСП20|21">2.01</ВерсияФормата>
  <Ид>…</Ид><Наименование>…</Наименование><ДатаВремяСоздания>…</ДатаВремяСоздания>
  <Источник ВерсияПлатформы=".." ВерсияКонфигурации=".." СинонимКонфигурации=..>Имя</Источник>
  <Приемник ...>Имя</Приемник>
  <УдалятьСопоставленныеОбъектыВПриемникеПриИхУдаленииВИсточнике>true</...>  (только если true)
  <Комментарий>…</Комментарий>
  [события конвертации — плоский список тегов, см. 2.2]
  <Параметры>…</Параметры>  или строка "Параметры" (см. 2.2)
  <Обработки>…</Обработки>
  <ПравилаКонвертацииОбъектов>…</ПравилаКонвертацииОбъектов>
  <ПравилаВыгрузкиДанных>…</ПравилаВыгрузкиДанных>
  <ПравилаОчисткиДанных>…</ПравилаОчисткиДанных>
  <Алгоритмы>…</Алгоритмы>
  <Запросы>…</Запросы>
</ПравилаОбмена>
```
(Реально проверено на образце — макет `ПравилаОбмена` доработанного плана обмена БП ↔ ЗУП, `ExchangePlans\<план>\Templates\ПравилаОбмена\Ext\Template.txt:1-63` — совпадает 1-в-1.)

Общий приём записи: `ДобавитьЭлемент(Имя, Значение)` (83–95) пишет тег `ЗаписатьТекст(XMLСтрока(Значение))` **только если** `ЗначениеЗаполнено(Значение)` — то есть пустые/незаполненные реквизиты в XML не попадают вовсе (не пишется как пустой тег). Экранирование — стандартное XML-экранирование через `XMLСтрока`, **CDATA нигде не используется** — даже код обработчиков пишется как обычный текстовый узел с escaping (`&lt;&gt;&amp;`; подтверждено в образце: `ПередВыгрузкойДанных` содержит `<>` как `&lt;&gt;`). `ВыгрузитьБулевоЗначениеТолькоЕслиИстина`(740–748) и `ВыгрузитьСтроковоеЗначениеТолькоЕслиНеПустая`(750–758) — те же паттерны «пишем только не-дефолт».

### 2.2 Заголовок и события (`ВыгрузитьРеквизитыКонвертации`/`ВыгрузитьСобытияКонвертации`, 389–555)

`ВерсияФормата` — атрибут `РежимСовместимости` = имя значения перечисления `Конвертация.РежимСовместимости` (`ИмяЗначенияПеречисления`, 42–68; сам реквизит `Конвертации.РежимСовместимости` типа `EnumRef.РежимСовместимости`, значения `РежимСовместимостиСБСП20`(умолчание, `КД\reference\kd2-cfg\Enums\РежимСовместимости.xml:111`)/`РежимСовместимостиСБСП21`(:99)).

Обработчики конвертации — плоские теги (пишутся, только если алгоритм не пуст): `ПослеЗагрузкиПравилОбмена, ПередПолучениемИзмененныхОбъектов, ПослеПолученияИнформацииОбУзлахОбмена, ПередВыгрузкойДанных, ПослеВыгрузкиДанных, ПередЗагрузкойДанных, ПослеЗагрузкиДанных, ПередВыгрузкойОбъекта, ПередКонвертациейОбъекта, ПослеВыгрузкиОбъекта, ПередЗагрузкойОбъекта, ПослеЗагрузкиОбъекта, ПередОтправкойИнформацииОбУдалении, ПриПолученииИнформацииОбУдалении, ПослеЗагрузкиПараметров` (437–457).

`Параметры` — двойной формат в зависимости от `ВыгружатьПараметрыПоВерсии2_01`: старый — просто строка кодов через запятую как текст тега `<Параметры>Код1, Код2</Параметры>`; новый — вложенные `<Параметр Имя=.. Наименование=.. ИспользуетсяПриЗагрузке=.. УстанавливатьВДиалоге=.. ТипЗначения=.. ПередаватьПараметрПриВыгрузке=.. ПравилоКонвертации=.. ПослеЗагрузкиПараметра=../>` (461–514; в образце используется новый формат, `Template.txt:60-62`). `Обработки` — вложенные `<Обработка Имя=.. Наименование=.. Параметры=.. Комментарий=.. ИспользуетсяПриВыгрузке=.. ИспользуетсяПриЗагрузке=.. ЭтоОбработкаНастройки=..>ХранилищеОбработки-как-XMLСтрока-двоичных-данных</Обработка>` (516–553).

### 2.3 ПКО — `<Правило>`/`<Группа>` (`ВыгрузитьПравилоКонвертацииОбъекта`, 792–888)

Общие для правила и группы: `Код, Наименование, Порядок, Описание, Комментарий`. У правила дополнительно (только не-дефолтные):
- обработчики `ПередВыгрузкой(АлгоритмПередВыгрузкойОбъекта), ПриВыгрузке, ПослеВыгрузки, ПослеВыгрузкиВФайл, ПередЗагрузкой, ПриЗагрузке, ПослеЗагрузки, ПоследовательностьПолейПоиска`;
- булевы флаги «только если Истина»: `НеЗамещать, НеЗапоминатьВыгруженные, СинхронизироватьПоИдентификатору, ПродолжитьПоискПоПолямПоискаЕслиПоИдентификаторуНеНашли, НеВыгружатьОбъектыСвойствПоСсылкам, НеСоздаватьЕслиНеНайден(из НеСоздаватьОбъектВПриемникеЕслиНеНайденПоПолямПоиска), ИспользоватьБыстрыйПоискПриЗагрузке, ГенерироватьНовыйНомерИлиКодЕслиНеУказан, ВыгружатьОбъектТолькоПриНаличииНаНегоСсылки, ПриПереносеОбъектаПоСсылкеУстанавливатьТолькоGIUD(так в коде, опечатка сохранена), НеЗамещатьОбъектСозданныйВИнформационнойБазеПриемнике`;
- `ПриоритетОбъектовОбмена` — пишется строкой `"Ниже"`/`"Совпадает"` **только если** значение отличается от значения по умолчанию `ПриоритетПоступившегоПриОбменеОбъектаВыше` (831–840; т.е. «выше» — молчаливый дефолт, тег не пишется);
- `Источник, Приемник` — имена типов (обязательные);
- `НастройкаВариантовПоискаОбъектов` — только если ТЧ не пуста, вложенные `<ВариантПоиска><ИмяНастройкиДляАлгоритма/ИмяНастройкиДляПользователя/ОписаниеНастройкиДляПользователя></ВариантПоиска>` (760–784);
- `<Свойства>`…`</Свойства>` — вложенные ПКС (см. 2.4);
- `<Значения>`…`</Значения>` — вложенные ПКЗ (см. 2.5).

### 2.4 ПКС — `<Свойство>`/`<Группа>` внутри `<Свойства>` (`ВыгрузитьПравилоКонвертацииСвойства`, 615–738)

Обходится деревом через `ВыгрузитьСтрокиДереваПКС` (1243–1290, обход результата иерархического запроса `Справочник.ПравилаКонвертацииСвойств`). У элемента-свойства: атрибуты `Отключить`(если true), `Поиск`(если true), `Обязательное`(если признак ЭтоГруппа-у-приёмника выставлен эвристикой `СвойстваПриемника.Наименование ПОДОБНО "%ЭтоГруппа%"`, см. запрос 1214–1216, — (вывод) похоже, зарезервировано для будущего распознавания «признак это группа» у приёмника); теги `НеЗамещать`(если true), `Код, Наименование, Порядок, Описание, Комментарий, ПолучитьИзВходящихДанных`(если true), вложенные `<Источник Имя=.. Вид=.. [Тип=..]/>`и `<Приемник Имя=.. Вид=.. [Тип=..]/>` (`Тип` — только если у свойства единственный тип), `КодПравилаКонвертации, ПриводитьКДлине`(только если включено автоприведение и у приёмника задана длина строки), `ИмяПараметраДляПередачи, ПоискПоДатеНаРавенство`(если true), обработчики `ПередВыгрузкой(АлгоритмПередВыгрузкойСвойства), ПриВыгрузке, ПослеВыгрузки`.

### 2.5 ПКЗ — `<Значение>`/`<Группа>` внутри `<Значения>` (`ВыгрузитьПравилоКонвертацииЗначения`, 563–607)

`Код, Наименование, Порядок, Описание, Комментарий, Источник(Наименование), Приемник(Наименование)`; группы — рекурсивно то же самое + вложенные значения. Источник запроса — `ВыполнитьЗапросПКЗ` (164–212, не читан построчно, но по использованию — вся коллекция ПКЗ по конвертации в дерево, привязка к конкретному ПКО через `Объект.ПравилоКонвертацииОбъектовСсылка`).

### 2.6 ПВД — `<Правило>`/`<Группа>` внутри `<ПравилаВыгрузкиДанных>` (896–957)

Атрибут `Отключить`; теги `Код, Наименование, Порядок, Описание, Комментарий, КодПравилаКонвертации, СпособОтбораДанных(имя значения перечисления), ОбъектВыборки(наименование объекта-источника)`; флаги «если true»: `ВыбиратьДанныеДляВыгрузкиОднимЗапросом, НеВыгружатьОбъектыСозданныеВБазеПриемнике`; обработчики: `ПередОбработкойПравила, ПередВыгрузкойОбъекта, ПослеВыгрузкиОбъекта, ПослеОбработкиПравила`.

### 2.7 ПОД — `<Правило>`/`<Группа>` внутри `<ПравилаОчисткиДанных>` (965–1018)

Атрибут `Отключить`; теги `Код, Порядок, Описание, Комментарий, Непосредственно, СпособОтбораДанных, ОбъектВыборки`; обработчики `ПередОбработкойПравила, ПослеОбработкиПравила, ПередУдалениемОбъекта`. Заметно, что у ПОД (в отличие от ПКО/ПВД) не пишется `Наименование` — вероятно, у справочника `ПравилаОчисткиДанных` этого реквизита нет или он не используется читателем (не проверялось напрямую по XML-схеме справочника).

### 2.8 Алгоритмы/Запросы (`ВыгрузитьАлгоритм`/`ВыгрузитьЗапрос`, 1026–1110)

`<Алгоритм Имя=.. ИспользуетсяПриЗагрузке=..><Текст>..текст-BSL..</Текст><Комментарий>..</Комментарий><Параметры>..список параметров через запятую..</Параметры></Алгоритм>`; группы — `<Группа Имя=..><Комментарий>..</Комментарий>[вложенные алгоритмы]</Группа>`. `Запрос` — то же самое, но без `Параметры` и с `<Текст>` = текст запроса. И там, и там код/текст пишется как обычный экранированный текстовый узел (не CDATA) — при наличии в тексте символов `<`, `>`, `&` они уходят как `&lt;/&gt;/&amp;` (см. образец `ПередВыгрузкойДанных` в 2.1 — там ровно так и есть).

### 2.9 Правила-корреспондента и файл регистрации — не «зеркалирование», а второй независимый набор (`ВыполнитьВыгрузкуПравил`, 1898–2005)

Если `ВыгружатьПравилаКорреспондента = Истина`, обработка **повторно вызывает** `ВыгрузитьКонвертацию(...)`, подставив в реквизит `КонвертацияДляВыгрузки` **другую** ссылку — на заранее отдельно настроенный объект `Конвертации`, взятый из реквизита `КонвертацияКорреспондентДляВыгрузки` (1935; сами реквизиты объявлены в `КД\reference\kd2-cfg\DataProcessors\ВыгрузкаКонвертации.xml:330,364`). Никакого автоматического «обращения» направления ПКО (Источник↔Приемник) в коде нет — см. раздел 6. Если ещё и `ВыгружатьПравилаРегистрации = Истина`, тем же вызовом дополнительно создаётся `Обработки.ВыгрузкаРегистрации` и вызывается её `ВыгрузитьРегистрацию()` (1955–1965) — то есть ПравилаРегистрации всегда пишутся отдельным XML-файлом, никогда не вложены внутрь ПравилаОбмена (что согласуется с тем, что писатель ПравилаОбмена нигде не пишет тег `<ПравилаРегистрацииОбъектов>`, а читатель БСП явно его пропускает — см. 3). При `СжиматьФайлПравил` все получившиеся файлы (`ExchangeRules.xml`, опционально `CorrespondentExchangeRules.xml`, `RegistrationRules.xml`) паковаются в один zip (1969–2003).

## 3. Читатель ПравилаОбмена в БСП (`КонвертацияОбъектовИнформационныхБаз`)

Файл: `БСП\DataProcessors\КонвертацияОбъектовИнформационныхБаз\Ext\ObjectModule.bsl` (18767 строк) — это не тонкая обёртка над `V8Exchan83`, а собственная реализация с той же архитектурой (см. также «эталонный» модуль `БСП\DataProcessors\УниверсальныйОбменДаннымиXML\Ext\ObjectModule.bsl`, куда, по всей видимости, портирован и доработан код V8Exchan83 — прямых вызовов между двумя DataProcessor'ами не найдено, (вывод) это независимые, но родственные копии одной кодовой базы).

### 3.1 Точка входа (`ЗагрузитьПравилаОбмена`, 16231–16560+)

Верхний цикл по `ПравилаОбмена.Прочитать()` (16300 и далее) распознаёт по `ЛокальноеИмя`:
- `ВерсияФормата, Ид, Наименование, ДатаВремяСоздания` — читаются в структуру `Конвертация`;
- `Источник`/`Приемник` — читаются вместе с атрибутами `ВерсияПлатформы, СинонимКонфигурации, ВерсияКонфигурации` (16329–16353); если вызов был с `ЗагружатьТолькоЗаголовокПравил=Истина`, чтение останавливается сразу после `Приемник` (16355–16357) — то есть «показать инфо о правилах» не досчитывает файл до конца;
- `РежимСовместимости, Комментарий, ОсновнойПланОбмена` — **явно пропускаются** (`одПропустить`, 16359–16368) — то есть узел `РежимСовместимости` как отдельный тег читатель ожидает(!), хотя писатель кладёт его только как **атрибут** тега `ВерсияФормата` (см. 2.2) — эта ветка в читателе, судя по всему, историческая/защитная и в актуальном формате 2.01 не срабатывает (сам атрибут `РежимСовместимости` у `ВерсияФормата` читателем нигде не читается через `ПолучитьАтрибут`, т.е. **фактически используется только режим по умолчанию** — не проверялось глубже, где `РежимСовместимости` вообще влияет на поведение загрузки);
- `Параметры` → `ЗагрузитьПараметры`;
- события конвертации — плоский список (16376–16450), взаимно однозначен с писателем (2.2), плюс `УдалятьСопоставленныеОбъектыВПриемникеПриИхУдаленииВИсточнике`;
- `ПравилаВыгрузкиДанных` → пропускается, если `РежимОбмена="Загрузка"` (16455–16459, ПВД не нужны на приёмнике);
- `ПравилаКонвертацииОбъектов` → `ЗагрузитьПравилаКонвертации`;
- `ПравилаОчисткиДанных` → `ЗагрузитьПравилаОчистки`;
- **`ПравилаРегистрацииОбъектов` — явно пропускается** (`одПропустить`, 16467–16468) — этот тег не используется читателем ПравилаОбмена в принципе (что согласуется с тем, что пишется он совсем другим обработчиком, см. 2.9/4);
- `Алгоритмы, Запросы, Обработки` — свои загрузчики;
- любой нераспознанный тег на этом уровне → ошибка формата (код протокола 7, 16489–16493) — то есть верхний уровень **строгий**, а не «пропускаем неизвестное».

### 3.2 ПКО (`ЗагрузитьПравилоКонвертации`, 5737–6139)

Читает весь список тегов писателя из 2.3 один в один, с двумя примечаниями:
- `РегистрироватьОбъектНаУзлеОтправителе` — распознаётся по имени, но **всегда пропускается** с комментарием `// не поддерживается` (5774–5776) — тег из более старых версий формата КД, в текущем писателе (`ВыгрузкаКонвертации`) не эмитируется вовсе;
- `ПриоритетОбъектовОбмена` — читаются только строки `"Ниже"`/`"Совпадает"`; всё остальное (включая отсутствие тега) молча остаётся дефолтным `ПриоритетОбъектаОбменаВыше` (5984–5992) — согласуется с тем, что писатель этот тег не пишет для дефолтного значения (2.3).

### 3.3 Прочее

`ЗагрузитьПКС`(5470+)/`ЗагрузитьСвойства`(5637+)/`ЗагрузитьПКЗ`(5682+)/`ЗагрузитьЗначения`(5714+)/`ЗагрузитьНастройкуВариантовПоиска`(6139+)/`ЗагрузитьПравилаОчистки`(6379+)/`ЗагрузитьАлгоритм(ы)`(6435–6508)/`ЗагрузитьЗапрос(ы)`(6508–6581)/`ЗагрузитьПараметры`(6581+)/`ЗагрузитьОбработку(и)`(6686–6764)/`ЗагрузитьПВД`(6764+) — по беглой сверке (grep по именам тегов) распознают тот же набор тегов, что пишет `ВыгрузкаКонвертации` (не выписывалось построчно ввиду объёма модуля — 18k строк). Явных зафиксированных расхождений «писатель пишет — читатель не знает» кроме двух пунктов 3.1/3.2 не найдено (кроме случая ПравилаРегистрации, см. §4, где расхождение куда заметнее).

Между чтением ПравилаОбмена читатель параллельно **переписывает** прочитанное в собственный `ЗаписьXML` (переменная `ЗаписьXML`, строка 16296+) — то есть при загрузке одновременно строится нормализованная копия правил в строку `XMLПравила` (16497), которая, по всей видимости, (вывод) используется дальше как кеш/источник для повторного разбора без файла (см. `ЗагрузитьПравилоКонвертации(ПравилаОбмена, ЗаписьXML)` и однотипные сигнатуры — второй параметр везде).

## 4. ПравилаРегистрации: писатель и читатель

### 4.1 Писатель (`КД\reference\kd2-cfg\DataProcessors\ВыгрузкаРегистрации\Ext\ObjectModule.bsl`)

Внутри `<ЭлементОтбора>` (по свойству плана обмена, `ВыгрузитьЭлементОтбора`, 323–360): `ЭтоСтрокаКонстанты, ТипСвойстваОбъекта(наименование), СвойствоПланаОбмена, ВидСравнения(имя перечисления), СвойствоОбъекта(строка — либо путь свойства, либо литерал константы), ТаблицаСвойствОбъекта, ТаблицаСвойствПланаОбмена` (вложенности свойств — списки `<Свойство><Наименование/><Тип/><Вид/></Свойство>`, нужны читателю для восстановления вложенных путей типа `Ссылка.Организация.ИНН`). Группа отбора — `<Группа><БулевоЗначениеГруппы>И|ИЛИ(имя перечисления)</БулевоЗначениеГруппы>… вложенные ЭлементОтбора/Группа …</Группа>`.

Для `<ОтборПоСвойствамОбъекта>` (`ВыгрузитьЭлементОтбораОбъекта`, 362–400) набор тегов немного другой: `ТипСвойстваОбъекта, ВидСравнения, СвойствоОбъекта, [Вид — если поле ВидЭлементаОтбора существует у ТЗ], ЗначениеКонстанты, ТаблицаСвойствОбъекта` (без `ТаблицаСвойствПланаОбмена`, без `ЭтоСтрокаКонстанты`).

### 4.2 Читатель (`БСП\DataProcessors\ЗагрузкаПравилРегистрацииОбъектов\Ext\ObjectModule.bsl`)

`ЗагрузитьРегистрацию` (144–230) читает `ВерсияФормата, Ид, Наименование, ДатаВремяСоздания, ПланОбмена(+атрибут Имя), Комментарий, Конфигурация(+3 атрибута)`. **`СоставПланаОбмена` в этом цикле верхнего уровня не обрабатывается вовсе** — нет такой ветки `Если ИмяУзла = "СоставПланаОбмена"`, поэтому он проваливается в `Иначе → одПропустить(Правила)` (222–226), то есть **весь блок `<СоставПланаОбмена>` со всеми `<Элемент>` молча игнорируется читателем БСП** — используется, по всей видимости, (вывод) только на стороне «мастера» плана обмена/автонастройки, а не при собственно загрузке правил регистрации в память.

`ЗагрузитьПравилоРегистрации` (279–363): правила с `Отключить=true` или `Валидное=false` **не грузятся вовсе** (пропуск всего под-дерева, 282–293) — то есть у писателя нет флага «отключено при выгрузке», отбор происходит на загрузке. Читаются: `ОбъектНастройки, ОбъектМетаданныхИмя, РеквизитРежимаВыгрузки(→ИмяРеквизитаФлага), ОтборПоСвойствамПланаОбмена, ОтборПоСвойствамОбъекта, ПередОбработкой, ПриОбработке, ПриОбработкеДополнительный, ПослеОбработки`. **Тег `ОбъектМетаданныхТип`, который писатель кладёт (строка 218 писателя, подтверждено в образце `Template.txt:130`), в этом цикле не имеет своей ветки** — тоже проваливается в `одПропустить` (355–359): читатель восстанавливает тип объекта из строки `ОбъектМетаданныхИмя` (префикс до точки), а не из отдельного тега.

## 5. Автонастройка правил

### 5.1 ПКО — сопоставление объектов (`АвтонастройкаПравилКонвертацииОбъектов\Ext\ObjectModule.bsl`)

Алгоритм — SQL-запрос с **полным соединением** (`ПОЛНОЕ СОЕДИНЕНИЕ`, строка 125) множества объектов-источников и объектов-приёмников **по равенству `(Наименование, Тип)`** (139: `Источники.Наименование = Приемники.Наименование И Источники.Тип = Приемники.Тип`, 55–170). Сопоставление — только по имени объекта метаданных (как оно попало в справочник `Объекты` при выгрузке структуры) и его роду (`Тип` — перечисление `ТипыОбъектов`); никакого сопоставления по синониму нет. Есть режим «показывать только данные без правил» (`ОтображатьТолькоДанныеБезПравил`) — тогда к запросу добавляется `ЛЕВОЕ СОЕДИНЕНИЕ …ПравилаКонвертацииОбъектов… ГДЕ Правила.Ссылка ЕСТЬ NULL`, чтобы не предлагать уже покрытые объекты. Новое ПКО при сохранении (`СохранитьПравила`, 196–265) получает только `Владелец, Источник, Приемник, Наименование(=глНаименованиеПКО(...))` — остальные поля правила остаются платформенными дефолтами объекта `ПравилаКонвертацииОбъектов`; опционально (по ответу пользователя на диалог) рекурсивно достраиваются нужные ПКС/ПКЗ (`РекурсивноеСозданиеНеобходимыхОбъектовДляПКО`, не читалось подробно).

### 5.2 ПКС — сопоставление свойств (`АвтонастройкаПравилКонвертацииСвойств\Ext\ObjectModule.bsl`)

Матчинг — по **`(Наименование, Вид)`** свойства (`СинхронизироватьСвойство`, 577–630: `НайтиСтроки({НаименованиеИсточника=Свойство.Наименование, ВидИсточника=Свойство.Вид})`). Если прямого совпадения нет, но имя входит в жёстко зашитый список синонимов документа — пробуется альтернативное имя: `Номер↔НомерДок`, `Дата↔ДатаДок` (`ОбщегоНазначения.ИмяРеквизитаМожетБытьИзменено`/`ПолучитьАналогИмениРеквизита`, `КД\reference\kd2-cfg\CommonModules\ОбщегоНазначения\Ext\Module.bsl:1628-1659`) — других переименований нет. Табличные части и дерево свойств обходятся рекурсивно через дерево значений с ключом «Соответствие[Родитель]→строка», то есть вложенность (табличная часть → её реквизиты) матчится только если сама табличная часть уже сопоставлена по имени на уровне выше (139–428).

Проверка допустимости автосопоставления типов — две отдельные функции:
- `НужноИскатьИлиСоздаватьПКОДляДанных` (456–515) — решает, нужно ли **искать/создавать под это свойство отдельное ПКО** (для сложных типов); примитивные типы и «простые» служебные типы (`Булево, Дата, Строка, Число, Календарь, НаборКонстант`, все виды регистров, `УникальныйИдентификатор, ХранилищеЗначения`) ПКО не требуют.
- `ОпределитьМожноАвтоматическиСопоставитьЭлементы` (517–564) — запрещает автосопоставление, если тип-источник примитивный (`Булево/Дата/Строка/Число`), а тип-приёмник — ссылочный объектный тип (`БизнесПроцесс, Документ, Задача, ПланВидовРасчета, ПланВидовХарактеристик, ПланОбмена, ПланСчетов, Справочник, ТочкаМаршрутаБизнесПроцесса`) — то есть примитив в ссылку конвертировать «само» не даёт, а обратное (ссылка → примитив, любые ссылка↔ссылка) не блокируется этой функцией.

Новое ПКС при сохранении (`СохранитьПравилаКС`, 794–898) получает `Владелец(=ПравилоКО), Родитель, Источник, Приемник, Порядок(шаг 50), ИмяИсточника/ВидИсточника/ТипИсточника, ИмяПриемника/ВидПриемника/ТипПриемника` и, что важно — **`Отключить = Истина`, если `Приемник` не найден/пуст** (816: `НовоеПравило.Отключить = Строка.Приемник.Пустая()`) — то есть автосозданные несопоставленные ПКС сохраняются в справочнике, но выключенными, а не удаляются.

### 5.3 ПКЗ (`АвтонастройкаПравилКонвертацииЗначений`) — не читалось детально (465 строк, вне бюджета этого дайджеста); (вывод) по аналогии с ПКС, видимо, сопоставление значений перечислений идёт тоже по имени (`Наименование`) значения перечисления с обеих сторон.

Прямого поиска по «Корреспондент/обратн/зеркаль» в `КД\reference\kd2-cfg\DataProcessors` — только один DataProcessor причастен: `ВыгрузкаКонвертации` (реквизиты `КонвертацияКорреспондентДляВыгрузки`, `ВыгружатьПравилаКорреспондента`, `КД\reference\kd2-cfg\DataProcessors\ВыгрузкаКонвертации.xml:330,364`). ## Итоговые технические заметки для генератора правил

1. **GUID/Ref в MD83Exp-дампе — не устойчивы между запусками** (кроме УИ типов внутри одного прогона) — при генерации ПравилаОбмена/ПравилаРегистрации из собственной модели метаданных можно использовать любые собственные GUID для `Ref`, лишь бы `Owner`/`Parent`/`Тип` внутри одного файла были внутренне согласованы; сопоставление на стороне загрузчика КД всё равно идёт по бизнес-ключу (Владелец+Имя+Родитель+Вид).
2. **Формат ПравилаОбмена 2.01 — «пиши только не-дефолт»**: почти все булевы и часть строковых полей вообще не появляются в XML, если равны платформенному умолчанию. Генератор, повторяющий этот стиль, будет давать более компактные и «похожие на эталонные» файлы, но читатель (см. §3) в целом одинаково спокойно принимает и явно продублированные дефолты.
3. **Не использовать CDATA** — весь текст (включая код обработчиков и текст запросов) пишется как обычный XML-текст с стандартным экранированием.
4. **`ПравилаРегистрацииОбъектов` как тег внутри ПравилаОбмена не существует** — регистрация всегда отдельный файл/поток с корнем `<ПравилаРегистрации>`; если сгенерировать её вложенной в ПравилаОбмена, читатель БСП её тихо проигнорирует (`одПропустить`).
5. **Известные «мёртвые»/игнорируемые читателем теги**, которые не стоит считать обязательными при генерации (но не вредно писать, раз читатель их спокойно пропускает): `РежимСовместимости` как отдельный тег на уровне ПравилаОбмена (используется только как атрибут `ВерсияФормата`), `РегистрироватьОбъектНаУзлеОтправителе` у ПКО, `ОбъектМетаданныхТип` у правила регистрации, весь блок `СоставПланаОбмена` у правил регистрации.
6. **Автосопоставление — по имени и роду объекта/свойства**, с двумя точечными синонимами (`Номер`/`НомерДок`, `Дата`/`ДатаДок`) и запретом «примитив → объектная ссылка». Для генератора это значит: чтобы автонастройка КД (если она когда-то будет прогнана поверх сгенерированных правил) не расходилась с самим генератором, стоит либо сохранять точные оригинальные имена реквизитов источника при копировании метаданных, либо не полагаться на автонастройку КД вовсе и генерировать ПКС напрямую по своей модели соответствий.
