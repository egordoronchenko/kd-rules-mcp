| Сборка | Эталон | Объекты | Свойства | Изменённые свойства | Значения |
|---|---|---|---|---|---|

Единственное отличие — **211 предопределённых элементов**, которые есть в конфигурации, но
которых нет в базе: все у объектов с `PredefinedDataUpdate = DontAutoUpdate`
(`ДрайверыОборудования` 68, `ВидыИспользованияРабочегоВремени` 47, `ПрочиеДоходыИРасходы` 42,
`СтатьиДвиженияДенежныхСредств` 26, `СтатьиЗатрат` 15, `ИдентификаторыОбъектовМетаданных` 5,
`ШаблоныДокументов` 5, ПВХ `РазделыДатЗапретаИзменения` 2, `Контрагенты` 1). MD83Exp берёт
предопределённые запросом из базы (`ВыгрузитьПредопределенныеЗначения`, MD83Exp:1669-1760), а при
`DontAutoUpdate` платформа их в базе не создаёт. Сборщик берёт их из конфигурации — для правил
обмена это правильнее (набор определяется конфигурацией, а не состоянием конкретной базы).
Тест проверяет, что все лишние значения принадлежат объектам с `DontAutoUpdate`.

Неразрешённых типов 10 — последовательности в составе планов обмена; ровно те же, что у MD83Exp
(последовательности он объектами не выгружает).

## Правила, найденные при сверке

- **Системные свойства** — цепочка `ВыгрузитьОсновныеСвойства` (MD83Exp:408-1150): свойство
  добавляется, если у метаданных есть соответствующее свойство. Наличие проверяется по элементам
  `Properties` выгрузки: `BasedOn` → `ПометкаУдаления`, `CodeLength` → `Код`, `Hierarchical` →
  `Родитель`, `HierarchyType`/`CharacteristicExtValues` → `ЭтоГруппа`, `NumberLength` → `Номер`,
  `Posting`/`NumberType` → `Дата`, `Проведен` и т. д. Важно учитывать и составные элементы:
  непустой `BasedOn` содержит вложенные элементы, но это то же «свойство есть» (первая версия
  сборщика теряла из-за этого `ПометкаУдаления` у 193 объектов).
- **Типы**: примитивы и ссылки — по таблицам `ПолучитьТип` (MD83Exp:2021-2054); `DefinedType`,
  `Characteristic` (тип ПВХ), `AnyIBRef` и `cfg:CatalogRef` без имени (все справочники)
  разворачиваются; тип, для которого в структуре нет объекта, считается неразрешённым — как у
  MD83Exp, где GUID типа разрешается только через выгруженный объект.
- **Квалификаторы даты по умолчанию** — «Дата и время» у любого свойства без даты: так их пишет
  MD83Exp (`ОписаниеТипов` по умолчанию).
- **Расширения**: собственные объекты добавляются; у заимствованных — новые реквизиты, ТЧ,
  колонки, значения перечислений, движения, состав плана обмена. Заимствованный реквизит или
  определяемый тип с `Type xsi:type="xr:ExtendedProperty"` расширяет тип основной конфигурации
  (`xr:ExtendValue`): типы объединяются, квалификаторы расширяются — у числа целая и дробная
  части берутся по максимуму (Число(15,3) + Число(15,8) → Число(20,8)), неотрицательность — только
  если у обоих; у строки — максимальная длина, неограниченная побеждает. Правило выведено из
  эталона: 1 312 свойств до его реализации расходились ровно так.
- **Состав плана обмена**: одноимённые элементы разных видов (`Документ.ВыработкаМатериалов` и
  `РегистрНакопления.ВыработкаМатериалов`) давали одинаковый ключ сравнения; в
  `compare_structures` тип стал частью ключа элемента состава.
- **Неперечисленные расширения** не читаются вовсе (расширение 6).

## 4.5. Вторая и третья конфигурации (без эталона)

| Сборка | Объекты | Свойства | Значения | Время | Неразрешённые типы |
|---|---|---|---|---|---|
| ЗУП КОРП: `main` + 3 расширения | 2 443 | 88 644 | 7 600 | 21 с | нет |
| ДО КОРП: `main` + 2 расширения | 1 204 | 14 739 | 2 665 | 2–6 с | нет (после правки `AnyRef`, см. ниже) |

`cfg:AnyRef` («любая ссылка») в БП не встречался (там только `cfg:AnyIBRef`). В ДО он у
типичных для БСП реквизитов «любая ссылка» (`ОчередьОбновленияПравДоступа.Объект`,
`ДанныеОбработанныеВЦентральномУзлеРИБ.Данные` и т. п.). Разворачивается так же, как `AnyIBRef`, —
во все ссылочные типы конфигурации; эталона MD83Exp для ДО нет, это решение по смыслу типа.
До правки 9 свойств ДО оставались с неразрешённым `AnyRef`; после — неразрешённых типов нет.
Синтетический тест: `test_any_ref_includes_every_reference` в `tests/test_structures_xmlbuild.py`.
