# Сверка и пилот

Дата: 27.09.2026. Этап 8: сверка через базу КД и пилот.

## 8.1. Сверка через базу КД

Код: внешняя обработка `kdbase/src/ПроверкаЗагрузкиПравил` (исходники XML, собирается `epf-build`),
скрипт `kdbase/kd_check.py`, тесты `tests/test_kdbase.py` (маркер `kdbase`, только с `KD2_KDBASE_CHECK=1`).

- Обработка запускается `db-run -Execute` с `/C "kd2check|<правила>|<протокол>"`, загружает файл штатной
  `ЗагрузкаКонвертации` так же, как её форма (`ЗагрузитьПравилаОбмена`, затем `Сохранить` в новую конвертацию с
  новыми конфигурациями — структуры в базе КД для этого не нужны: недостающие объекты создаются при сопоставлении),
  пишет протокол (UTF-8: количество правил по справочникам, `ОШИБКА …`, `ИТОГ OK|ОШИБКА`, `КОНЕЦ`) и завершает
  сеанс. Без метки `kd2check` обработка ничего не делает.
- Внешнее соединение для самой загрузки не годится: модуль `ЗагрузкаКонвертации` целиком под `#Если Клиент Тогда`.
  OLE-автоматизация `V83.Application` на этой машине отключается при подключении.
- `kd_check.py prepare` (один раз для `base\`, через COM): стартовое обновление КД — иначе клиент останавливается на
  «Изменился номер версии конфигурации»; пользователь «Агент» с ролью `ПолныеПрава` без предупреждений об опасных
  действиях — иначе `/Execute` останавливается на «Предупреждении безопасности». Системный `conf.cfg` платформы не
  менялся.
- `kd_check.py check <файл>`: копия `base\` в `kdbase\run\…`, сборка EPF при изменении исходников, запуск, ожидание
  протокола (таймаут 300 с, затем клиент завершается), код выхода 0/1, копия удаляется.
- Режим совместимости КД — 8.2.13: в модуле обработки нет функций платформы 8.3 (первая версия падала на `СтрРазделить`).

Результат: макет `ПравилаОбмена` доработанного плана обмена БП ↔ ЗУП загружается без ошибок — 48 ПКО и 26 ПВД
(как в модели сервера); файл, обрезанный на 30 КБ, даёт в протоколе `ОШИБКА … Ошибка разбора XML` и `ИТОГ ОШИБКА`.
Около 7 с на прогон.

## 8.2. Пилот

Правила дорабатывала отдельная сессия Claude (`claude-sonnet-5`, `claude -p`) только инструментами
`kd-rules-mcp` — без исходников сервера, по описаниям инструментов. Постановка, отчёт агента и итоговый файл
в репозиторий не входят. 50 ходов, 5 мин, $1,28.

- Правила `ПравилаОбмена` доработанного плана обмена БП ↔ ЗУП, структуры `bp-full` (основная конфигурация
  + 5 расширений) и `zup-full` (вместо доработанной конфигурации ЗУП — настоящего приёмника, выгрузки которой нет).
- Агент выбрал `Справочник.Сотрудники` (в обеих структурах, ПКО в правилах нет, на него ссылаются ПКС других ПКО),
  создал ПКО по кандидатам: 20 ПКС, 5 выключено — 1 автоматически (свойство только приёмника), 4 решением агента
  (доп. реквизиты и наборы доступа БСП со ссылками без однозначного ПКО); ссылки `ФизическоеЛицо`,
  `ГоловнаяОрганизация`, `ГоловнойСотрудник` получили коды ПКО автоматически; флаги ПКО и `Поиск` у `Наименование`
  — по образцу соседних ПКО. Затем ПВД `Сотрудники` по образцу существующего.
- `rules_validate` до и после: те же 6 ошибок и 1 предупреждение (все — следствие подмены приёмника и дефекта
  алгоритма из 5.5), новых нет; `format_check` сохранённого файла чистый.
- База КД (8.1): `ИТОГ OK`, 49 ПКО и 27 ПВД (исходные 48 и 26 + новые).
- Песочница БП, штатная загрузка БСП: `kdbase/bsp_check.py` упаковывает правила и правила корреспондента в ZIP
  (так БСП принимает правила конвертации из файла) и вызывает `РегистрыСведений.ПравилаДляОбменаДанными.ЗагрузитьПравила`
  через внешнее соединение с записью в памяти — без `Записать`, регистр базы не меняется. Исходная пара и пилотный
  файл — `ИТОГ OK` (`ПравилаЗагружены`); испорченный файл — `ОШИБКА … Ошибка разбора XML`, код 1.

Замечания агента к серверу и что сделано:

1. `match_objects` без фильтра на двух типовых конфигурациях не влезал в лимит ответа клиента (124 тыс. символов при
   `limit=200`) — добавлен параметр `text`, строки кандидатов объектов стали компактными (`Вид.Имя` сторон и синоним).
2. Переполнение приходило не JSON-ошибкой сервера, а сообщением клиента Claude Code — лечится компактностью ответа (п. 1).
3. `skipped` у правок читался как ошибка — теперь «правка применена; проверка по структуре … не выполнена: структура
   не передана».
4. Флаг `Поиск` ПКС не был виден в списке ПКС `rules_get` для ПКО — добавлен `search`.
