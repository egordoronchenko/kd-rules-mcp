# MD83Exp: попадают ли расширения в выгрузку структуры (26.09.2026)

Вопрос: читает ли MD83Exp объекты и реквизиты расширений, если его запустить в базе с
подключёнными расширениями. В коде обработки расширения не упоминаются вовсе
(`reference\kd2-dist-src\MD83Exp\ВыгрузкаМетаданных\Ext\ObjectModule.bsl`, ни одного «Расширен»),
поэтому проверено сравнением двух реальных выгрузок.

## Исходные данные

- `structures\БП с расширениями.xml` — 970 МБ, песочница БП (БП КОРП с доработками) с пятью активными
  расширениями (шестое расширение отключено).
- `structures\БП без расширений.xml` — 951 МБ, та же база без расширений.

Сравнение по именам (GUID `Ref` случайные в каждом прогоне): объект = `Тип.Имя`,
свойство = `объект|родитель|Вид|Имя`, значение = `объект|Имя`.

## Результат

| | Без расширений | С расширениями | Только с расширениями | Только без |
|---|---|---|---|---|
| Объекты | 5 429 | 5 524 | 95 | 0 |
| Свойства | 186 973 | 188 485 | 1 512 | 0 |
| Значения | 17 873 | 17 963 | 90 | 0 |

Новые объекты: 28 справочников, 23 регистра сведений, 21 перечисление, 18 документов,
4 регистра накопления, 1 план обмена (имена — с префиксами своих расширений).
Новые реквизиты у типовых объектов тоже есть (например, `Документ.Доверенность`: `Руководитель`,
`ГлавныйБухгалтер`…), новые значения у типовых перечислений (например, `ВидыДополнительныхСтатейЗатрат`).

**Вывод: MD83Exp видит метаданные сеанса с применёнными расширениями.** Выгрузка из базы с
подключёнными расширениями — полноценный эталон для сборщика структуры из XML-выгрузок.

## Замечания для MCP

- Разбор 950 МБ потоковым `xml.etree.iterparse` с очисткой элементов — 47–58 с на файл.
  Приемлемо для разового импорта в кэш; держать файл в памяти целиком нельзя.
- 188 тыс. свойств не объясняют 950 МБ — основной объём, по всей видимости, в списках `Типы`
  составных типов (определяемые типы, «любая ссылка»). Типы в кэше стоит хранить наборами
  с дедупликацией. (вывод, не измерено)

Скрипт сравнения — одноразовый, в репозиторий не входит.
