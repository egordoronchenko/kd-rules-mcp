# Словарь

Термины «Конвертации данных», БСП и этого сервера — коротко, с тем, где термин живёт в XML правил (тег) и в
инструментах (раздел `rules_list`, вид `rule_create`). Инструменты — [tools.md](tools.md), проверки —
[checks.md](checks.md), устройство — [architecture.md](architecture.md).

## Платформа и продукты 1С

| Термин | Что это |
|---|---|
| **КД** | «Конвертация данных» — конфигурация 1С, в которой правила обмена составляют вручную. КД 2 (2.1.8.2) выгружает XML `ПравилаОбмена` 2.01. КД 3 пишет модуль менеджера обмена EnterpriseData; сервер предоставляет его чтение через `ed_*` |
| **БСП** | «Библиотека стандартных подсистем» — общая часть типовых конфигураций; её подсистема обмена данными читает и исполняет правила КД 2 (обработка `КонвертацияОбъектовИнформационныхБаз`). «Читатель БСП» — что из XML правил реально загружается, «исполнитель БСП» — как правило работает в обмене |
| **ИБ**, база | информационная база 1С. **Песочница** — база роли «песочница» в `projects.yaml`, где можно загружать правила и гонять обмен; **боевая** — рабочая база, агенту не подключается |
| **ИТС** | информационно-технологическое сопровождение 1С — откуда берётся поставка КД |
| **MD83Exp** | обработка «Выгрузка структуры метаданных» из поставки КД: пишет XML со всеми объектами и реквизитами конфигурации базы; второй вход сервера, когда исходников конфигурации нет (`structure_load_md83exp`) |
| **Расширение** | расширение конфигурации 1С; в структуру попадают только явно перечисленные в `projects.yaml` или в `structure_load_xml` |
| **ТЧ** | табличная часть объекта; в ПКС — группа свойств вида `ТабличнаяЧасть` |
| **РС** | регистр сведений; правила обмена базы хранятся в РС `ПравилаДляОбменаДанными` БСП |
| **БП, ЗУП, ДО** | типовые конфигурации «Бухгалтерия предприятия», «Зарплата и управление персоналом», «Документооборот» — в примерах как стороны обмена |
| **ИНН, КПП, ФНС** | реквизиты контрагента и налоговая служба — в примерах ключей поиска контрагентов |
| **BSL** | встроенный язык 1С; обработчики правил — фрагменты BSL |
| **COM** | внешнее соединение с базой 1С (`V83.COMConnector`); через него работает `bsp_check` |

## Обмен данными

| Термин | Что это |
|---|---|
| **План обмена** | объект метаданных, задающий участников обмена (узлы) и состав: какие объекты регистрируются к выгрузке. В правилах регистрации — тег `ПланОбмена` (`structure_plan_content` — состав) |
| **Узел** | элемент плана обмена — база-участник. «Этот узел» — своя база; изменения регистрируются на узле корреспондента |
| **Корреспондент** | вторая сторона обмена. «Правила корреспондента» — правила обмена в обратную сторону, которые база отдаёт другой стороне (`ПравилаОбменаКорреспондента` в макетах, `CorrespondentExchangeRules.xml` в комплекте); `correspondent_draft` строит их черновик |
| **Комплект правил** | то, что загружается в базу на БСП из файла: ZIP с `ExchangeRules.xml`, `CorrespondentExchangeRules.xml` и, если есть, `RegistrationRules.xml` (`rules_pack`) |
| **Макет** | правила, встроенные в конфигурацию: `ExchangePlans\<План>\Templates\…\Ext\Template.txt` в выгрузке. Сервер в макеты не пишет |
| **Живые правила** | правила, которые база загружает из файла, а не из макета; хранятся в репозитории проекта в папке `rules_dir`, сервер может писать туда напрямую |
| **Обработчик** | фрагмент кода BSL в правиле, выполняется на событии (`ПередВыгрузкой`, `ПриЗагрузке`, `ПослеЗагрузки` …). Выгрузочные пишутся против конфигурации-источника, загрузочные — против приёмника |

## Правила КД 2

| Термин | Тег XML | В инструментах | Что это |
|---|---|---|---|
| **Правила обмена** | `ПравилаОбмена` (`ВерсияФормата` 2.01) | вид проекта `exchange` | файл конвертации: заголовок (`Ид`, `Источник`, `Приемник`), события конвертации, параметры, обработки и разделы ниже |
| **ПКО** — правило конвертации объектов | `ПравилаКонвертацииОбъектов/Правило` | раздел `pko`, вид `pko` | как объект типа источника превращается в объект типа приёмника; содержит ПКС, ПКЗ, варианты поиска и обработчики |
| **ПКС** — правило конвертации свойств | `Свойства/Свойство` внутри ПКО | вид `pks`, адрес — путь `группа/…/свойство-приёмник`; при совпадении имён в контейнере к звену добавляются `[поиск]` и `#N` | как реквизит источника переносится в реквизит приёмника; флаг `Поиск` делает его ключом поиска |
| **ПКГС** — правило конвертации группы свойств | `Свойства/Группа` | вид `pks_group` | группа ПКС для табличной части или набора записей |
| **ПКЗ** — правило конвертации значений | `Значения/Значение` внутри ПКО | вид `pkz`, адрес — значение источника | соответствие значений перечислений и предопределённых элементов |
| **ПВД** — правило выгрузки данных | `ПравилаВыгрузкиДанных/Правило` | раздел `pvd`, вид `pvd` | какие объекты выбираются к выгрузке и каким ПКО конвертируются; без включённого ПВД объект сам не выгружается |
| **ПОД** — правило очистки данных | `ПравилаОчисткиДанных/Правило` | раздел `pod`, вид `pod` | удаление объектов в приёмнике при загрузке |
| **Алгоритм** | `Алгоритмы/Алгоритм` | раздел `algorithms`, вид `algorithm` | общий код, который обработчики вызывают как `Алгоритмы.Имя`; флаг `ИспользуетсяПриЗагрузке` — режим |
| **Запрос**, **параметр**, **обработка** | `Запросы/Запрос`, `Параметры/Параметр`, `Обработки/Обработка` | разделы `queries`, `parameters` | тексты запросов, параметры конвертации, внешние обработки внутри правил |
| **Поиск** (поля и варианты) | атрибут `Поиск` у ПКС, `НастройкаВариантовПоискаОбъектов`, обработчик `ПоследовательностьПолейПоиска` | проверки `search.*` | как приёмник находит существующий объект; ошибки тут дают дубли |
| **Правила регистрации** | `ПравилаРегистрации` | вид проекта `registration`, раздел `registration` | какие изменения объектов регистрируются на узлах плана обмена |
| **ПРО** — правило регистрации объекта | `ПравилаРегистрацииОбъектов/Правило` | вид `pro` | регистрация одного объекта с отборами по свойствам плана обмена и объекта (`registration_build`) |
| **Состав плана обмена** | `СоставПланаОбмена` | `structure_plan_content` | объекты плана с признаком авторегистрации; в правилах регистрации пишется, но читателем БСП пропускается |
| **Адрес правила** | — | `key` и `owner` у `rules_get`, `rule_*`; `address` в ответах | как сервер называет правило: `ПКО «Код»`, `ПКО «Код» / ПКС путь`, `ПКО «Код» / ПКЗ значение`, `алгоритм «Имя»` |

## EnterpriseData и КД 3

| Термин | Что это |
|---|---|
| **EnterpriseData (ED)** | универсальный формат обмена данными; стороны правил называются `configuration` (конфигурация) и `format` (формат), независимо от направления обмена |
| **Менеджер обмена** | модуль BSL с точками заполнения правил, обработчиками и алгоритмами; сервер читает структуру модуля, не выполняет его. Версия интерфейса менеджера отличается от упоминаний версии формата данных |
| **ПКТЧ** | правило конвертации табличной части: группа ПКС внутри ПКО; её ПКС запрашиваются отдельно. Форма: `reference/kd3-cfg/DataProcessors/ВыгрузкаМодуля/Templates/ШаблоныТекстовМодулей/Ext/Template.txt:190` |
| **ПКПД** | правило конвертации предопределённых данных, с парами значений для отправки и получения. Форма: `reference/kd3-cfg/DataProcessors/ВыгрузкаМодуля/Templates/ШаблоныТекстовМодулей/Ext/Template.txt:99` |
| **ПОД в КД 3** | правило обработки данных: выборка, обработчик, используемые ПКО; отличается от правила очистки данных КД 2. Форма: `reference/kd3-cfg/DataProcessors/ВыгрузкаМодуля/Templates/ШаблоныТекстовМодулей/Ext/Template.txt:19` |
| **Непрозрачный код** (`opaque_code`) | тело принятого обработчика, алгоритма или служебной процедуры; границы распознаны, понимание семантики BSL не заявляется |
| **Неизвестный фрагмент** (`unknown`) | корректно ограниченный фрагмент вне принятого структурного подмножества; доступен по адресу и исходному тексту, делает разбор `partial` |

## Сервер kd2-rules-mcp

| Термин | Что это |
|---|---|
| **MCP** | Model Context Protocol — протокол, по которому агент вызывает инструменты сервера (streamable HTTP, `/mcp`) |
| **Структура** | метаданные одной конфигурации (объекты, свойства с типами, значения) в кэше сервера под идентификатором (`structure_id`, например `<проект>-full`); собирается из XML-выгрузки конфигурации с расширениями или из MD83Exp |
| **Проект** (1С) | запись в `projects.yaml`: конфигурации, базы, серверы кода, обмены; папка на машине — в `projects.local.yaml` (`project_list`) |
| **Кандидат** | предложенная сервером пара объектов, свойств или значений двух структур (`match_*`) с классом уверенности и признаком `auto` |
| **Класс уверенности** | «точно» (имя и вид совпадают), «синоним КД» (`Номер↔НомерДок`, `Дата↔ДатаДок`), «по синониму» (совпадает синоним, имена разные — только подсказка), «нет пары» |
| **Рабочий проект правил** | правила, открытые на сервере (`rules_open`, `rules_create`, `registration_build`, `correspondent_draft`) и изменяемые инструментами; снимок в рабочей папке переживает перезапуск, закрывает проект `rules_close` ([workflow.md](workflow.md)) |
| **Рабочая папка** | `workspace\` репозитория сервера — куда сервер пишет правила, обёртки и архивы, кроме `rules_dir` |
| **`rules_dir`** | папка живых правил проекта в его репозитории; сервер может в неё писать |
| **Обёртка обработчика** | `.bsl`-файл с процедурой обработчика и объявленными переменными его события для синтакс-чекера (`handlers_export`); строка ошибки переводится в правило через `handlers_locate` |
| **Каноническая форма** | приведённый XML правил для смыслового сравнения (правила К1–К8): порядок атрибутов, концы строк и значения по умолчанию не важны. На ней держится проверка **round-trip** — чтение и запись правил без потери смысла |
| **Лестница проверок** | `rules_validate` → синтакс-чекер → `kd_check` → `bsp_check` → `exchange_check`: каждая доказывает то, чего не может предыдущая; скрипты `kdbase` печатают итог `ИТОГ OK` или `ИТОГ ОШИБКА` и `КОНЕЦ` ([checks.md](checks.md)) |
| **Сервер кода**, **сервер данных** | серверы MCP для 1С из `.mcp.json` проекта: поиск по коду и метаданным конфигурации (`code_mcp`) и выполнение кода и запросов в базе-песочнице (`data_mcp`, нужен `exchange_check`) |
| **Синтакс-чекер** | внешний сервер MCP, проверяющий синтаксис BSL; вызывает агент по файлам `handlers_export` |

Прочие сокращения: XML, ZIP, JSON, HTTP — форматы и протокол; UI — интерфейс пользователя (MCP QA — сервер
UI-тестирования форм 1С); WSL — подсистема Linux в Windows; API — программный интерфейс.
