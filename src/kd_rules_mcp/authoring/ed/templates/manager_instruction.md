# Собственный модуль правил обмена: ${extension_name}

## Что это

Расширение конфигурации с одним общим модулем `${module_name}`. В модуле лежат правила обмена через
универсальный формат (EnterpriseData) для версии формата `${version_key}`. После установки база при обмене по
плану `${plan_name}` с этой версией формата берёт правила из этого модуля, а не из типового.

Прочитайте до установки:

- Подмена действует на **всех** узлах плана с версией формата `${version_key}` и заменяет **все** типовые
  правила этой версии, а не дополняет их. Объекты, для которых в новом модуле правил нет, по этим узлам ходить
  перестанут.
- Версия формата сравнивается буква в букву: `1.20.0` и `1.20` — разные версии.
- Комплект собран для одной базы. Для базы на другой стороне обмена нужен свой комплект — его собирают так же,
  по её конфигурации.
- Если в базе уже стоит расширение, которое дорабатывает типовой модуль правил (обработчики, добавленные
  свойства) для этой же версии формата, после установки оно перестаёт действовать для этой версии: правила двух
  модулей не объединяются.
- Основная конфигурация не меняется. Расширение не создаёт план обмена, узлы, расписание, роли и не настраивает
  регистрацию изменений.

Сборка `${build_hash}`, версия расширения `${extension_version}`. Режим совместимости расширения —
`${compatibility_mode}`, режим совместимости интерфейса — `${interface_compatibility_mode}`: они взяты из
выгрузки конфигурации, для которой собран комплект. Если у базы они другие, проверка применимости на шаге 2 не
пройдёт — значит, комплект собран не для этой конфигурации.

Код из этой инструкции выполняют в базе от имени администратора: в «Консоли кода» или в любой обработке, где
можно выполнить произвольный код на сервере.

## Шаг 1. Посмотрите, что изменится

Сделайте резервную копию и сначала попробуйте на копии базы. Затем выполните в базе:

```bsl
ИмяПлана = "${plan_name}";
Для Каждого Расширение Из РасширенияКонфигурации.Получить() Цикл
	Сообщить("Расширение " + Расширение.Имя + ": активно " + Расширение.Активно
		+ ", безопасный режим " + Расширение.БезопасныйРежим);
КонецЦикла;
ЭтотУзел = ПланыОбмена[ИмяПлана].ЭтотУзел();
Выборка = ПланыОбмена[ИмяПлана].Выбрать();
Пока Выборка.Следующий() Цикл
	Если Выборка.Ссылка <> ЭтотУзел Тогда
		Сообщить("Узел " + Выборка.Код + " «" + Выборка.Наименование + "»: версия формата "
			+ Выборка.ВерсияФорматаОбмена);
	КонецЕсли;
КонецЦикла;
```

Что проверить по выводу:

1. **Узлы.** Каждый узел с версией формата `${version_key}` перейдёт на новый модуль. Если среди них есть узел,
   которому нужны типовые правила, расширение ставить нельзя.
2. **Другие расширения.** Для каждого активного расширения откройте в конфигураторе модуль менеджера плана
   обмена `${plan_name}` (если расширение его содержит) и поищите `ПриПолученииНастроек`. Если другое расширение
   тоже подставляет свой модуль для версии `${version_key}`, сработает то, которое применяется последним, —
   оставьте одно.

## Шаг 2. Установите расширение

Замените в командах `<строка соединения>` и `<каталог комплекта>` (папка, где лежит этот файл). Каждая команда
пишет журнал в файл `.log` и результат в файл `.result` рядом с комплектом: в `.result` должен быть `0`. Если
там другое число — остановитесь и прочитайте журнал.

**Способ А — конфигуратором целевой базы** (нужен монопольный доступ на время обновления):

```text
${command_load_extension}
${command_check_extension}
${command_check_modules}
${command_update_extension}
```

То же можно сделать вручную: в конфигураторе «Конфигурация → Расширения конфигурации», добавить расширение
`${extension_name}`, «Конфигурация → Загрузить конфигурацию из файлов» для папки `extension`, затем проверить
применимость и обновить конфигурацию базы данных.

**Способ Б — без конфигуратора целевой базы.** Сначала соберите файл расширения в пустой базе:

```text
${command_create_infobase}
${command_load_build_extension}
${command_dump_extension}
```

Затем выполните в целевой базе (путь к файлу должен быть виден серверу 1С):

```bsl
Данные = Новый ДвоичныеДанные("<путь к файлу>/${extension_name}.cfe");
Имя = "${extension_name}";
Найденные = РасширенияКонфигурации.Получить(Новый Структура("Имя", Имя));
Если Найденные.Количество() = 0 Тогда
	Расширение = РасширенияКонфигурации.Создать();
Иначе
	Расширение = Найденные[0];
КонецЕсли;
Проблемы = Расширение.ПроверитьВозможностьПрименения(Данные, Истина);
Для Каждого Проблема Из Проблемы Цикл
	Сообщить(Проблема.Описание);
КонецЦикла;
Если Проблемы.Количество() = 0 Тогда
	Расширение.Записать(Данные);
	Сообщить("Расширение записано");
КонецЕсли;
```

Если код вывел проблемы применимости, расширение не записано — разберитесь с ними, прежде чем продолжать.
При обновлении код проверяет и записывает данные поверх найденного расширения с тем же именем,
сохраняя его идентификатор; новое расширение создаётся только при отсутствии установленного.

## Шаг 3. Снимите безопасный режим расширения

В безопасном режиме подмена модуля **молча не работает**: ошибки нет, база продолжает брать типовые правила.

```bsl
Найденные = РасширенияКонфигурации.Получить(Новый Структура("Имя", "${extension_name}"));
Расширение = Найденные[0];
Защита = Новый ОписаниеЗащитыОтОпасныхДействий;
Защита.ПредупреждатьОбОпасныхДействиях = Ложь;
Расширение.ЗащитаОтОпасныхДействий = Защита;
Расширение.БезопасныйРежим = Ложь;
Расширение.Записать();
```

Решение снять безопасный режим принимает администратор базы: код расширения после этого работает с правами
основной конфигурации.

## Шаг 4. Начните новые сеансы

Настройки плана обмена база запоминает на время сеанса. Пока сеанс не перезапущен, он продолжает работать по
типовым правилам. Перезайдите в базу; фоновые задания обмена подхватят изменение при следующем запуске.

## Шаг 5. Проверьте, что база берёт правила из нового модуля

Версия установленного расширения:

${version_probe}

Выбор модуля и число правил (в новом сеансе):

```bsl
ИмяПлана = "${plan_name}";
НашМодуль = ОбщегоНазначения.ОбщийМодуль(${module_name_literal});
Узел = Неопределено;
ЭтотУзел = ПланыОбмена[ИмяПлана].ЭтотУзел();
Выборка = ПланыОбмена[ИмяПлана].Выбрать();
Пока Выборка.Следующий() Цикл
	Если Выборка.Ссылка = ЭтотУзел Или Выборка.ВерсияФорматаОбмена <> ${version_literal} Тогда
		Продолжить;
	КонецЕсли;
	Узел = Выборка.Ссылка;
	Менеджер = ОбменДаннымиXDTOСервер.МенеджерОбменаВерсииФормата(${version_literal}, Узел);
	Сообщить("Узел " + Выборка.Код + ": новый модуль выбран — " + (Менеджер = НашМодуль));
КонецЦикла;
Если Узел <> Неопределено Тогда
	Для Каждого Направление Из СтрРазделить("Отправка,Получение", ",") Цикл
		Компоненты = ОбменДаннымиXDTOСервер.ИнициализироватьКомпонентыОбмена(Направление);
		Компоненты.ВерсияФорматаОбмена = ${version_literal};
		Компоненты.МенеджерОбмена = НашМодуль;
		Компоненты.УзелКорреспондента = Узел;
		Компоненты.XMLСхема = ОбменДаннымиXDTOСервер.ФорматОбмена(ИмяПлана, ${version_literal});
		ОбменДаннымиXDTOСервер.ИнициализироватьТаблицыПравилОбмена(Компоненты);
		ЧислоПКС = 0;
		Для Каждого ПКО Из Компоненты.ПравилаКонвертацииОбъектов Цикл
			ЧислоПКС = ЧислоПКС + ПКО.Свойства.Количество();
			Для Каждого ПКТЧ Из ПКО.СвойстваТабличныхЧастей Цикл
				ЧислоПКС = ЧислоПКС + ПКТЧ.Свойства.Количество();
			КонецЦикла;
		КонецЦикла;
		Сообщить(Направление + ": ПКО " + Компоненты.ПравилаКонвертацииОбъектов.Количество()
			+ ", ПОД " + Компоненты.ПравилаОбработкиДанных.Количество() + ", ПКС " + ЧислоПКС);
	КонецЦикла;
КонецЕсли;
```

Что должно получиться:

- для каждого узла — «новый модуль выбран — Да». Если «Нет»: проверьте шаги 3 и 4 и порядок расширений из
  шага 1;
- числа правил — как в таблице (ПКО — правила конвертации объектов, ПОД — правила обработки данных, ПКС —
  правила конвертации свойств):

${counts_table}

${names_table}

Число ПКС сравнивайте с последним столбцом: при инициализации к каждому правилу отправки добавляется свойство
«Ссылка», которого в модуле нет. Код и таблица считают ПКС шапки и всех описанных табличных частей,
а после инициализации — также служебную «Ссылка» у каждого ПКО отправки.
Если узлов с версией `${version_key}` нет, код ничего не выведет — проверять
пока не на чем.

Проверка модулей конфигуратором (шаг 2) не замечает, что в модуле не хватает обязательной процедуры или что для
объекта нет правила обработки данных, — это видно только этой пробой и первым обменом.

## Шаг 6. Первый обмен

1. Сначала выполните отправку **из базы, которая должна начать получать новые объекты**. В заголовке её
   сообщения написано, какие объекты она теперь умеет принимать; пока другая сторона не получит такое сообщение,
   она эти объекты не выгрузит.
2. Затем выполните обмен с другой стороны и проверьте на одном-двух объектах: создание, изменение, повторный
   обмен без дублей, поиск уже существующего объекта.
3. Сохраните файлы сообщений и записи журнала регистрации — по ним разбирают расхождения.

Чтобы объект попал в сообщение, он должен быть зарегистрирован к выгрузке на узле. Расширение регистрацию не
настраивает: работают правила регистрации, которые уже есть в базе, либо объект регистрируют вручную.

## Если переносите руками или через хранилище

Готовое расширение ставить не обязательно: то же самое можно перенести в своё расширение или в свою
конфигурацию. Переносить нужно **две вещи**, а не одну:

1. **Общий модуль с правилами.** Текст — в файле `extension/CommonModules/${module_name}/Ext/Module.bsl`.
   Создайте у себя общий модуль с тем же именем `${module_name}` и вставьте текст целиком. Флажки модуля:
   «Сервер», «Внешнее соединение», «Клиент (обычное приложение)»; «Вызов сервера» и «Глобальный» — сняты.
2. **Строку, которая подключает модуль к версии формата.** Без неё модуль лежит в базе, но обмен по-прежнему
   идёт по типовым правилам. Текст — в файле `extension/ExchangePlans/${plan_name}/Ext/ManagerModule.bsl`: это
   дополнение процедуры `ПриПолученииНастроек` модуля менеджера плана обмена `${plan_name}`, одна вставка в
   `Настройки.ВерсииФорматаОбмена`. В своём расширении перенесите процедуру как есть; в своей конфигурации —
   добавьте эту вставку в конец той же процедуры.

После переноса выполните шаги 4–6 этой инструкции: проверка на шаге 5 одинакова для любого способа установки и
покажет, подхватила ли база ваш модуль. Имя модуля не меняйте — на него ссылается строка подключения.

Не проверяется сервером: код обработчиков (он не исполнялся), права пользователей, регистрация объектов,

## Обновление комплекта

Новую сборку ставят теми же шагами поверх прежней. Версия расширения у неё другая — по шагу 5 видно, какая
сборка стоит в базе. Повторная загрузка безопасный режим обратно не включает, но шаг 5 всё равно выполните.

Файлы комплекта руками не правьте: сервер сверяет их с описью и откажется собирать следующую сборку поверх
изменённых. Изменения вносят в модель правил на сервере.

## Как вернуть типовые правила

Отключите расширение (снимите «Активно») или удалите его и начните новые сеансы — версия формата
`${version_key}` снова ведёт на типовой модуль. Данные при этом не удаляются. Другая сторона узнает об изменении
состава принимаемых объектов из следующего сообщения. Чтобы вернуть прежнюю сборку, установите её из
сохранённой папки прежнего комплекта.
