## Установка готовой выгрузки

1. Откройте именно окно расширений конфигурации, создайте/выберите ${extension_name}.
2. Загрузите файлы из `${extension_folder}` **в расширение**. Не загружайте их в основную конфигурацию.
3. Выполните проверку применимости расширения; при ошибке остановитесь и сохраните её текст.
4. Проверьте модули серверного и внешнего соединения; обновите конфигурацию базы данных расширения.
5. Проверьте активность и область действия. Снимите безопасный режим **этого расширения**:
   загрузка из файлов создаёт его в безопасном режиме, и перехватчик тогда молча не действует.
   Решение принимает администратор; не отключайте защиту всех расширений или всего сервера.
   При записи этого свойства из кода также требуется отключить предупреждение защиты от опасных
   действий для этого объекта расширения: `ЗащитаОтОпасныхДействий.ПредупреждатьОбОпасныхДействиях = Ложь`.
   Без этого запись свойства не происходит. Применимость/компиляция не доказывают работу перехватчика.
6. Начните новый сеанс и проверьте фактический состав ПКС по разделу «Проверка в базе».

### Пакетный конфигуратор

Запускайте из каталога комплекта; `<строка соединения>` подставляется администратором.
Учётные данные в комплект не входят. При ошибке любой команды остановитесь и сохраните её журнал.

```text
1cv8 DESIGNER /IBConnectionString "<строка соединения>" /LoadConfigFromFiles "extension" -Extension "${extension_name}" -Format Hierarchical
1cv8 DESIGNER /IBConnectionString "<строка соединения>" /CheckCanApplyConfigurationExtensions -Extension "${extension_name}"
1cv8 DESIGNER /IBConnectionString "<строка соединения>" /CheckModules -Server -ExternalConnection -Extension "${extension_name}"
1cv8 DESIGNER /IBConnectionString "<строка соединения>" /UpdateDBCfg -Extension "${extension_name}"
```

После команд выполните шаги 5–6: безопасный режим автоматически не снимается.

## Проверка в базе

Не запускайте код в рабочей базе как часть статической проверки. В согласованной песочнице:
${runtime_probes}
Ожидаемый результат: для каждой операции найдены один ПКО и ровно одна нужная ПКС с указанной парой
«свойство конфигурации ↔ свойство формата». Проверьте оба направления, включая случай отсутствия
целевого ПКО: по всей таблице противоположного направления ищется тот же реквизит.
Сравните с результатом до установки; при явных операциях на обоих направлениях проверьте каждое.
Если найдена ПКС чужого реквизита на том же свойстве формата, этот перехватчик не добавит свою.
${header_pass_note}

Для живого теста нужны две стороны, соответствующие версии и узлы-корреспонденты.
Код корреспондента должен совпадать с кодом «этого узла» другой базы.
Создание/запись узла может менять настройки использования обмена: снимите значения до изменения.
Проверьте заполненное значение, новое сообщение с тем же объектом и изменение значения.
Повтор буквально того же сообщения не проверяет обновление объекта: БСП может его отклонить как принятое ранее.
Убедитесь, что значение присутствует в XML и у того же объекта получателя, дубликата нет.
${empty_value_probe}
Проверьте ограничения длины/типа.

## Обновление и возврат

Для дополнения или пересборки сохраните каталог комплекта с manifest и передайте новые решения.
После обновления типовой конфигурации перечитайте снимки и маршруты, выполните preview: все прежние
и новые операции проверяются заново, UUID сохранённых объектов расширения остаются прежними.
Если прежняя операция больше невозможна, явно исключите её ID через drop_operations и повторите preview.
Для write используйте новый build_hash и подтвердите все замечания текущего preview.
После ручной правки файлов автоматическая пересборка запрещена. Проверьте результат в новом сеансе.
Удаление расширения с новым реквизитом удаляет его данные: сначала сохраните нужные данные.
Автоматического отката узлов, объектов и глобальных настроек этот комплект не выполняет.
