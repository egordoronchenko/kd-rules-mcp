# Перенос правил регистрации

## Перенос неполон

- ПРО «Справочник.TestObjects», лист ОтборПоСвойствамПланаОбмена/0: реквизит узла «reg_Flag» не найден у плана обмена «TargetPlan»; реквизит будет добавлен расширением

Проверьте замечания до загрузки правил.

План обмена: `TargetPlan`. Расширение: `reg_Registration`.
Режимы совместимости взяты из выгрузки конфигурации: `Version8_3_24`, интерфейс `TaxiEnableVersion8_2`.

## Что это

Правила регистрации решают, какие изменённые объекты попадут в очередь на отправку и на какие узлы. В комплекте —
правила регистрации из прежнего обмена, переписанные под план `TargetPlan`, и расширение, которое добавляет
узлу плана недостающие реквизиты. Порядок важен: сначала расширение, потом настройки узлов, потом файл правил.

Прочитайте до установки:

- Файл заменяет правила регистрации **всего плана**, а не одного узла. Если по этому плану идут другие обмены,
  сначала убедитесь, что новые правила подходят и им.
- Основная конфигурация не меняется.
- Комплект собран для одной базы. Для базы на другой стороне обмена собирают свой комплект.

## 1. Сохраните текущее состояние

Сделайте резервную копию базы. Откройте регистр сведений `ПравилаДляОбменаДанными`, найдите правила
регистрации объектов этого плана и запишите себе:

- откуда они берутся сейчас — из файла, из макета конфигурации или из менеджера регистрации;
- имя макета или менеджера;
- если из файла — сохраните сам файл.

Сохраните настройки каждого узла плана (снимок экрана формы подойдёт). Остановите задания обмена на время
установки.

## 2. Установите расширение

В конфигураторе: «Конфигурация → Расширения конфигурации», добавьте расширение `reg_Registration` и загрузите
его конфигурацию из файлов папки `extension`. Проверьте применимость, обновите конфигурацию базы данных и
начните новые сеансы. Расширение добавляет узлу плана реквизиты:

| Реквизит | Тип | Подпись |
| --- | --- | --- |
| reg_Flag | Булево | Не выгружать персональные данные |

То же пакетными командами (подставьте свои пути; `1cv8` — исполняемый файл платформы):

```text
1cv8 DESIGNER /F "<каталог файловой базы>" /LoadConfigFromFiles "<каталог комплекта>/extension" -Format Hierarchical -Extension "reg_Registration" /DisableStartupDialogs /Out "<каталог комплекта>/load.log" /DumpResult "<каталог комплекта>/load.result"
1cv8 DESIGNER /F "<каталог файловой базы>" /CheckConfig -Extension "reg_Registration" /DisableStartupDialogs /Out "<каталог комплекта>/check.log" /DumpResult "<каталог комплекта>/check.result"
1cv8 DESIGNER /F "<каталог файловой базы>" /CheckCanApplyConfigurationExtensions -Extension "reg_Registration" /DisableStartupDialogs /Out "<каталог комплекта>/apply.log" /DumpResult "<каталог комплекта>/apply.result"
1cv8 DESIGNER /F "<каталог файловой базы>" /UpdateDBCfg -Extension "reg_Registration" /DisableStartupDialogs /Out "<каталог комплекта>/update.log" /DumpResult "<каталог комплекта>/update.result"
```

После каждой команды код завершения и число в файле `.result` должны быть `0`. Если нет — остановитесь и
прочитайте журнал.

**Расширение ставят до загрузки правил.** Иначе правила будут обращаться к реквизиту, которого в базе ещё нет,
и запись объектов начнёт падать с ошибкой.

## 3. Перенесите настройки узлов

Для каждого узла нового плана возьмите значения из соответствующего узла прежнего обмена:

| Старый реквизит | Новый реквизит или настройка | Как перенести |
| --- | --- | --- |
| OldFlag | reg_Flag | Перенести значение старого узла |

Реквизит, который добавило расширение, на типовой форме узла не виден — заполните его кодом на сервере
(подставьте код узла, имя реквизита и значение из старого узла):

```bsl
Узел = ПланыОбмена.TargetPlan.НайтиПоКоду("<код нового узла>");
Если Узел.Пустая() Тогда
    ВызватьИсключение "Узел не найден";
КонецЕсли;
ОбъектУзла = Узел.ПолучитьОбъект();
ОбъектУзла["<имя нового булевого реквизита>"] = Ложь; // Значение из старого узла.
ОбъектУзла.Записать();
```

**Дату начала и отбор по организациям переносите выбором настроек «правила отправки», а не записью полей.**
Модуль узла при каждой записи сам пересчитывает эти поля по настройкам отправки, и значение, записанное
напрямую, сотрёт:

- Дата начала. В настройках узла для документов выберите автоматическую синхронизацию
  (`ПравилаОтправкиДокументов = АвтоматическаяСинхронизация`) и задайте дату в форме настройки отправки. При
  любом другом режиме дата `ДатаНачалаВыгрузкиДокументов` очищается.
- Организации. Для справочников выберите режим отправки, отличный от «не синхронизировать»
  (`ПравилаОтправкиСправочников`), включите ограничение по организациям и заполните список в той же форме.
  Пустой список в некоторых конфигурациях снимает ограничение.

После записи откройте настройку узла ещё раз и проверьте, что дата и организации остались.

## 4. Загрузите файл правил регистрации

В форме правил регистрации объектов этого плана (`ПравилаДляОбменаДанными → ПравилаРегистрацииОбъектов`)
выберите источник **Файл**, укажите `registration/RegistrationRules.xml` и запишите. Нужны права администратора
обмена. Форма сама сбрасывает кэш регистрации.

Если формой воспользоваться нельзя — то же кодом на сервере:

```bsl
ИмяПланаОбмена = "TargetPlan";
ИмяФайлаПравил = "<полный путь, доступный серверу 1С>/registration/RegistrationRules.xml";
ОбменДаннымиСервер.ЗагрузитьПоставляемыеПравилаРегистрацииОбъектов(
    ИмяПланаОбмена, ИмяФайлаПравил);
ОбменДаннымиСлужебный.СброситьКэшМеханизмаРегистрацииОбъектов();
ОбновитьПовторноИспользуемыеЗначения();
```

Код делает меньше проверок, чем форма, поэтому после него откройте запись правил в форме и убедитесь, что
источник — файл и правила загружены. Файл сохраняется в базе: путь к нему после загрузки больше не нужен.
Процедуры взяты из БСП 3.1.12 (`ОбменДаннымиСервер`, строки 1449–1455; `ОбменДаннымиСлужебный`, строки
138–151); после обновления конфигурации проверьте, что они на месте.

**Предупреждение: после загрузки файла настройки узла «что отправлять» перестают управлять регистрацией —
регистрацией управляют правила из файла.** Так устроен перенос «как было в прежнем обмене»: что регистрировать,
решают перенесённые правила. Настройки отправки по-прежнему определяют дату начала и список организаций
(шаг 3). Правила, отключённые в прежнем обмене, остаются отключёнными.

## 5. Проверьте обычной записью объекта

1. Начните новый сеанс.
2. Откройте объект, который должен отправляться (подходит под дату и организацию узла), измените его и
   обычно запишите. Проверьте, что он появился в очереди нужного узла.
3. Сделайте то же с объектом, который отправляться не должен (другая организация или дата раньше начала).
   В очереди его быть не должно.

Проверяйте именно обычной записью: команда «Зарегистрировать изменения» ставит объект в очередь без проверки
правил. Первый обмен и начальную выгрузку проверяют отдельно, после этого шага.

## Как вернуть прежнее состояние

Если до установки правила брались из файла — загрузите сохранённый файл тем же способом (шаг 4) и верните
настройки узлов. Если из типовой поставки — выберите свой вариант:

- **Из макета:** в форме выберите источник `МакетКонфигурации` и прежний макет (обычно `ПравилаРегистрации`),
  загрузите и запишите. То же делает код
  `ОбменДаннымиСервер.УдалитьПоставляемыеПравилаРегистрацииОбъектов("TargetPlan");` — он возвращает источник
  к макету.
- **Из менеджера регистрации:** в форме выберите `МенеджерТиповой`, проверьте имя менеджера по своей записи из
  шага 1, загрузите и запишите. Команда «Использовать типовые правила» и код из предыдущего пункта сюда не
  подходят: они всегда выбирают макет.

После возврата сбросьте кэш и проверьте обычную запись объекта в новом сеансе:

```bsl
ОбменДаннымиСлужебный.СброситьКэшМеханизмаРегистрацииОбъектов();
ОбновитьПовторноИспользуемыеЗначения();
```

Расширение отключайте только после того, как загружены правила, которые на его реквизиты не ссылаются; значения
этих реквизитов перед отключением сохраните. Возврат правил не отменяет уже накопленную очередь и отправленные
сообщения.

## Что входит в комплект

`registration/RegistrationRules.xml` — правила регистрации; `extension` — исходники расширения (заимствованный
план обмена и добавленные реквизиты узла; состав плана, подписки и модули расширение не меняет);
`manifest.json` — опись входов и файлов комплекта.

Что проверено: расширение такого вида загружается платформой 8.3.27 и выгружается обратно без расхождений.
**Этот комплект в базу не ставился**: регистрацию и обмен проверяет шаг 5 в вашей тестовой базе.
