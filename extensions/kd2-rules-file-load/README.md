# Расширение «Загрузка правил КД 2 из файла» (`kd2-rules-file-load`)

В БСП 3.1.12 и новее (БП 3.0.207, ЗУП 3.1.38 и новее) формы регистра `ПравилаДляОбменаДанными` больше не дают
выбрать файл правил «Конвертации данных 2». Переключатель «Из файла на компьютере» недоступен, процедура
`ОбменДаннымиКлиент.ВыбратьИПередатьФайлНаСервер` удалена. Сама загрузка в типовой форме «Загрузить правила
синхронизации» осталась: `ПередЗагрузкойПравил` → `ВыполнитьЗагрузкуПравил` → `ЗагрузитьКомплектПравил` менеджера
регистра с проверкой совместимости, запись, сброс кэша регистрации. Расширение возвращает к ней вход.

**Как поставить и пользоваться** — [docs/INSTALL.md, «Загрузка правил КД 2 в базу на БСП 3.1.12 и новее»](../../docs/INSTALL.md#загрузка-правил-кд-2-в-базу-на-бсп-3112-и-новее).
Готовый `.cfe` — во вложении к [релизу](https://github.com/egordoronchenko/kd-rules-mcp/releases/latest/download/kd2-rules-file-load.cfe).

## Что внутри

| | |
|---|---|
| Имя, префикс | `кд2_ЗагрузкаПравилИзФайла`, `кд2_`; назначение — дополнение |
| Заимствовано | язык `Русский`, регистр `ПравилаДляОбменаДанными` и его форма `ЗагрузитьПравилаСинхронизацииДанных` — больше ничего |
| Форма | после `ПриСозданииНаСервере` включает переключатель `ИсточникПравилИзФайла`; кнопка «Загрузить комплект из файла...» выбирает ZIP (`ФайловаяСистемаКлиент.ЗагрузитьФайл`), проверяет расширение `.zip`, ставит `ИсточникПравил = "ЗагруженныеИзФайла"` и вызывает `ПередЗагрузкойПравил` формы |
| Сопоставление | по именам (`KeepMappingToExtendedConfigurationObjectsByIDs = false`, без `ExtendedConfigurationObject`). UUID языка у БП, ЗУП и ERP разные, поэтому при сопоставлении по UUID один `.cfe` к другой конфигурации не применится |
| Режим совместимости | 8.3.24: БСП 3.1.12 поддерживает конфигурации с режимом от 8.3.24, а режим расширения не должен быть выше режима конфигурации. Коду расширения новее ничего не нужно |
| Безопасный режим | можно оставить: серверная часть загрузки — код типовой формы |

Ограничения: только полный комплект из трёх файлов (`ExchangeRules.xml`, `CorrespondentExchangeRules.xml`,
`RegistrationRules.xml`), только эта форма. Расширение опирается на неэкспортные процедуры типовой формы — после
обновления БСП проверьте кнопку.

## Сборка `.cfe`

Исходники — `src/` (XML-выгрузка конфигуратора, формат `Hierarchical`, версия 2.20 — платформа 8.3.27+).
Нужна файловая база с конфигурацией на БСП 3.1.12+ — подойдёт пустая, созданная из `.cf` нужной конфигурации.
Исходная база не меняется: скрипт работает на её копии.

```powershell
uv run python kdbase/extension_build.py build --base <каталог файловой базы>
```

Скрипт загружает расширение из `src/`, проверяет применимость (`/CheckCanApplyConfigurationExtensions`),
выгружает обратно и сверяет с исходниками, сохраняет `kdbase/build/kd2-rules-file-load.cfe` и паспорт
`kd2-rules-file-load.cfe.json` (версия, отпечатки исходников и файла). `.cfe` в git не хранится.

- Тот же `.cfe` на другой конфигурации: `uv run python kdbase/extension_build.py check --base <другая база>`.
- Сборка соответствует исходникам: `uv run python kdbase/extension_build.py verify`.
- Правили расширение в конфигураторе — выгрузите в каноническую форму: `build … --dump-to <каталог>` и
  перенесите файлы в `src/` (без `ConfigDumpInfo.xml`).
- Новая версия — поднять `<Version>` в `src/Configuration.xml`.

Пользователь базы — `--user`, пароль — переменная `KD2_IB_PASSWORD`; платформа — `--platform`, `KD2_1CV8` или
последняя установленная.
